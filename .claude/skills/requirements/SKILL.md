# เก็บ Requirement

ไฟล์ใน `docs/requirements/` คือที่เก็บ requirement ที่เดียว agent ตัวอื่นต้องเปิดไฟล์แล้วทำต่อได้ทันที โดยไม่ต้องเห็นบทสนทนานี้

```
GLOSSARY.md               คำศัพท์ (สกิล domain-modeling ดูแล)
docs/adr/                 การตัดสินใจที่ย้อนยาก (สกิล domain-modeling ดูแล)
docs/requirements/
  product.md              ภาพรวมทั้งระบบ และรายการ feature
  <feature>.md            หนึ่งไฟล์ต่อ feature ชื่อไฟล์ภาษาอังกฤษ คั่นด้วยขีด
```

## ขั้นตอน

1. **เปิดไฟล์เป้าหมาย** เลือกหนึ่งไฟล์ต่อหนึ่งรอบงาน
   - `product.md` ยังไม่มี หรือสถานะยังเป็น `กำลังเก็บ`: เก็บระดับทั้งระบบก่อน ถ้ายังไม่มีไฟล์ให้สร้างจาก [templates/product.md](templates/product.md)
   - `product.md` สถานะ `ครบแล้ว`: เปิดไฟล์ของ feature ที่ผู้ใช้พูดถึง ถ้ายังไม่มีให้สร้างจาก [templates/feature.md](templates/feature.md) และเพิ่มแถวในรายการ feature ของ `product.md`
   - ไฟล์ที่มีอยู่แล้ว: อ่านทั้งไฟล์ แล้วทำต่อจากหมวดที่ยังไม่ `ชัด` ในตารางความครบถ้วน

   เสร็จเมื่อบอกผู้ใช้ได้ว่ากำลังเก็บไฟล์ไหน และหมวดไหนยังไม่ชัด

2. **สัมภาษณ์** โหลดสกิล `grilling` และ `domain-modeling` แล้วทำตามทั้งสองสกิล หมวดทั้ง 10 ข้างล่างคือกิ่งชั้นแรกของ design tree คำถามแต่ละรอบมาจากหมวดที่ยังไม่ชัด กฎแต่ละข้อถือว่าชัดเมื่อมีตัวอย่างจริงอย่างน้อยหนึ่งตัวอย่าง ที่ระบุคน จำนวน และเวลา

3. **บันทึกทุกรอบ** หลังผู้ใช้ตอบ และก่อนถามรอบถัดไป ให้ทำครบสามอย่าง
   - เขียนคำตอบลงส่วนของไฟล์ที่ตรงกับหมวด
   - อัปเดตตารางความครบถ้วน
   - เพิ่มหนึ่งบรรทัดในบันทึกถาม-ตอบ พร้อมวันที่

   เรื่องที่ยังไม่มีคำตอบ ติดป้าย `[NEEDS CLARIFICATION: <คำถาม>]` เรื่องที่เติมเองโดยผู้ใช้ยังไม่ยืนยัน ติดป้าย `[ASSUMPTION: <ข้อสมมติ>]`

4. **ผ่านด่านตรวจ** ไฟล์ถือว่าเสร็จเมื่อจริงทุกข้อ
   - ตารางความครบถ้วนทุกแถวเป็น `ชัด` หรือ `ไม่เกี่ยว` ที่ผู้ใช้ยืนยันเหตุผลแล้ว
   - ค้นคำว่า `[NEEDS CLARIFICATION` และ `[ASSUMPTION` ในไฟล์ ได้ศูนย์รายการ
   - requirement ทุกข้อมีรหัส ลำดับความสำคัญ ประโยค EARS หนึ่งประโยค และ Given/When/Then อย่างน้อยหนึ่งกรณีปกติกับหนึ่งกรณีผิดพลาด
   - คำบอกคุณภาพทุกคำ (เร็ว เสถียร รองรับได้มาก ใช้ง่าย) มีตัวเลขและวิธีวัดกำกับ
   - ทุกบรรทัดบรรยายพฤติกรรมที่สังเกตได้จากภายนอกระบบ เรื่องวิธีสร้าง (ชื่อไฟล์ library โครงสร้างโค้ด) ให้ย้ายไปที่ ADR
   - คำเฉพาะทุกคำสะกดและมีความหมายตรงกับ `GLOSSARY.md`

5. **ปิดงาน** สรุปสิ่งที่ตกลงกันให้ผู้ใช้ยืนยัน แล้วเปลี่ยนสถานะในหัวไฟล์เป็น `ครบแล้ว` ถ้าเป็นไฟล์ feature ให้อัปเดตแถวของมันใน `product.md` และบอกผู้ใช้เรียกสกิล `to-tickets` กับไฟล์นี้ (สกิลนั้นผู้ใช้ต้องเรียกเอง) ถ้าขอบเขตใหญ่จนคุยไม่จบในรอบงานเดียว ให้บอกผู้ใช้เรียกสกิล `wayfinder`

## หมวดที่ต้องถาม

| หมวด | ต้องได้คำตอบว่า | ส่วนในไฟล์ feature |
|---|---|---|
| เป้าหมาย | ทำไปเพื่ออะไร สำเร็จแล้ววัดจากตัวเลขไหน | 1 |
| ผู้ใช้และสิทธิ์ | ใครใช้ แต่ละบทบาททำอะไรได้และทำอะไรไม่ได้ | 3 |
| ขอบเขตที่ไม่ทำ | อะไรที่คนมักคิดว่ารวมอยู่ แต่รอบนี้ไม่ทำ | 2 |
| ข้อจำกัด | เวลา งบ กฎหมาย ระบบเดิม ที่บังคับทางเลือก | 2 |
| ข้อมูลและสถานะ | เก็บข้อมูลอะไร แต่ละสถานะเปลี่ยนไปสถานะไหนได้ เพราะเหตุการณ์อะไร | 5 |
| ขั้นตอนใช้งาน | ผู้ใช้ทำอะไรทีละขั้น รวมหน้าว่าง หน้ากำลังโหลด และหน้าผิดพลาด | 4 |
| กรณีขอบ | ข้อมูลซ้ำ มาช้า มาไม่ครบ ทำพร้อมกัน ยกเลิกกลางทาง | 4 |
| คุณภาพ | เร็วแค่ไหน รับได้กี่รายการ ล่มได้นานเท่าไร เก็บข้อมูลนานแค่ไหน | 6 |
| ระบบภายนอก | ต่อกับระบบไหน ถ้าระบบนั้นล่มหรือช้า เราทำอย่างไร | 7 |
| คำศัพท์ | คำเฉพาะทุกคำมีความหมายเดียว | `GLOSSARY.md` |

`product.md` ใช้หมวดชุดเดียวกัน ลงที่ส่วนที่หัวข้อตรงกับหมวด หมวดข้อมูลและสถานะ ขั้นตอนใช้งาน กรณีขอบ และระบบภายนอก ลงที่ส่วนภาพรวมการทำงาน

สถานะในตารางความครบถ้วนมีสี่ค่า: `ยังไม่มี` `บางส่วน` `ชัด` `ไม่เกี่ยว`

สถานะในหัวไฟล์มีสองค่า: `กำลังเก็บ` `ครบแล้ว`

## รูปแบบ requirement

รหัสคือ `<รหัสย่อของ feature>-<เลขสามหลัก>` เช่น `TRK-001` ข้อด้านคุณภาพใช้ `TRK-Q01` รหัสที่ออกแล้วคงเดิมตลอด ข้อที่เลิกใช้ให้คงรหัสไว้และเขียนว่า `ยกเลิก` เพราะ ticket อ้างกลับมาที่รหัสนี้

ลำดับความสำคัญมีสามค่า: `ต้องมี` `ควรมี` `ไว้ทีหลัง`

หนึ่งข้อเขียนหนึ่งประโยคตามแบบ EARS คงคำหลักเป็นภาษาอังกฤษ

| ใช้เมื่อ | แบบ |
|---|---|
| เป็นจริงเสมอ | THE SYSTEM SHALL <ผลลัพธ์> |
| มีเหตุการณ์เกิดขึ้น | WHEN <เหตุการณ์> THE SYSTEM SHALL <ผลลัพธ์> |
| อยู่ในสถานะหนึ่ง | WHILE <สถานะ> THE SYSTEM SHALL <ผลลัพธ์> |
| เกิดเรื่องผิดปกติ | IF <เรื่องผิดปกติ> THEN THE SYSTEM SHALL <ผลลัพธ์> |
| เฉพาะเมื่อเปิดความสามารถเสริม | WHERE <ความสามารถเสริม> THE SYSTEM SHALL <ผลลัพธ์> |
