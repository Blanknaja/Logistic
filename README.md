# Blanksong (แบลงค์ส่ง)

แพลตฟอร์มซื้อขายของออนไลน์ที่มีหลายร้านในที่เดียว requirement อยู่ที่ [docs/requirements/product.md](docs/requirements/product.md) โครงโค้ดอยู่ที่ [docs/architecture.md](docs/architecture.md)

กฎสำหรับ agent ทุกค่ายอยู่ที่ [AGENTS.md](AGENTS.md) ส่วนเส้นทางงานอยู่ที่ [docs/agent-routing.md](docs/agent-routing.md)

## ติดตั้ง

ต้องมี Node 26 ขึ้นไป และ pnpm ไม่ต้องมีฐานข้อมูลหรือ Docker เพราะใช้ SQLite ที่มากับ Node

```sh
pnpm install
git config core.hooksPath .githooks
```

บรรทัดที่สองเปิด git hook ที่ตรวจก่อน commit ถ้ามีคำที่ห้ามขึ้น repo เช่นชื่อบัญชีอื่นหรืออีเมลจริง ให้ใส่ไว้ใน `.git/info/private-words` หนึ่งคำต่อบรรทัด ไฟล์นี้อยู่ใน `.git/` จึงไม่ถูก commit ทดสอบตัวตรวจด้วย `scripts/agent-checks/test.sh`

## รัน

```sh
pnpm dev
```

เปิด http://localhost:3100 ถ้าพอร์ตนี้ไม่ว่าง ใช้ `PORT=3200 pnpm dev` คำสั่งนี้สร้างข้อมูลตัวอย่างให้เองถ้ายังไม่มี

ฐานข้อมูลอยู่ที่ `data/blanksong.db` เปลี่ยนที่เก็บได้ด้วยค่า `DATABASE_PATH` ข้อมูลอยู่ครบหลังปิดและเปิดแอปใหม่ ระบบไม่ลบเอง

แบบ production: `pnpm build` แล้ว `pnpm start` (พอร์ตเดียวกัน)

### อีเมลตั้งรหัสผ่านใหม่

ไม่ต้องตั้งค่าอะไรก็ใช้ได้ ลิงก์ตั้งรหัสผ่านใหม่จะขึ้นในบันทึกของเซิร์ฟเวอร์ (หน้าจอที่รัน `pnpm dev`) ใต้บรรทัด `[อีเมล]` ถ้าจะส่งอีเมลจริงผ่าน Resend แผนฟรี ให้ตั้งค่าเหล่านี้

| ค่า | ใส่อะไร |
|---|---|
| `RESEND_API_KEY` | API key จากบัญชี Resend |
| `EMAIL_FROM` | ผู้ส่งที่อยู่บนโดเมนที่ยืนยันใน Resend แล้ว เช่น `Blanksong <no-reply@โดเมนของคุณ>` |
| `APP_URL` | ที่อยู่เว็บที่ผู้ใช้เปิด เช่น `https://blanksong.example` ลิงก์ในอีเมลใช้ค่านี้ |

## ข้อมูลตัวอย่าง

```sh
pnpm seed          # สร้างข้อมูลตัวอย่างถ้ายังไม่มี รันซ้ำได้โดยข้อมูลไม่ซ้ำ
pnpm seed --reset  # ลบฐานข้อมูลในเครื่องแล้วสร้างใหม่ทั้งหมด
```

ได้ 12 หมวดหมู่ 50 ร้าน และ 1,000 สินค้าพร้อมแบบย่อยและสต็อก ร้านของ `seller01` มีคำสั่งซื้อตัวอย่าง 8 รายการครบทุกสถานะ (จ่ายแล้ว กำลังจัดส่ง สำเร็จ ยกเลิก) ที่สร้างผ่านกฎจริงของการสั่งซื้อ จ่ายเงิน และจัดส่ง `buyer1` จึงมีพัสดุที่ `ส่งสำเร็จ` รอกด "ได้รับสินค้าแล้ว" อยู่หนึ่งชิ้น

มีรีวิวตัวอย่างราว 1,700 รีวิวของสินค้าราว 640 รายการ จากผู้ซื้อตัวอย่าง 24 บัญชี (REV-019) `buyer1` มีรายการที่รอรีวิวและรีวิวที่ยังแก้ได้ ดูที่ "คำสั่งซื้อ" → "รอรีวิว" ร้านของ `seller01` มีรีวิวที่ยังไม่ตอบ ดูที่ "ร้านของฉัน" → "รีวิว" และ `admin@example.com` ซ่อนรีวิวได้ที่ "จัดการรีวิว" ในแถบด้านบน

ร้านของ `seller01` อยู่กรุงเทพมหานคร ที่อยู่จัดส่งของ `buyer1` อยู่เชียงใหม่ ของ `buyer2` อยู่ขอนแก่น และของ `buyer3` อยู่กรุงเทพมหานคร พัสดุตัวอย่างจึงผ่านหลายจังหวัด เข้าสู่ระบบเป็น `buyer1` หรือ `buyer2` แล้วเปิด "คำสั่งซื้อ" → คำสั่งซื้อที่ `กำลังจัดส่ง` → "ติดตามพัสดุ" จะเห็นแผนที่การจัดส่งที่มีหมุด 3 จังหวัด (ภาพ [1440](docs/screenshots/delivery-map-1440.png) [390](docs/screenshots/delivery-map-390.png)) ภาพแผนที่มาจาก OpenStreetMap เบราว์เซอร์ขอเองโดยตรง จึงต้องต่ออินเทอร์เน็ต ถ้าไม่ต่อ ที่ของแผนที่ขึ้น "แสดงแผนที่ไม่ได้ ลองใหม่อีกครั้ง" ส่วนข้อความเส้นทางใต้แผนที่ยังอ่านได้ ตำแหน่งของแต่ละจังหวัดมาจาก Wikidata (CC0) ที่มาอยู่ใน `src/features/delivery/server/province-points/SOURCES.txt`

สินค้าที่มีไฟล์ 3 มิติมีสองชิ้น อยู่ในร้าน "บ้านสวนช็อป" ของ `seller01` คือ "เก้าอี้ผ้ากำมะหยี่" (http://localhost:3100/products/6) และ "แจกันแก้วใส่ดอกไม้" (http://localhost:3100/products/12) ค้นชื่อที่หน้าแรก เปิดหน้าสินค้า แล้วกด "ดูแบบ 3 มิติ" ต่อท้ายรูปย่อ สินค้าตัวอย่างชิ้นอื่นไม่มีไฟล์ 3 มิติ ไฟล์ทั้งสองมาจากชุดตัวอย่างของ Khronos ที่ใช้สัญญาอนุญาต CC0 ที่มาอยู่ใน `src/shared/seed/models/SOURCES.txt` ปุ่ม "ดูในห้องของคุณ" โผล่เฉพาะบนมือถือที่วางของในห้องผ่านกล้องได้ ซึ่งยังไม่เคยลองกับมือถือจริง

| ผู้ซื้อ (ยังไม่มีร้าน) | `buyer1@example.com` ถึง `buyer24@example.com` | `demo1234` |
| ผู้ขาย (เจ้าของร้านที่ 1 ถึง 50) | `seller01@example.com` ถึง `seller50@example.com` | `demo1234` |

## ตัวจำลองการจ่ายเงิน

ถ้าไม่ได้ใส่ `OMISE_PUBLIC_KEY` และ `OMISE_SECRET_KEY` แอปใช้ตัวจำลองในเครื่องแทน Omise ทุกหน้าจ่ายเงินมีป้าย "กำลังใช้ตัวจำลองการจ่ายเงิน" และกล่อง "ตัวจำลองการจ่ายเงิน" ท้ายหน้า

- บัตร: `4242 4242 4242 4242` จ่ายสำเร็จ `4111 1111 1114 0011` วงเงินไม่พอ `4111 1111 1111 0014` ถูกปฏิเสธ ชื่อบนบัตรอะไรก็ได้ วันหมดอายุเป็นวันในอนาคต เช่น `12/30` รหัสหลังบัตร 3 หลักอะไรก็ได้
- PromptPay: กด "จ่ายเงิน" แล้วได้ QR ปลอมที่ค้าง `รอผล` จากนั้นผู้ซื้อของกลุ่มคำสั่งซื้อนั้นกด "ทำเครื่องหมายว่าสำเร็จ" หรือ "ทำเครื่องหมายว่าไม่สำเร็จ" ในกล่องตัวจำลอง หน้าที่เปิดค้างจะเห็นผลเองภายในไม่กี่วินาที ทำเครื่องหมายได้เฉพาะการจ่ายเงินที่รอผลของกลุ่มตัวเอง
- ปุ่ม "Omise ไม่ตอบเกิน 10 วินาที" และ "Omise ให้บริการไม่ได้" ใช้ลองกรณีระบบจ่ายเงินล่ม ปุ่มนี้มีผลกับทุกคนที่ใช้เซิร์ฟเวอร์นั้นจนกด "Omise ตอบปกติ" จึงขึ้นเฉพาะบัญชีผู้ดูแลแพลตฟอร์ม (`admin@example.com`) ที่หน้าจ่ายเงินของกลุ่มคำสั่งซื้อของตัวเอง บัญชีอื่นเห็นแค่ว่าใช้โหมดไหนอยู่
- ตัวจำลองลืมทุกอย่างเมื่อปิดเซิร์ฟเวอร์ และเมื่อใส่กุญแจของ Omise แล้ว กล่องตัวจำลองหายไป ปุ่มทั้งสองแบบใช้ไม่ได้ แม้ส่งคำขอเองก็ไม่มีผล

ใส่กุญแจทดลองของ Omise (ขึ้นต้น `pkey_test_` และ `skey_test_`) ใน `.env.local` แล้วเปิดแอปใหม่ จะใช้ Omise โหมดทดลองแทน แอปไม่ยอมรับกุญแจที่ไม่ใช่โหมดทดลอง ลองกับ Omise จริงแล้วเมื่อ 2026-11-25 ทั้งบัตรและ PromptPay

- บัตร: ใช้เลขบัตรทดลองชุดเดียวกับข้างบน รายการเต็มอยู่ที่ docs.omise.co/api-testing โหมดทดลองของ Omise รับเลขบัตรอื่นที่ถูกรูปแบบเป็นจ่ายสำเร็จด้วย ต่างจากตัวจำลองที่ตอบว่าบัตรไม่ถูกต้อง บัญชีทดลองตอนนี้ไม่ได้เปิด 3-D Secure
- PromptPay: QR ค้าง `รอผล` จนทำเครื่องหมายผล ทำได้สองทาง คือหน้าจัดการของ Omise (Charges → เลือก charge → Actions → Mark as Successful หรือ Mark as Failed) หรือ API ของโหมดทดลอง `POST https://api.omise.co/charges/<charge id>/mark_as_paid` หรือ `/mark_as_failed` ด้วยกุญแจลับ หน้าที่เปิดค้างเห็นผลเองภายในไม่กี่วินาที เลขอ้างอิง (`chrg_test_...`) อยู่ในคอลัมน์ `payments.omise_charge_id`
- webhook: ตั้งที่อยู่ `https://<โดเมนของแอป>/pay/omise-webhook` ในหน้าจัดการของ Omise ต้องเป็นที่อยู่ที่ Omise เข้าถึงได้ จึงลองจากเครื่องตัวเองไม่ได้ ไม่ตั้งก็ใช้ได้ เพราะหน้าที่เปิดค้างถามผลเองทุก 3 วินาที
- `pnpm test:omise` ลองทั้งหมดนี้กับ Omise จริงอัตโนมัติ ใช้กุญแจจาก `.env.local`

## อะไรจริง อะไรจำลอง

| เรื่อง | สถานะ |
|---|---|
| บัญชี ร้าน สินค้า สต็อก ตะกร้า คำสั่งซื้อ | จริง เก็บในฐานข้อมูล สต็อกถูกจองตอนสั่งซื้อและคืนเมื่อยกเลิก หมดเวลาจ่าย หรือส่งไม่สำเร็จ |
| การจ่ายเงิน | ตัวจำลองในเครื่องเป็นค่าเริ่มต้น ใส่กุญแจทดลองแล้วใช้ Omise โหมดทดลองจริง (ลองแล้วทั้งบัตรและ PromptPay) ไม่มีเงินจริงในทุกกรณี |
| การจัดส่ง | ไม่ต่อบริษัทขนส่ง ผู้ขายหรือผู้ดูแลแพลตฟอร์มกดเปลี่ยนสถานะเองพร้อมเลือกจังหวัด แผนที่การจัดส่งแสดงจังหวัดที่เลือกไว้ ไม่ใช่ตำแหน่งจริงของพัสดุ ภาพแผนที่มาจาก OpenStreetMap จริง |
| อีเมล | ขึ้นในบันทึกของเซิร์ฟเวอร์ ส่งจริงเมื่อใส่ค่าของ Resend |
| งานตามเวลา | ยกเลิกคำสั่งซื้อที่ไม่จ่ายใน 30 นาที (ตรวจทุก 15 วินาที) และปิดคำสั่งซื้อเป็น `สำเร็จ` หลังส่งสำเร็จ 7 วัน (ตรวจทุก 1 นาที) ทำงานเฉพาะตอนแอปเปิดอยู่ แอปเปิดใหม่แล้วตามเก็บให้ทันที |

pnpm check      # ตรวจชนิดข้อมูล ตรวจรูปแบบโค้ด และรัน test ทั้งหมด ไม่ต้องต่ออินเทอร์เน็ต ราว 20 วินาที

## ข้อจำกัดที่รู้อยู่

- ข้อมูลบัตรผ่านเซิร์ฟเวอร์ของเราก่อนส่งให้ Omise (ไม่เก็บ) โหมดทดลองของบัญชีนี้ยอมรับแบบนี้ แต่ก่อนรับเงินจริงต้องเปลี่ยนไปใช้ Omise.js และ webhook ไม่ตรวจลายเซ็นแต่ถามผลกลับจาก Omise ก่อนเชื่อ การส่ง webhook จาก Omise มาที่แอปจริงยังไม่ได้ลอง รายละเอียดอยู่ในคำถามค้างของ `docs/requirements/payment.md`
- หน้าลืมรหัสผ่านยังไม่จำกัดจำนวนครั้งที่ขอ และตั้งรหัสผ่านใหม่แล้วยังไม่ล้างการพักเข้าสู่ระบบ 15 นาที
- หน้า "ไม่พบ" ตอบสถานะ HTTP 200 ไม่ใช่ 404 เพราะหน้ากำลังโหลดเริ่มส่งออกไปก่อน ผู้ใช้เห็นข้อความถูกต้อง และหน้า "ไม่พบคำสั่งซื้อ" มี error ของ React (#419) ในคอนโซลของเบราว์เซอร์ โดยหน้ายังแสดงถูก
- ปุ่มย้อนกลับของเบราว์เซอร์ไม่ถามก่อนทิ้งฟอร์มที่ยังไม่บันทึก (หน้าตั้งค่าร้านและหน้าลงสินค้า)
- เมนูหลังบ้านขอหน้าใหม่อีกหนึ่งครั้งทุกครั้งที่กดไปหน้าอื่นในหลังบ้าน เพื่อให้ตัวเลข "รอจัดของ" ไม่ค้าง
- ตัวเลขที่ต้องให้คนจริงลอง (เช่นคนที่ไม่เคยใช้ระบบเปิดร้านจบใน 2 นาที หรือเดินเส้นทางหลักจบใน 10 นาที) และเวลาที่อีเมลไปถึงผู้รับ ยังไม่ได้วัด `pnpm e2e` ตรวจแค่ว่าเครื่องเดินเส้นทางหลักจบภายใน 2 นาที
- ฟอร์มที่รอผลไม่เกิน 10 วินาที (เช่น สมัครบัญชี โปรไฟล์ เปิดร้าน ตั้งค่าร้าน บันทึกสินค้า สั่งซื้อ) ตัดที่ 10 วินาทีในเบราว์เซอร์เท่านั้น เซิร์ฟเวอร์ไม่ยกเลิกงานที่ทำค้างอยู่ ถ้าเซิร์ฟเวอร์ช้าเกิน 10 วินาทีแต่บันทึกสำเร็จทีหลัง ผู้ใช้จะเห็น "ไม่สำเร็จ" ทั้งที่ข้อมูลถูกบันทึกแล้ว (ACC-014 SHP-002 SHP-007 PRD-007) เปิดหน้าใหม่จะเห็นข้อมูลจริง
- ความเร็วขณะมีผู้ใช้ 20 คนพร้อมกันวัดแค่การเปิด 16 หน้าในตารางข้างบน การกดบันทึกหรือส่งฟอร์ม (ACC-Q02 SHP-Q02 INV-Q03 PRD-Q02 CHK-Q01) และหน้าที่ไม่อยู่ในตาราง เช่นหน้าของบัญชี หน้าเปิดร้าน หน้าฟอร์มสินค้า และหน้าประวัติสต็อก (ACC-Q01 SHP-Q01 PRD-Q01 INV-Q01) วัดแค่ใน test ระดับฟังก์ชันทีละคน
- แผนที่การจัดส่งลองบนมือถือแค่แบบจำลองใน Chrome ยังไม่เคยลองบนมือถือจริงหรือ Safari บนมือถือ นิ้วเดียวเลื่อนหน้าผ่านแผนที่ ส่วนการเลื่อนแผนที่บนมือถือใช้สองนิ้วหรือปุ่มซูม และตัวเลขความสำเร็จของ `delivery-map.md` (คน 5 คนตอบได้ว่าพัสดุอยู่จังหวัดไหนภายใน 10 วินาที) ยังไม่ได้วัดกับคนจริง
- คอลัมน์ `cart_items.last_seen_name` ถูกเขียนทุกครั้งที่ใส่ตะกร้าแต่ไม่มีที่ใดอ่าน ยังเก็บไว้เพราะเป็น `NOT NULL` ที่เลิกเขียนไม่ได้โดยไม่แก้โครงข้อมูล
