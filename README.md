# Blanksong (แบลงค์ส่ง)

แพลตฟอร์มซื้อขายของออนไลน์ที่มีหลายร้านในที่เดียว requirement อยู่ที่ [docs/requirements/product.md](docs/requirements/product.md) โครงโค้ดอยู่ที่ [docs/architecture.md](docs/architecture.md)

กฎสำหรับ agent ทุกค่ายอยู่ที่ [AGENTS.md](AGENTS.md) ส่วนเส้นทางงานอยู่ที่ [docs/agent-routing.md](docs/agent-routing.md)

## ติดตั้ง

ต้องมี Node 26 ขึ้นไป และ pnpm ไม่ต้องมีฐานข้อมูลหรือ Docker เพราะใช้ SQLite ที่มากับ Node

```sh
pnpm install
git config core.hooksPath .githooks
```

บรรทัดที่สองเปิด git hook ที่ตรวจก่อน commit ถ้ามีคำที่ห้ามขึ้น repo เช่นชื่อบัญชีอื่นหรืออีเมลจริง ให้ใส่ไว้ใน `.git/info/private-words` หนึ่งคำต่อบรรทัด ไฟล์นี้อยู่ใน `.git/` จึงไม่ถูก commit ทดสอบตัวตรวจด้วย `scripts/agent-checks/test.sh`

## รัน

```sh
pnpm dev
```

เปิด http://localhost:3100 ถ้าพอร์ตนี้ไม่ว่าง ใช้ `PORT=3200 pnpm dev` คำสั่งนี้สร้างข้อมูลตัวอย่างให้เองถ้ายังไม่มี

ฐานข้อมูลอยู่ที่ `data/blanksong.db` เปลี่ยนที่เก็บได้ด้วยค่า `DATABASE_PATH` ข้อมูลอยู่ครบหลังปิดและเปิดแอปใหม่ ระบบไม่ลบเอง

แบบ production: `pnpm build` แล้ว `pnpm start` (พอร์ตเดียวกัน)

### อีเมลตั้งรหัสผ่านใหม่

ไม่ต้องตั้งค่าอะไรก็ใช้ได้ ลิงก์ตั้งรหัสผ่านใหม่จะขึ้นในบันทึกของเซิร์ฟเวอร์ (หน้าจอที่รัน `pnpm dev`) ใต้บรรทัด `[อีเมล]` ถ้าจะส่งอีเมลจริงผ่าน Resend แผนฟรี ให้ตั้งค่าเหล่านี้

| ค่า | ใส่อะไร |
|---|---|
| `RESEND_API_KEY` | API key จากบัญชี Resend |
| `EMAIL_FROM` | ผู้ส่งที่อยู่บนโดเมนที่ยืนยันใน Resend แล้ว เช่น `Blanksong <no-reply@โดเมนของคุณ>` |
| `APP_URL` | ที่อยู่เว็บที่ผู้ใช้เปิด เช่น `https://blanksong.example` ลิงก์ในอีเมลใช้ค่านี้ |

## ข้อมูลตัวอย่าง

```sh
pnpm seed          # สร้างข้อมูลตัวอย่างถ้ายังไม่มี รันซ้ำได้โดยข้อมูลไม่ซ้ำ
pnpm seed --reset  # ลบฐานข้อมูลในเครื่องแล้วสร้างใหม่ทั้งหมด
```

ได้ 12 หมวดหมู่ 50 ร้าน และ 1,000 สินค้าพร้อมแบบย่อยและสต็อก ร้านของ `seller01` มีคำสั่งซื้อตัวอย่าง 8 รายการครบทุกสถานะ (จ่ายแล้ว กำลังจัดส่ง สำเร็จ ยกเลิก) ที่สร้างผ่านกฎจริงของการสั่งซื้อ จ่ายเงิน และจัดส่ง `buyer1` จึงมีพัสดุที่ `ส่งสำเร็จ` รอกด "ได้รับสินค้าแล้ว" อยู่หนึ่งชิ้น

บัญชีตัวอย่างมีดังนี้ รหัสผ่านใช้สาธิตเท่านั้น

| บัญชี | อีเมล | รหัสผ่าน |
|---|---|---|
| ผู้ดูแลแพลตฟอร์ม | `admin@example.com` | `admin1234` |
| ผู้ซื้อ (ยังไม่มีร้าน) | `buyer1@example.com` ถึง `buyer3@example.com` | `demo1234` |
| ผู้ขาย (เจ้าของร้านที่ 1 ถึง 50) | `seller01@example.com` ถึง `seller50@example.com` | `demo1234` |

## ตัวจำลองการจ่ายเงิน

ถ้าไม่ได้ใส่ `OMISE_PUBLIC_KEY` และ `OMISE_SECRET_KEY` แอปใช้ตัวจำลองในเครื่องแทน Omise ทุกหน้าจ่ายเงินมีป้าย "กำลังใช้ตัวจำลองการจ่ายเงิน" และกล่อง "ตัวจำลองการจ่ายเงิน" ท้ายหน้า

- บัตร: `4242 4242 4242 4242` จ่ายสำเร็จ `4111 1111 1114 0011` วงเงินไม่พอ `4111 1111 1111 0014` ถูกปฏิเสธ ชื่อบนบัตรอะไรก็ได้ วันหมดอายุเป็นวันในอนาคต เช่น `12/30` รหัสหลังบัตร 3 หลักอะไรก็ได้
- PromptPay: กด "จ่ายเงิน" แล้วได้ QR ปลอมที่ค้าง `รอผล` จากนั้นกด "ทำเครื่องหมายว่าสำเร็จ" หรือ "ทำเครื่องหมายว่าไม่สำเร็จ" ในกล่องตัวจำลอง หน้าที่เปิดค้างจะเห็นผลเองภายในไม่กี่วินาที
- ปุ่ม "Omise ไม่ตอบเกิน 10 วินาที" และ "Omise ให้บริการไม่ได้" ใช้ลองกรณีระบบจ่ายเงินล่ม ปุ่มนี้มีผลกับทุกคนที่ใช้เซิร์ฟเวอร์นั้นจนกด "Omise ตอบปกติ" และตัวจำลองลืมทุกอย่างเมื่อปิดเซิร์ฟเวอร์

ใส่กุญแจทดลองของ Omise (ขึ้นต้น `pkey_test_` และ `skey_test_`) ใน `.env.local` แล้วเปิดแอปใหม่ จะใช้ Omise โหมดทดลองแทน แอปไม่ยอมรับกุญแจที่ไม่ใช่โหมดทดลอง

## อะไรจริง อะไรจำลอง

| เรื่อง | สถานะ |
|---|---|
| บัญชี ร้าน สินค้า สต็อก ตะกร้า คำสั่งซื้อ | จริง เก็บในฐานข้อมูล สต็อกถูกจองตอนสั่งซื้อและคืนเมื่อยกเลิก หมดเวลาจ่าย หรือส่งไม่สำเร็จ |
| การจ่ายเงิน | ตัวจำลองในเครื่องเป็นค่าเริ่มต้น โค้ดที่ต่อ Omise โหมดทดลองมีอยู่แต่ยังไม่เคยลองกับ Omise จริง ไม่มีเงินจริงในทุกกรณี |
| การจัดส่ง | ไม่ต่อบริษัทขนส่ง ผู้ขายหรือผู้ดูแลแพลตฟอร์มกดเปลี่ยนสถานะเอง |
| อีเมล | ขึ้นในบันทึกของเซิร์ฟเวอร์ ส่งจริงเมื่อใส่ค่าของ Resend |
| งานตามเวลา | ยกเลิกคำสั่งซื้อที่ไม่จ่ายใน 30 นาที (ตรวจทุก 15 วินาที) และปิดคำสั่งซื้อเป็น `สำเร็จ` หลังส่งสำเร็จ 7 วัน (ตรวจทุก 1 นาที) ทำงานเฉพาะตอนแอปเปิดอยู่ แอปเปิดใหม่แล้วตามเก็บให้ทันที |

## ตรวจโค้ด

```sh
pnpm check   # ตรวจชนิดข้อมูล ตรวจรูปแบบโค้ด และรัน test ทั้งหมด ไม่ต้องต่ออินเทอร์เน็ต ราว 20 วินาที
pnpm e2e     # เดินเส้นทางหลักผ่านหน้าเว็บจริงด้วย Playwright ราว 20 วินาที รวม build
```

`pnpm e2e` build แอป ล้างแล้วสร้างฐานข้อมูลของตัวเองที่ `data/e2e.db` เปิดแอปแบบ production ที่พอร์ต 3300 (เปลี่ยนด้วย `E2E_PORT`) แล้วเปิด Google Chrome ที่ติดตั้งในเครื่องแบบไม่มีหน้าต่าง ทุกขั้นตรวจด้วยว่าที่จอกว้าง 360 จุดไม่มีส่วนล้นจนต้องเลื่อนซ้ายขวา

- เครื่องที่ไม่มี Google Chrome: `pnpm exec playwright install chromium` ครั้งเดียว แล้วรัน `E2E_BROWSER=chromium pnpm e2e`
- ถ่ายภาพหน้าจอใหม่ลง `docs/screenshots/`: `SCREENSHOTS=1 pnpm e2e`
- ถ้าพัง ดูภาพและ trace ใน `test-results/` ด้วย `pnpm exec playwright show-trace <ไฟล์ trace.zip>`

## ข้อจำกัดที่รู้อยู่

- ยังไม่เคยต่อ Omise จริง ข้อมูลบัตรผ่านเซิร์ฟเวอร์ของเราก่อนส่งให้ Omise (ไม่เก็บ) ก่อนรับเงินจริงต้องเปลี่ยนไปใช้ Omise.js และ webhook ไม่ตรวจลายเซ็นแต่ถามผลกลับจาก Omise ก่อนเชื่อ รายละเอียดอยู่ในคำถามค้างของ `docs/requirements/payment.md`
- หน้าลืมรหัสผ่านยังไม่จำกัดจำนวนครั้งที่ขอ และตั้งรหัสผ่านใหม่แล้วยังไม่ล้างการพักเข้าสู่ระบบ 15 นาที
- หน้า "ไม่พบ" ตอบสถานะ HTTP 200 ไม่ใช่ 404 เพราะหน้ากำลังโหลดเริ่มส่งออกไปก่อน ผู้ใช้เห็นข้อความถูกต้อง และหน้า "ไม่พบคำสั่งซื้อ" มี error ของ React (#419) ในคอนโซลของเบราว์เซอร์ โดยหน้ายังแสดงถูก
- ปุ่มย้อนกลับของเบราว์เซอร์ไม่ถามก่อนทิ้งฟอร์มที่ยังไม่บันทึก (หน้าตั้งค่าร้านและหน้าลงสินค้า)
- เมนูหลังบ้านขอหน้าใหม่อีกหนึ่งครั้งทุกครั้งที่กดไปหน้าอื่นในหลังบ้าน เพื่อให้ตัวเลข "รอจัดของ" ไม่ค้าง
- ตัวเลขที่ต้องให้คนจริงลอง (เช่นคนที่ไม่เคยใช้ระบบเปิดร้านจบใน 2 นาที หรือเดินเส้นทางหลักจบใน 10 นาที) และเวลาที่อีเมลไปถึงผู้รับ ยังไม่ได้วัด
