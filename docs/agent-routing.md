# เส้นทางงานและระดับโมเดล

ก่อนเริ่มงาน ดูว่างานเป็นประเภทไหน แล้วใช้สกิลและระดับโมเดลตามตาราง

| ประเภทงาน | สกิล | ระดับโมเดล |
|---|---|---|
| เก็บหรือแก้ requirement | `requirements` | วางแผน |
| แตก requirement เป็น ticket | `to-tickets` (ผู้ใช้เรียกเอง) | วางแผน |
| ลงมือทำตาม ticket | `implement` (ผู้ใช้เรียกเอง) | ลงมือทำ |

งานที่ไม่ตรงกับแถวไหน ให้เลือกระดับจากคำอธิบายในตารางถัดไป

## ขั้นตอนทำ ticket

1. เปิด session ตามระดับลงมือทำ แล้วแตก branch `<feature>/<เลข issue>-<slug>` จาก `main` ก่อนพิมพ์ `/implement` เพราะสกิลนี้ commit ลง branch ปัจจุบัน
2. ระหว่าง `/implement` ให้ commit ก่อนเรียก `/code-review` และใช้ `main` เป็นจุดเทียบ เพราะ `/code-review` ดูเฉพาะงานที่ commit แล้ว ถ้า review เจอเรื่องต้องแก้ ให้แก้แล้ว commit เพิ่ม
3. commit message ใส่ `Closes #<เลข issue>` เพื่อให้ `/code-review` หา ticket เจอ และ issue ปิดเองตอน merge PR
4. ผู้ใช้ push และเปิด PR เอง agent ไม่ push

ticket เสร็จเมื่อครบทุกข้อ

- คำสั่ง check ของโปรเจคผ่าน (กำหนดคำสั่งตอนเลือก stack)
- เกณฑ์รับงานทุกข้อมี test
- `/code-review` แกน Spec ไม่มีข้อค้าง
- มีภาพหรือวิดีโอจากการรันแอปจริง (เริ่มบังคับเมื่อมีสกิลตรวจตอนรันแอป)

## ระดับโมเดล

ไฟล์ในโปรเจคนี้ระบุโมเดลด้วยชื่อระดับเท่านั้น ไม่ใส่เลขรุ่น เมื่อมีรุ่นใหม่ ชื่อระดับจะชี้ไปรุ่นใหม่เอง

| ระดับ | ใช้กับ | โมเดล |
|---|---|---|
| วางแผน | งานที่ต้องตัดสินใจว่าจะทำอะไร รวมถึงการเลือกเส้นทางงานตามตารางข้างบน | ตัวที่ฉลาดที่สุดที่แพคของผู้ใช้รวมไว้ในโควตา |
| ลงมือทำ | งานที่มี ticket หรือแผนชัดแล้ว | ตัวรองจากตัวที่ฉลาดที่สุดของค่ายนั้น ถ้าบัญชีเปิดได้สูงสุดแค่ตัวนี้ สองระดับใช้ตัวเดียวกัน |

### Claude Code

- ระดับวางแผนคือโมเดลของ session หลัก ใช้ Fable เฉพาะแพค Max โดยเริ่มด้วย `claude --model fable` แพคอื่น เช่น Pro ใช้ค่าเริ่มต้นของบัญชี
- agent สายวางแผนใน `.claude/agents/` ตั้ง `model: inherit` จึงได้ Fable เฉพาะตอน session หลักเป็น Fable ไม่ต้องแก้ไฟล์ agent เมื่อเปลี่ยนแพค
- ถ้าผู้ใช้ขอให้เรียก Fable เป็น subagent ตรงๆ ให้เรียกได้ ถ้าเรียกแล้วไม่มี Fable ให้ใช้ `opus` แทน แล้วบอกผู้ใช้
- ระดับลงมือทำ เปิด session ใหม่ด้วย `claude --model opus` แล้วพิมพ์ `/implement` ทีละ ticket เพราะสกิลที่ผู้ใช้เรียกเองจะรันด้วยโมเดลของ session ที่พิมพ์
- ช่อง `model` ในโปรเจคนี้ใส่แค่ alias: `inherit` `fable` `opus` `sonnet` `haiku` (Claude Code รับรหัสรุ่นเต็มได้ด้วย แต่โปรเจคนี้ไม่ใช้)

### Codex และเครื่องมืออื่น

- เครื่องมือเหล่านี้ไม่มี alias ของระดับ จึงใช้โมเดลของ session
- `requirements-analyst` เป็นไฟล์ agent ของ Claude เท่านั้น ค่ายอื่นเก็บ requirement ด้วยการเรียกสกิล `requirements` ตรงๆ
- ผู้ใช้เลือกโมเดลของ session ให้ตรงกับระดับของงานตอนเริ่ม
