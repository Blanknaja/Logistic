# หน้าตาของแอป รอบ 3 "ตลาดเช้า"

Blanksong ควรรู้สึกเหมือนตลาดเช้าที่จัดร้านเรียบร้อย: พื้นอุ่นแบบกระดาษ ของลอยอยู่บนการ์ดขาว สีเขียวสดกับสีดอกดาวเรือง ของเด่นมาก่อนตาราง และทุกการกระทำมีคำตอบที่มองเห็น ภาพประจำเว็บคือพัสดุที่เดินทางจากร้านถึงบ้าน เหตุผล งานวิจัย และแผนทีละหน้าอยู่ที่ `docs/research/lively-design.md` (ข้อ c ถึง g) รอบ 2 (เรียบ พื้นขาว ไม่มีเงา) ถูกแทนด้วยไฟล์นี้ทั้งหมด

- ค่าทุกตัวอยู่ใน `:root` ของ `src/app/globals.css` ใช้ผ่าน `var()` เท่านั้น สีพิมพ์เป็นตัวเลขได้ที่นั่นที่เดียว (test ตรวจ)
- ฟอนต์โหลดครั้งเดียวใน `src/app/layout.tsx` ด้วย `next/font` มีสามตัว ห้ามเพิ่ม
- หน้าแบบอย่างคือหน้าแรก (`src/features/browse/components/home-sections.tsx` กับ `home.module.css`) และหน้าสินค้า (`src/app/products/[productId]/page.tsx` กับ `browse.module.css`) ภาพจอแรกอยู่ที่ `docs/screenshots/design-3/`
- กฎที่เครื่องตรวจได้อยู่ใน `src/app/design-system.test.ts` แก้กฎข้อไหน ให้แก้ test ข้อนั้นพร้อมกัน

## กฎ

### สีและพื้นผิว

- พื้นมีสามชั้น: พื้นหน้า (`--color-bg`) ของที่ลอย (`--color-surface` กับเงา) ของที่จม (`--color-surface-sunken`) ของที่กดได้หรือเป็นก้อนข้อมูลของตัวเองลอยอยู่บนการ์ด ไม่ตีเส้นขอบรอบการ์ด
- การ์ดใช้ class `card` (พื้นขาว มุม `--radius-l` เงา `--shadow-1`) กับการ์ดสินค้า กล่องซื้อ กล่องสรุปยอด กลุ่มร้านในตะกร้า ห้ามการ์ดซ้อนการ์ด ในการ์ดคั่นด้วยเส้น `--color-border`
- ตารางของหลังบ้าน (คำสั่งซื้อ สินค้า สต็อก) อยู่บนการ์ดใบเดียว แถวคั่นด้วยเส้น ส่วนของฟอร์มยาวเป็นการ์ดส่วนละใบ แถบปุ่มที่ติดขอบล่างจอเป็น `--color-surface` กับ `--shadow-2` มุมบน `--radius-l`
- ดาวของรีวิวเป็นรูป: พื้น `--color-accent` กับเส้นขอบ `--color-ink` ไม่นับเป็นสีตัวหนังสือ
- สีเขียวใช้กับปุ่มหลัก ตัวเลือกที่เลือกอยู่ ลิงก์ที่เป็นการกระทำ และสถานะสำเร็จ สีดอกดาวเรืองใช้เป็นพื้นของของใหม่และของฉลอง `--color-sale` ใช้กับราคาที่ลดและเวลาที่ใกล้หมดเท่านั้น
- ปุ่มสีเขียวเต็ม (`class="button"` ที่ไม่มี `button-secondary`) หน้าละหนึ่งปุ่ม และกดได้ในจอแรกทั้ง 390x844 และ 1440x900 กฎเรื่องหน้าต่างถามยืนยัน ปุ่มลบ (`button-secondary` กับ `destructive`) และ `link-action` เหมือนรอบ 2
- สถานะใช้ป้าย `badge` ที่มีสี ข้อความในป้ายต้องบอกสถานะครบเอง สีเป็นแค่ตัวช่วย
- แถบพื้น `--color-ink` มีได้หนึ่งแถบต่อหน้ายาว
- gradient มีสามที่: พื้นของส่วนต้อนรับ ขอบจางของแถวที่เลื่อนข้าง และแสงของโครงสี (test ตรวจ) ไม่ใช้บนปุ่มหรือตัวหนังสือ
- มุม: ช่องกรอกและรูปย่อ `--radius-s` ปุ่มและรูปในการ์ด `--radius-m` การ์ดและกรอบรูปใหญ่ `--radius-l` chip ป้าย และปุ่มไอคอน `--radius-pill`

### ตัวหนังสือ

- สามน้ำหนัก: 400 เนื้อหา ชื่อสินค้า ป้ายช่องกรอก / 600 `h2` ปุ่ม ราคาในการ์ด ชื่อร้านในการ์ดร้าน / 700 ตัวโชว์ `h1` ราคาในหน้าสินค้า ยอดที่ต้องจ่าย
- หน้าหนึ่งใช้ไม่เกิน 6 ขนาด และ `display` ไม่เกินหนึ่งตัว
- ตัวโชว์ที่แบ่งบรรทัดเองให้แบ่งที่รอยต่อของคำ ลองคำที่มีสระบนล่างซ้อน เช่น "ที่เดียว" ในภาพจริงก่อนใช้

### รูป

- รูปในรายการและการ์ดเป็นสี่เหลี่ยมจัตุรัสแบบ `cover` มุม `--radius-m` รูปใหญ่ในหน้าสินค้า (`.plate`) แสดงทั้งรูปด้วย `contain` บนกรอบ `--color-surface-sunken` test ตรวจว่ามี `contain` แค่ที่นั่น
- รูปสำรองคือ `ProductImage` ที่ไม่มี `src`: ไอคอนของหมวดบนพื้น `--tint-*` กับคำว่า "ไม่มีรูป" ส่ง `categoryId` ถ้ารู้ ที่แคบกว่า 100px ซ่อนคำด้วย CSS

### การขยับ

การขยับบอกว่าเกิดอะไรขึ้น ไม่ใช่ของประดับ ปิดการขยับทั้งหมดแล้วหน้าต้องยังครบ

|---|---|---|
| กด | ย่อ `scale(0.97)` ใน `--dur-press` แล้วเด้งกลับด้วย `--ease-spring` | มีใน `button` `chip` แล้ว ของอื่นใส่ class `pressable` |
| ชี้การ์ดที่กดได้ | ยก 4px เงาเป็น `--shadow-2` รูปขยาย 1.04 เท่าในกรอบ | class `lift` คู่กับ `card` |
| เปิดหน้าที่มีส่วนต้อนรับ | บรรทัดเลื่อนขึ้น 16px พร้อมชัดขึ้น ห่างกัน `--stagger` | class `rise` กับ `style={{ "--i": ลำดับ }}` |

ตัวช่วยของ React อยู่ที่ `src/shared/ui/`: `transitions.tsx` `fly-to-cart.ts` `status-badge.tsx` (คำสถานะทุกคำได้สีจากตารางเดียว) `journey.tsx` (`Journey` `PurchaseSteps`) และ `celebrate.tsx` class อยู่ท้าย `globals.css`

ทุก `page.tsx` ครอบเนื้อหาด้วย `<PageReveal>` (หรือ `<PageSlide>` ในเส้นทางซื้อ: ตะกร้า สั่งซื้อ จ่ายเงิน) และทุก `loading.tsx` ครอบด้วย `<SkeletonExit>` การเดินหน้าที่เกิดจาก server action ใส่ `addTransitionType("nav-forward")` ใน transition เดียวกับที่เรียก action

- ขยับได้แค่ `transform` กับ `opacity` (และ `box-shadow` สี ตอนชี้ กับ `stroke-dashoffset` `offset-distance` ของภาพประกอบ) ห้ามขยับ `width` `height` `top` `left` `margin` `padding` (test ตรวจทั้ง `transition` และ `@keyframes`)
- เวลาใช้ `--dur-*` จังหวะใช้ `--ease-*` ห้ามพิมพ์ตัวเลขเอง (test ตรวจ)
- hover ห่อด้วย `@media (hover: hover)`
- ของที่ผูกกับการเลื่อน (`animation-timeline`) ต้องอยู่ใน `@supports` เบราว์เซอร์ที่ไม่รองรับเห็นของนิ่งครบ (test ตรวจ)
- ของทุกชิ้นเริ่มจากสภาพที่มองเห็นได้ ห้ามตั้ง `opacity: 0` รอให้สคริปต์มาเปิด animation ตอนเข้าใช้ `@keyframes` ที่มีแต่ `from`
- ไม่มีอะไรขยับเองนานกว่า 5 วินาที ยกเว้นโครงสีระหว่างโหลด (test ตรวจ `infinite`) ของที่จำเป็นต้องขยับต่อเนื่องด้วยสคริปต์ต้องมีปุ่มหยุดที่กดด้วยแป้นพิมพ์ได้ และหยุดเองเมื่อพ้นจอ แบบ `ParcelStage`
- ผู้ใช้ขอลดการขยับ: กฎท้าย `globals.css` ทำให้ทุก animation จบทันที เลิกผูกกับการเลื่อน และการเปลี่ยนหน้าไม่ขยับ (test ตรวจ) โค้ดที่ขยับด้วยสคริปต์ต้องถาม `matchMedia("(prefers-reduced-motion: reduce)")` เอง แบบ `flyToCart` และ `ParcelStage`
- ชื่อของ `<Morph>` ห้ามซ้ำในหน้าเดียว ชื่อซ้ำทำให้การเปลี่ยนหน้านั้นไม่ขยับเลย สินค้าที่มีการ์ดสองใบในหน้าเดียวให้ใบหนึ่งส่ง `morph={false}` แบบชั้นวางของหน้าแรก
- รูปขยายตอนเปลี่ยนหน้าได้เมื่อหน้าปลายทางโหลดไว้ก่อนแล้วเท่านั้น `ProductCard` จึงโหลดหน้าสินค้าตั้งแต่ชี้ แตะ หรือโฟกัส ถ้าไม่ทัน ผู้ซื้อเห็นโครงสีแล้วเนื้อหาเลื่อนขึ้นแทน
- 3 มิติใช้ได้สองที่: ตัวแสดงโมเดลของหน้าสินค้า และฉากพัสดุของส่วนต้อนรับ โหลดด้วย `import()` หลังหน้าแสดงแล้ว มีภาพนิ่งขนาดเท่ากันจองที่ไว้ก่อน ไม่ใช้ในตาราง ตะกร้า หน้าสั่งซื้อ ฟอร์ม หรือหลังบ้าน

### ผังหน้า (เหมือนรอบ 2)

- เนื้อหาอยู่ใน `.container` ของที่ต้องชนขอบจอใช้ `margin-inline: calc(-1 * var(--gutter))`
- breakpoint สามค่า 600 900 1200 เขียนจอเล็กก่อนด้วย `min-width` ใช้ `max-width: 599px` หรือ `899px` ได้กับกฎที่มีเฉพาะจอเล็ก (test ตรวจ) จอ 900 ขึ้นไปหน้าที่มีงานหลักหนึ่งอย่างแบ่ง 7:5 ของที่ดูอยู่ซ้าย กล่องที่ต้องกดอยู่ขวาและค้างข้างจอ (`position: sticky; top: calc(var(--header-height) + var(--space-4))`)
- บนจอเล็กกว่า 900 ปุ่มหลักที่อยู่ต่ำกว่าจอแรกให้ติดขอบล่างจอแบบ `.buyBar`
- จอกว้าง 360 จุดต้องไม่ล้นจนเลื่อนซ้ายขวาได้ แถวที่เลื่อนข้างต้องอยู่ในกรอบของตัวเอง (`.scroller` ใน `home.module.css`)
- วงโฟกัสตั้งไว้ที่ `:focus-visible` ทั้งแอป ถ้าซ่อนวงของ input ให้ใส่วงที่ตัวห่อด้วย `:focus-within` หรือ `:has(input:focus-visible)`
- ของที่รอสคริปต์ใช้สถานะที่ component ตั้งเองหลังเริ่มทำงาน ไม่ใช้ `@media (scripting)` (test ตรวจ)
- วันเวลาใช้ตัวช่วยใน `src/shared/format.ts` ห่อด้วย `<time>`

## แถบด้านบนและเมนูหลังบ้าน

- ติดขอบบนจอ (`position: sticky`) ได้เงาเมื่อเลื่อนลง และอยู่กับที่ระหว่างเปลี่ยนหน้า (`view-transition-name: site-header`)
- จอเล็กกว่า 900 เป็นแถวเดียวสูง 56: โลโก้ ช่องค้นหา ไอคอนตะกร้ากับตัวเลข และปุ่มเมนู จอ 900 ขึ้นไปลิงก์เรียงชิดขวาในแถวเดียวกัน ไอคอนใหม่ (เช่นกระดิ่งแจ้งเตือน) วางเป็น `header-icon-button` ถัดจากตะกร้า ตัวเลขบนไอคอนใช้ class `cart-count`
- ไอคอนตะกร้ามี attribute `data-cart-target` เป็นปลายทางของ `flyToCart()`
- ช่องค้นหา แถบ `.search-preview` (SNT-011) `HeaderMenu` และ `.seller-menu` ทำงานเหมือนรอบ 2

## รายการตรวจเมื่อปรับหน้าตา module ของ feature หนึ่ง

1. อ่านแผนของหน้านั้นใน `docs/research/lively-design.md` ข้อ (f) และดูหน้าแบบอย่าง
2. เปิด test ของ feature ก่อน หลายตัวอ่าน CSS หรือ markup ตรงๆ แก้ test เฉพาะที่ตรวจโครงหรือหน้าตาที่ตั้งใจเปลี่ยน ห้ามแก้ข้อที่ตรวจพฤติกรรม
3. module ที่ยังไม่ได้ปรับถูกแทน token แบบกลไกแล้ว: `--color-surface` เดิมเป็น `--color-surface-sunken` และพื้น `--color-bg` คือสีกระดาษ ให้เปลี่ยนกล่องสรุปยอดและกลุ่มข้อมูลเป็น `card` แถบที่ติดขอบจอและแผ่นที่กางทับเป็น `--color-surface` กับ `--shadow-2` แทนเส้นขอบ
4. สถานะที่เป็นตัวหนังสือดำเปลี่ยนเป็น `badge` ตามตารางข้างบน ข้อความสำเร็จใช้ `badge-success` หรือสี `--color-primary-press`
5. ปุ่มขอบดำที่ซ้ำทุกแถวเป็น `link-action` มุมใช้ `--radius-*` ตามบทบาท รูปได้มุม
6. ใส่การขยับจากตาราง: `lift` กับการ์ดที่กดได้ `reveal` กับรายการยาว `SkeletonExit` กับ `PageReveal` หรือ `PageSlide` ใน `loading.tsx` กับ `page.tsx`
7. ข้อความหรือพฤติกรรมที่ต้องเปลี่ยน ใช้คำตาม `GLOSSARY.md` เปลี่ยนน้อยที่สุด และเขียน "agent ตัดสินใจ: ... (วันที่)" ในส่วนที่ 8 ของไฟล์ใน `docs/requirements/`
8. ถ่ายภาพจอแรกและทั้งหน้าที่ 1440x900 และ 390x844 ลง `docs/screenshots/design-3/` แล้วเปิดดูเองทุกภาพ repo นี้ public จึงเก็บใน git เฉพาะภาพจอแรก (`*-first-screen.png`) ภาพทั้งหน้าใช้ดูในเครื่องเท่านั้น `.gitignore` กันไม่ให้ถูก commit ถ้าเอกสารต้องลิงก์ถึงภาพทั้งหน้าภาพใด ให้เพิ่มข้อยกเว้นของภาพนั้นใน `.gitignore` ภาพทั้งหน้าให้ตั้งความสูงจอเท่าความสูงหน้า (ไม่ใช้ `fullPage`) ของที่โผล่ตามการเลื่อนและแถบที่ติดขอบจอจึงอยู่ในสภาพสุดท้าย รอ animation ตอนเข้าจบก่อนถ่าย
9. รัน e2e ด้วยพอร์ตของตัวเอง `E2E_PORT=<พอร์ตว่าง> pnpm e2e` แล้ว `pnpm check` กับ `pnpm e2e` ต้องผ่าน
