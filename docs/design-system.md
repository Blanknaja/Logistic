# หน้าตาของแอป รอบ 2

รอบนี้ทำตามคำสั่งของเจ้าของโปรเจค: เรียบ อ่านง่าย ให้ข้อมูลที่ผู้ใช้มาหา โดยใช้วิธีของร้าน Apple ที่ศึกษาไว้ใน `docs/research/apple-store-design.md` (ส่วน 2 คือปัญหาของแต่ละหน้า ส่วน 3 คือข้อเสนอ) พื้นขาว ตัวหนังสือไม่มีเชิง สีเน้นเขียวเข้มสีเดียว แบ่งส่วนด้วยระยะว่างก่อน เส้นเป็นตัวช่วย

- ค่าทุกตัวอยู่ใน `:root` ของ `src/app/globals.css` ใช้ผ่าน `var()` เท่านั้น ห้ามพิมพ์สี ขนาดตัวอักษร หรือระยะเป็นตัวเลขเอง
- ฟอนต์โหลดครั้งเดียวใน `src/app/layout.tsx` ด้วย `next/font` ห้ามโหลดฟอนต์อื่นเพิ่ม
- หน้าแบบอย่างคือหน้าสินค้า `src/app/products/[productId]/page.tsx` กับส่วน "หน้ารายละเอียดสินค้า" ใน `src/features/browse/components/browse.module.css` ภาพอยู่ที่ `docs/screenshots/design/product-1-*.png` และ `product-6-*.png`

## กฎ

- สีเน้นมีสองที่เท่านั้น: พื้นของปุ่มหลักปุ่มเดียวของหน้า (`class="button"`) และขอบ 2px ของตัวเลือกที่เลือกอยู่ (`--selected-ring`) เช่น วิธีจ่าย ที่อยู่ chip ค่าตัวเลือก รูปย่อ ห้ามใช้กับลิงก์ ราคา หัวข้อ หรือสถานะ ไฟล์ CSS ของ feature ไม่ใช้ `--color-primary` ตรงๆ (test `src/app/design-system.test.ts` ตรวจ)
- ปุ่มอื่นที่เป็นงานจริงใช้ `button button-secondary` การกระทำรองในแถวรายการ ("ลบ" "ดูการจัดส่ง" "ประวัติสต็อก" "ยกเลิก") ใช้ `link-action`
- แถวหนึ่งมี `button button-secondary` ได้หนึ่งปุ่ม เมื่อปุ่มนั้นคืองานที่ผู้ใช้เปิดรายการนี้มาทำ เช่น "จัดส่ง" ในรายการคำสั่งซื้อของร้าน และ "บันทึก" ของแถวสต็อก ซึ่งขึ้นพร้อม "ยกเลิก" ที่เป็นปุ่มรองคู่กันเฉพาะตอนที่แก้ตัวเลขแล้ว การเปิดดูหรือไปหน้าอื่นยังเป็น `link-action`
- หน้าต่างถามยืนยัน (`<dialog>` ที่เปิดด้วย `showModal()`) เป็นพื้นผิวของตัวเอง ระหว่างที่เปิด ปุ่มหนึ่งปุ่มในหน้าต่างเป็น `button` ได้ แม้หน้าข้างหลังมีปุ่มหลักอยู่แล้ว การถามยืนยันที่วางในหน้า (ไม่ใช่หน้าต่าง) นับเป็นส่วนของหน้า ปุ่มหลักเดิมของหน้าต้องเป็น `button-secondary` หรือซ่อนระหว่างถาม แบบหน้าที่อยู่จัดส่งและหน้าคำสั่งซื้อ
- ปุ่มที่ยืนยันการลบหรือการยกเลิกที่ย้อนไม่ได้ (ลบสินค้า เอาออกจากตะกร้า ลบที่อยู่ ยกเลิกคำสั่งซื้อ) ใช้ `button button-secondary` ไม่ใช้สีเขียว ทางที่ไม่เปลี่ยนอะไรข้างกัน เช่น "ยกเลิก" "ไม่ลบ" "ไม่ยกเลิก" "อยู่ต่อ" เป็น `button` แทน ฟอร์มที่ใช้ `ActionForm` ใส่ `destructive` ส่วนการยืนยันที่ไม่ได้ลบหรือยกเลิก เช่น "ได้รับสินค้าแล้ว" ใช้ `button` ตามปกติ
- ตัวหนังสือมีสองน้ำหนักคือ 400 กับ 600 ตัวหนาใช้ได้แค่สี่ที่: `h1` `h2` (รวม `legend` ที่เป็นหัวส่วนของฟอร์ม) ปุ่ม และยอดที่ต้องจ่าย ป้ายช่องกรอก ชื่อร้าน สถานะ ยอดรวมที่ไม่ใช่ยอดที่ต้องจ่าย และข้อมูลรองเป็น 400
- ช่องกรอกพื้นขาว ขอบ `--color-border-strong` 1px มุม `--radius` ข้อผิดพลาดอยู่ใต้ช่องด้วย `field-error` และช่องได้ `aria-invalid="true"` ซึ่งทำให้ขอบเป็น `--color-danger` ทั้ง `input` `select` และ `textarea` ขอบสีแดงนี้ไม่เปลี่ยนตอนชี้หรือโฟกัส วงโฟกัสยังขึ้นตามปกติ
- ข้อความสำเร็จใช้สีตัวหนังสือปกติ ไม่มีสีเขียว
- มุมใช้ `--radius` อย่างเดียว รูปและกรอบรูปไม่มีมุม ห้าม `999px` ยกเว้นโลโก้ร้านที่อยู่ในวงกลมตาม SHP-008
- ไม่มีเงา ไม่มี gradient ส่วนของหน้าแยกกันด้วย `--section-gap` ใช้เส้น `--color-border` คั่นแถวในรายการ เส้น `--color-text` ใช้เปิดส่วนสำคัญได้หน้าละไม่เกินหนึ่งเส้น
- ระยะในกลุ่มใช้ `--space-1` ถึง `--space-4` ระหว่างกลุ่มในส่วนเดียวกันใช้ `--space-5` ระหว่างส่วนของหน้าใช้ `--section-gap`
- รูปสินค้าในรายการและแถว (การ์ดหน้าแรก ผลค้นหา หน้าร้าน ตะกร้า หน้าสั่งซื้อ คำสั่งซื้อ หลังบ้าน รูปย่อในแกลเลอรี) เต็มกรอบสี่เหลี่ยมจัตุรัสด้วย `object-fit: cover` ตรงกลาง ทุกรูปในรายการจึงขนาดเท่ากัน ไม่มีช่องขาวข้างรูป รูปใหญ่ในหน้าสินค้า (`.plate`) แสดงทั้งรูปด้วย `object-fit: contain` บนกรอบสี่เหลี่ยมจัตุรัสพื้น `--color-surface` test `src/app/design-system.test.ts` ตรวจว่ามี `contain` แค่ที่กรอบนี้
- เนื้อหาอยู่ใน `.container` ที่ layout ใส่ให้แล้ว ของที่ต้องชนขอบจอใช้ `margin-inline: calc(-1 * var(--gutter))`
- วงโฟกัสตั้งไว้ที่ `:focus-visible` ทั้งแอปแล้ว ห้าม `outline: none` ถ้าซ่อน input ไว้ เช่น radio ใน chip ให้ใส่วงที่ตัวห่อด้วย `:has(input:focus-visible)` แบบ `.choice` ใน `browse.module.css`
- hover เปลี่ยนสีหรือเส้นขอบด้วย `--duration` `--ease` และห่อด้วย `@media (hover: hover)` ตอนกดย่อ `scale(0.98)` ไม่มีของที่ขยับตามการเลื่อนหน้า
- breakpoint มีสามค่า เขียนจอเล็กก่อนแล้วใช้ `min-width` ยกเว้นกฎที่มีเฉพาะจอเล็กกว่า breakpoint เช่น แถบที่ติดขอบล่างจอ และตัวกรองหรือเมนูที่พับหรือเป็นแถวเดียวเลื่อนซ้ายขวา ใช้ `max-width: 899px` หรือ `max-width: 599px` ได้ จะได้ไม่ต้องเขียนกฎล้างค่าที่จอกว้าง กฎอื่นทั้งหมดใช้ `min-width` test `src/app/design-system.test.ts` ตรวจว่า `max-width` มีแค่สองค่านี้
  - 600: gutter 32 รูปย่อใหญ่ขึ้น โลโก้ใหญ่ขึ้น กรอบรูปใหญ่ของหน้าสินค้าเลิกชนขอบจอและกว้างไม่เกิน 640
  - 900: gutter 48 หัวเรื่องใหญ่ขึ้น แถบด้านบนเรียงลิงก์ในแถวเดียว หน้าที่มีงานหลักหนึ่งอย่างแบ่งสองคอลัมน์ 7:5 (`minmax(0, 7fr) minmax(0, 5fr)`) ของที่ดูอยู่ซ้าย ส่วนที่ต้องกดอยู่ขวา
  - 1200: เนื้อหาหยุดกว้างที่ `--content-width`
- ปุ่มหลักต้องกดได้ในจอแรกทั้ง 390x844 และ 1440x900 บนจอเล็กกว่า 900 ถ้าอยู่ต่ำกว่าจอแรก ให้ติดขอบล่างจอแบบ `.buyBar` ของหน้าสินค้า แล้วเว้นท้ายหน้าไว้ไม่ให้แถบบังเนื้อหา
- จอกว้าง 360 จุดต้องไม่ล้นจนเลื่อนซ้ายขวาได้ e2e ตรวจทุกหน้าในเส้นทางหลัก
- ของที่ซ่อนไว้หรือจองที่ไว้โดยหวังให้สคริปต์มาเปิดหรือเติม เช่น ปุ่มของแถวสต็อกและกรอบแผนที่ ให้ขึ้นกับสถานะที่ component ตั้งเองหลังเริ่มทำงาน (`useSyncExternalStore(noSubscribe, () => true, () => false)` แบบ `stock-row.tsx` และ `delivery-map.tsx`) ไม่ใช้ `@media (scripting)` เพราะเบราว์เซอร์ที่เปิด JavaScript แต่โหลดสคริปต์ของแอปไม่ได้ก็ตอบว่ามีสคริปต์ test `src/app/design-system.test.ts` ตรวจ
- วันเวลาแสดงด้วย `formatThaiDateTime` ("25 พ.ย. 13:07") `formatThaiDate` ("25 พ.ย.") `formatTime` ("13:07") หรือ `formatTimeOrDateTime` (วันนี้ได้แค่เวลา วันอื่นได้วันกับเวลา) จาก `src/shared/format.ts` ปีโผล่เองเมื่อไม่ใช่ปีนี้ ห่อด้วย `<time dateTime={ค่า ISO}>` ไม่มีที่ไหนแสดงแบบ "25/11/2026"

## แถบด้านบนและเมนูหลังบ้าน

- จอเล็กกว่า 900 เป็นแถวเดียวสูง 56: โลโก้ ช่องค้นหาสินค้า ไอคอนตะกร้ากับตัวเลข และปุ่มเมนู ลิงก์อื่นอยู่ในเมนู จอ 900 ขึ้นไปลิงก์เรียงต่อในแถวเดียวกัน
- ลิงก์ในเมนูมาจาก `nav.ts` ของแต่ละ feature เหมือนเดิม ไอคอนตะกร้า `SiteHeader` วาดเอง (`src/shared/layout/site-header.tsx`)
- ปุ่มเมนูคือ `HeaderMenu` (`src/shared/layout/header-menu.tsx`) ก่อน JavaScript ทำงานเป็น `<details>` หลังจากนั้นเป็นปุ่มที่มี `aria-expanded` ปิดด้วย Escape กดข้างนอก หรือเปลี่ยนหน้า e2e อยู่ที่ `e2e/site-header.spec.ts`
- เมนูหลังบ้านของร้านบนจอเล็กเป็นแถวเดียวที่เลื่อนซ้ายขวา (`.seller-menu`)
- หน้าไม่ต้องใส่ช่องค้นหาสินค้าเอง ช่องในแถบด้านบนส่ง `q` ไปหน้าแรก
- ระหว่างที่ช่องค้นหาถูกเลือกอยู่ แถบ `.search-preview` กว้างเต็มจอใต้แถบด้านบนบอกว่าระบบจะค้นอะไร (SNT-011) แถบนี้ลอยทับเนื้อหา ไม่ดันหน้าลง แสดงด้วย `:focus-within` ของช่องค้นหาและซ่อนเองเมื่อไม่มีข้อความ คำนำอย่าง "จะค้นหา" เป็น `--color-muted` ส่วนที่ระบบเข้าใจเป็นสีตัวหนังสือปกติ
- ตัวกรองที่ใช้อยู่ใต้จำนวนผลลัพธ์เป็นลิงก์ข้อความที่มีกากบาทสี `--color-muted` ตามหลัง (`.remove` ใน `browse.module.css`) กดแล้วเอาเฉพาะอันนั้นออก ไม่ใช้กรอบแบบ chip เพื่อไม่ให้ปนกับ chip หมวดหมู่ที่เป็นตัวเลือก

## class กลางใน globals.css

| `.button` | ปุ่มหลักปุ่มเดียวของหน้า ใช้กับ `a` หรือ `button` |
| `.button.button-secondary` | ปุ่มรองที่เป็นงานจริง เช่น "ลองใหม่" "ใช้ตัวกรอง" |
| `.link-action` | การกระทำรองในแถวรายการ ลิงก์ขีดเส้นใต้สีตัวหนังสือ ขนาด `--text-label` สูงอย่างน้อย `--tap` ใช้กับ `a` หรือ `button` |
| `.input` | `input` `select` `textarea` |
| `.field` `.field-error` | ตัวห่อป้ายกับช่อง และข้อความผิดพลาดใต้ช่อง |
| `.chips` `.chip` | ตัวกรองและค่าตัวเลือก chip ที่มี `aria-current` `aria-pressed="true"` หรือมี input ที่เลือกอยู่ ได้ `--selected-ring` เอง |
| `.state` `.state-title` `.state-message` `.state-actions` | หน้าว่าง กำลังโหลด ผิดพลาด ไม่พบ (`src/shared/ui/states.tsx`) หัวข้อเป็น `h1` เมื่อกล่องคือเนื้อหาทั้งหน้า และ `h2` เมื่อวางในหน้าที่มี `h1` แล้ว ตาเห็นขนาด `--text-heading` เท่ากัน `NotFoundState` `ErrorState` `LoadingState` เป็น `h1` เอง `EmptyState` เป็น `h2` เอง เปลี่ยนด้วย `level` |
| `.visually-hidden` | ข้อความที่โปรแกรมอ่านจอต้องได้ยินแต่ตาไม่ต้องเห็น เช่นชื่อของปุ่มที่เป็นไอคอน |
| `.nav-list` `.nav-link` `.seller-menu` `.site-header*` `.header-*` `.brand` | แถบด้านบนและเมนูหลังบ้าน ไม่ใช้ในหน้า |

`.card` ถูกลบแล้ว ตามหลัก "ไม่ตีกรอบ" ข้างล่าง

ใน `*.module.css` ชื่อ class กลางต้องห่อด้วย `:global()` เช่น `.actions > :global(.button)` ถ้าไม่ห่อ CSS modules จะเปลี่ยนชื่อ class และกฎนั้นไม่มีผล

## หลักการจัดข้อมูล

ทุกหน้าต้องผ่านทุกข้อ ข้อไหนต้องเปลี่ยนข้อความหรือพฤติกรรม ให้ทำน้อยที่สุดแล้วบันทึกเป็น "agent ตัดสินใจ" ในไฟล์ requirement ของ feature นั้น

| หลัก | วิธีตรวจ |
|---|---|
| จอแรกมีสิ่งที่ผู้ใช้มาหา | เปิดภาพจอแรกที่ 390x844 และ 1440x900 แล้วชี้ได้ว่าคำตอบของหน้าอยู่ตรงไหน (เช่น สถานะ ยอด สินค้า ช่องที่ต้องกรอก) และปุ่มหลักกดได้โดยไม่ต้องเลื่อน |
| หัวเรื่องบอกคำตอบ ตัวระบุเป็นข้อมูลรอง | `h1` หรือบรรทัดแรกใต้ `h1` คือสถานะหรือยอด ส่วนเลขคำสั่งซื้อ เลขพัสดุ และวันที่ใช้ `--text-label` หรือ `--text-body` สี `--color-muted` |
| ปุ่มสีเน้นหน้าละหนึ่งปุ่ม | ค้นในหน้าที่เรนเดอร์แล้วว่ามี `class="button"` ที่ไม่มี `button-secondary` ไม่เกินหนึ่งตัว |
| การกระทำรองในแถวเป็นลิงก์ข้อความ | ปุ่มที่ซ้ำกันทุกแถวและใช้เปิดดูหรือไปหน้าอื่นใช้ `link-action` ไม่ใช่ `button` แถวหนึ่งมีกรอบได้เฉพาะช่องกรอก กับปุ่มรองหนึ่งปุ่มที่เป็นงานที่ผู้ใช้เปิดรายการนี้มาทำ ("จัดส่ง" "บันทึก" ของแถวสต็อก) |
| ตัวเลขเดียวกันไม่พูดสองครั้ง | อ่านภาพของหน้าทีละบรรทัด ถ้าเลขเดียวกันโผล่สองที่ในส่วนเดียวกัน (เช่น ราคาต่อชิ้นกับยอดของแถวเมื่อมีชิ้นเดียว) ให้เหลือที่เดียว |
| ช่องกรอกกว้างตามข้อมูล | รหัสไปรษณีย์ รหัสหลังบัตร เดือนปีหมดอายุ จำนวน กว้างไม่เกิน `12ch` บนจอ 600 ขึ้นไป ช่องข้อความยาวกว้างไม่เกิน `--measure` |
| ตัวหนาเฉพาะหัวเรื่อง หัวส่วน ปุ่ม และยอดที่ต้องจ่าย | ค้น `font-weight: 600` ใน module ของหน้า ทุกตัวต้องเป็นหนึ่งในสี่อย่างนี้ |
| หน้าหนึ่งใช้ตัวหนังสือไม่เกิน 5 ขนาด | นับ `--text-*` ที่หน้าใช้รวมแถบด้านบน ตอนนี้มีให้แค่ 4 ขนาด ห้ามเพิ่ม |
| ไม่ตีกรอบสิ่งที่ไม่ใช่ช่องกรอกหรือปุ่ม | ค้น `border:` และ `box-shadow: inset` ใน module ที่ไม่ได้อยู่กับช่องกรอก ปุ่ม chip หรือการ์ดตัวเลือก ให้เปลี่ยนเป็นระยะว่างหรือเส้นคั่นบนล่าง |

## รายการตรวจเมื่อปรับหน้าตา module ของ feature หนึ่ง

1. อ่านปัญหาของหน้านั้นใน `docs/research/apple-store-design.md` ส่วน 2.2 และข้อเสนอที่เกี่ยวข้องในส่วน 3.5
2. เปิด test ของ feature นั้นก่อน หลายตัวอ่านไฟล์ CSS หรือ markup ตรงๆ เช่น `class="button"` และ `min-width: var(--tap)` แก้ test เฉพาะที่ตรวจโครง รูปแบบ หรือข้อความที่ตั้งใจเปลี่ยน
3. สีที่พิมพ์เอง (`#...` `rgb(...)`) เปลี่ยนเป็น token ถ้าไม่มีตัวที่ตรง ให้เพิ่มใน `globals.css` กับตารางข้างบนพร้อมกัน ห้ามมีสองชื่อที่ค่าเดียวกันและใช้กับเรื่องเดียวกัน
4. ระยะ (`4px` `8px` `12px`) เปลี่ยนเป็น `--space-*` ระหว่างส่วนของหน้าเปลี่ยนเป็น `--section-gap` ขนาดตัวอักษรเปลี่ยนเป็น `--text-*`
5. ไล่ `--color-primary` ทุกที่ เหลือไว้เฉพาะปุ่มหลักของหน้า ตัวเลือกที่เลือกอยู่เปลี่ยนจาก `inset 0 0 0 2px var(--color-text)` เป็น `var(--selected-ring)`
6. ไล่ `font-weight: 600` ให้เหลือตามหลักตัวหนา ทั้งแอปไม่มี `700` แล้ว
7. ปุ่มขอบดำที่ซ้ำทุกแถวเปลี่ยนเป็น `link-action` เว้นปุ่มรองหนึ่งปุ่มที่เป็นงานที่ผู้ใช้เปิดรายการนี้มาทำ กรอบที่ไม่ใช่ช่องกรอกหรือปุ่มเอาออก
8. วันเวลาใช้ `formatThaiDateTime` หรือ `formatThaiDate` ไม่ตัดสตริงเอา ถ้าอยากได้แค่เวลาใช้ `formatTime`
9. ข้อความ ชื่อช่องในฟอร์ม ที่อยู่หน้าเว็บ หรือพฤติกรรมที่ต้องเปลี่ยน ให้ใช้คำตาม `GLOSSARY.md` เปลี่ยนน้อยที่สุด และเขียน "agent ตัดสินใจ: ... (วันที่)" ในส่วนสมมติฐานของไฟล์ใน `docs/requirements/` ที่ตรงกับ feature
10. ถ่ายภาพจอแรกและภาพทั้งหน้าที่ 1440x900 และ 390x844 ลง `docs/screenshots/design/` แล้วเปิดดูเองทุกภาพ ตรวจตามตาราง "หลักการจัดข้อมูล" ใช้ Playwright ของ repo กับ Chrome ในเครื่อง เช่น `pnpm exec playwright screenshot --channel chrome --viewport-size 390,844 <ที่อยู่> <ไฟล์>` ภาพแบบ `--full-page` วาดแถบที่ติดขอบจอไว้กลางภาพ ถ้าหน้ามีแถบแบบนี้ ให้ตั้งความสูงจอเท่าความสูงหน้าแทน
11. ถ้าทำหลาย worktree พร้อมกัน รัน e2e ด้วยพอร์ตของตัวเอง `E2E_PORT=<พอร์ตว่าง> pnpm e2e` เพราะพอร์ต 3300 อาจมี worktree อื่นใช้อยู่
12. `pnpm check` และ `pnpm e2e` ผ่าน
