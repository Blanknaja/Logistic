## 1. เป้าหมายและตัวเลขความสำเร็จ

- เป้าหมาย: ผู้ซื้อพักสินค้าจากหลายร้านไว้ในที่เดียว เห็นราคาและยอดรวมที่ถูกต้อง ณ ตอนนั้น แล้วเลือกได้ว่าจะสั่งซื้อรายการไหน
- วัดความสำเร็จจาก: คนหนึ่งคนที่เข้าสู่ระบบแล้ว เพิ่มสินค้า 2 ชิ้นจาก 2 ร้านลงตะกร้า แล้วไปถึงหน้าสั่งซื้อได้ภายใน 1 นาที โดยไม่มีใครช่วย วัดจากการลองทำ 5 ครั้งกับข้อมูลตัวอย่าง ต้องผ่านทั้ง 5 ครั้ง

## 2. ขอบเขต

### ทำ

- ผู้ซื้อที่เข้าสู่ระบบแล้ว เพิ่มแบบย่อยของสินค้าพร้อมจำนวนลงตะกร้า
- หน้าตะกร้าที่จัดกลุ่มรายการตามร้าน
- เปลี่ยนจำนวน และลบรายการ
- เลือกรายการที่จะสั่งซื้อ เห็นยอดรวมของแต่ละร้านและยอดรวมทั้งหมด
- แจ้งเมื่อร้านแก้ราคาหลังสินค้าอยู่ในตะกร้า
- แสดงรายการที่ซื้อไม่ได้ และกันไม่ให้เลือกไปสั่งซื้อ
- ปุ่มไปหน้าสั่งซื้อ พร้อมตรวจราคา สต็อก และสถานะสินค้าอีกครั้งก่อนไป
- สิ่งที่เกิดเมื่อคนที่ยังไม่เข้าสู่ระบบกดเพิ่มสินค้าลงตะกร้า

### ไม่ทำ

- ไม่สร้างคำสั่งซื้อและไม่เลือกที่อยู่ เพราะอยู่ใน CHK ค่าส่งในตะกร้าคิดตามกฎของ CHK-004 (40 บาทต่อร้าน) เพื่อบอกยอดล่วงหน้าเท่านั้น ยอดที่ใช้จริงคิดที่หน้าสั่งซื้อ
- ไม่รับจ่ายเงิน เพราะอยู่ใน PAY
- ไม่ใช้คูปองหรือส่วนลดในตะกร้า เพราะอยู่ใน PRM
- ไม่ทำ "เก็บไว้ซื้อทีหลัง" และรายการสินค้าที่ชอบ เพราะไม่อยู่ในเส้นทางหลัก ผู้ซื้อเลิกเลือกรายการที่ยังไม่อยากซื้อแทนได้
- ไม่จองสต็อกตอนสินค้าอยู่ในตะกร้า เพราะสต็อกถูกจองตอนกดสั่งซื้อ (ดู INV-009) สินค้าในตะกร้าจึงหมดก่อนสั่งซื้อได้
- ไม่มีตะกร้าของคนที่ยังไม่เข้าสู่ระบบ เพราะตะกร้าผูกกับบัญชี
- ไม่จำกัดจำนวนรายการในตะกร้า เพราะยังไม่มีผู้ใช้จริง ตัวเลขคุณภาพวัดที่ 50 รายการ

### ข้อจำกัด

- ต้องเสร็จพร้อม feature ชุด 1 ภายในเช้าวันที่ 2026-11-25
- ราคา สต็อก และสถานะของสินค้าและร้าน มาจาก PRD INV และ SHP ตะกร้าแสดงค่าล่าสุดเสมอ ไม่เก็บราคาไว้ใช้คิดเงินเอง
- การเข้าสู่ระบบมาจาก ACC

## 3. ผู้ใช้และสิทธิ์

| บทบาท | ทำได้ | ทำไม่ได้ |
|---|---|---|
| ผู้ซื้อ (เข้าสู่ระบบแล้ว) | เพิ่ม ดู เปลี่ยนจำนวน ลบ และเลือกรายการในตะกร้าของตัวเอง แล้วไปหน้าสั่งซื้อ | ดูหรือแก้ตะกร้าของบัญชีอื่น ใส่จำนวนเกินสต็อก เลือกรายการที่ซื้อไม่ได้ไปสั่งซื้อ |
| ผู้ขาย | ใช้ตะกร้าแบบผู้ซื้อกับสินค้าของร้านอื่น | เพิ่มสินค้าของร้านตัวเองลงตะกร้า ดูว่าสินค้าของร้านอยู่ในตะกร้าของใคร |
| ผู้ดูแลแพลตฟอร์ม | ใช้ตะกร้าของบัญชีตัวเองแบบผู้ซื้อ | ดูหรือแก้ตะกร้าของบัญชีอื่น |
| คนที่ยังไม่เข้าสู่ระบบ | กดปุ่มใส่ตะกร้า แล้วถูกพาไปหน้าเข้าสู่ระบบ | มีตะกร้า หรือเปิดหน้าตะกร้า |

## 4. Requirements

### CRT-001 เพิ่มสินค้าลงตะกร้า

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อที่เข้าสู่ระบบแล้วเลือกค่าตัวเลือกครบทุกตัวเลือก ใส่จำนวนเป็นเลขเต็มตั้งแต่ 1 ขึ้นไป แล้วกด "ใส่ตะกร้า" ในหน้ารายละเอียดสินค้า THE SYSTEM SHALL เพิ่มรายการในตะกร้าหนึ่งรายการที่มีสถานะเลือกไว้ แสดงข้อความ "ใส่ตะกร้าแล้ว" และแสดงจำนวนรายการในตะกร้าที่ไอคอนตะกร้า

กรณีปกติ

- Given สมชายเข้าสู่ระบบแล้ว ตะกร้ามี 2 รายการ เวลา 14:05 เขาเปิดหน้ารายละเอียดสินค้า "เสื้อยืดคอกลม" ของร้านบ้านผ้า ราคา 250 บาท สต็อก 10 ชิ้น
- When สมชายเลือกสีดำ ขนาด L ใส่จำนวน 2 แล้วกด "ใส่ตะกร้า"
- Then สมชายเห็นข้อความ "ใส่ตะกร้าแล้ว" ไอคอนตะกร้าแสดงเลข 3 และยังอยู่ที่หน้ารายละเอียดสินค้าเดิม ระหว่างรอผล ปุ่มกดซ้ำไม่ได้

กรณีผิดพลาด

- Given สมชายเปิดหน้ารายละเอียดสินค้าเดิม เวลา 14:07 สินค้ามีตัวเลือกสีและขนาด ตะกร้ามี 3 รายการ
- When สมชายเลือกสีดำแต่ยังไม่เลือกขนาด แล้วกด "ใส่ตะกร้า" หรือใส่จำนวนเป็น 0 หรือเว้นว่าง
- Then สมชายเห็นข้อความ "กรุณาเลือกขนาด" หรือ "จำนวนต้องเป็น 1 ขึ้นไป" ตะกร้ายังมี 3 รายการเท่าเดิม

### CRT-002 เพิ่มสินค้าที่มีอยู่ในตะกร้าแล้ว

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อเพิ่มแบบย่อยเดียวกับรายการที่อยู่ในตะกร้าแล้ว THE SYSTEM SHALL บวกจำนวนเข้ากับรายการเดิมแทนการสร้างรายการใหม่

กรณีปกติ

- Given สมหญิงมีเสื้อยืดคอกลม สีดำ ขนาด L จำนวน 2 ชิ้นในตะกร้า ตะกร้ามี 1 รายการ สต็อก 10 ชิ้น เวลา 09:30
- When สมหญิงเพิ่มสินค้าเดิม สีดำ ขนาด L อีก 3 ชิ้น
- Then ตะกร้ายังมี 1 รายการ จำนวนเป็น 5 ชิ้น ส่วนถ้าเธอเพิ่มสีขาว ขนาด L ตะกร้าจะมี 2 รายการ

กรณีผิดพลาด

- Given สมหญิงมีสินค้าเดิม 8 ชิ้นในตะกร้า สต็อก 10 ชิ้น เวลา 09:35
- When สมหญิงเพิ่มสินค้าเดิมอีก 5 ชิ้น ซึ่งรวมแล้วเป็น 13 ชิ้น
- Then สมหญิงเห็นข้อความ "เพิ่มได้อีกไม่เกิน 2 ชิ้น เพราะในตะกร้ามีอยู่แล้ว 8 ชิ้น" จำนวนในตะกร้ายังเป็น 8 ชิ้น

### CRT-003 คนที่ยังไม่เข้าสู่ระบบกดใส่ตะกร้า

- ลำดับความสำคัญ: ต้องมี
- IF คนที่ยังไม่เข้าสู่ระบบกด "ใส่ตะกร้า" หรือเปิดหน้าตะกร้า THEN THE SYSTEM SHALL พาไปหน้าเข้าสู่ระบบ (ดู ACC-008) โดยไม่เพิ่มสินค้า และพากลับมาหน้าเดิมหลังเข้าสู่ระบบสำเร็จ

กรณีปกติ

- Given มานียังไม่เข้าสู่ระบบ เวลา 20:10 เธอเปิดหน้ารายละเอียดสินค้า "แก้วเซรามิก" ราคา 120 บาท
- When มานีกด "ใส่ตะกร้า" แล้วเข้าสู่ระบบสำเร็จเวลา 20:11
- Then มานีกลับมาที่หน้ารายละเอียดสินค้า "แก้วเซรามิก" ตะกร้าของเธอยังไม่มีแก้วใบนี้ เธอต้องเลือกค่าตัวเลือกและกด "ใส่ตะกร้า" อีกครั้ง

กรณีผิดพลาด

- Given มานียังไม่เข้าสู่ระบบ เวลา 20:15 เธอกด "ใส่ตะกร้า" และถูกพาไปหน้าเข้าสู่ระบบ
- When มานีกดย้อนกลับโดยไม่เข้าสู่ระบบ
- Then มานีกลับมาที่หน้ารายละเอียดสินค้าเดิมในฐานะคนที่ยังไม่เข้าสู่ระบบ ไม่มีสินค้าถูกใส่ตะกร้าใด

### CRT-004 ผู้ขายเพิ่มสินค้าของร้านตัวเองไม่ได้

- ลำดับความสำคัญ: ต้องมี
- IF ผู้ขายพยายามเพิ่มสินค้าของร้านตัวเองลงตะกร้า THEN THE SYSTEM SHALL ไม่เพิ่มสินค้า และแสดงข้อความ "ซื้อสินค้าจากร้านตัวเองไม่ได้"

กรณีปกติ

- Given วิชัยเป็นเจ้าของร้านบ้านผ้า เวลา 11:00 เขาเปิดหน้ารายละเอียดสินค้า "หมอนอิง" ของร้านสวนหลังบ้าน ราคา 180 บาท
- When วิชัยใส่จำนวน 1 แล้วกด "ใส่ตะกร้า"
- Then หมอนอิง 1 ชิ้นเข้าตะกร้าของวิชัยตามปกติ เพราะเป็นสินค้าของร้านอื่น

กรณีผิดพลาด

- Given วิชัยเป็นเจ้าของร้านบ้านผ้า เวลา 11:05 เขาเปิดหน้ารายละเอียดสินค้า "เสื้อยืดคอกลม" ของร้านบ้านผ้า ตะกร้าของเขามี 1 รายการ
- When วิชัยดูปุ่ม "ใส่ตะกร้า" หรือส่งคำขอเพิ่มสินค้านี้จากอีกหน้าต่างหนึ่งที่เปิดค้างไว้ก่อนเปิดร้าน
- Then ปุ่มกดไม่ได้และมีข้อความ "ซื้อสินค้าจากร้านตัวเองไม่ได้" คำขอจากหน้าต่างเก่าถูกปฏิเสธด้วยข้อความเดียวกัน ตะกร้ายังมี 1 รายการ

### CRT-005 จำนวนไม่เกินสต็อก

- ลำดับความสำคัญ: ต้องมี
- IF ผู้ซื้อเพิ่มสินค้าหรือเปลี่ยนจำนวน จนจำนวนของรายการในตะกร้ามากกว่าสต็อกของแบบย่อยนั้น (ดู INV) THEN THE SYSTEM SHALL ไม่รับจำนวนนั้น คงจำนวนเดิมไว้ และแสดงจำนวนสูงสุดที่ใส่ได้

กรณีปกติ

- Given ปิติเปิดหน้ารายละเอียดสินค้า "รองเท้าผ้าใบ" ขนาด 42 สต็อก 3 ชิ้น เวลา 16:20 ตะกร้าของเขายังไม่มีสินค้านี้
- When ปิติใส่จำนวน 3 แล้วกด "ใส่ตะกร้า"
- Then รองเท้า 3 ชิ้นเข้าตะกร้า เพราะไม่เกินสต็อก

กรณีผิดพลาด

- Given ปิติมีรองเท้าผ้าใบ ขนาด 42 จำนวน 3 ชิ้นในตะกร้า สต็อก 3 ชิ้น เวลา 16:25
- When ปิติพิมพ์จำนวนเป็น 5 ในหน้าตะกร้า
- Then ปิติเห็นข้อความ "ใส่ได้ไม่เกิน 3 ชิ้น" จำนวนกลับเป็น 3 ชิ้น ยอดรวมไม่เปลี่ยน

### CRT-006 ดูตะกร้าแยกตามร้าน

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อเปิดหน้าตะกร้า THE SYSTEM SHALL แสดงรายการในตะกร้าของบัญชีนั้นจัดกลุ่มตามร้าน โดยร้านที่มีรายการเพิ่มล่าสุดอยู่บนสุด และแต่ละรายการแสดงรูป ชื่อสินค้า แบบย่อย ราคาปัจจุบันต่อชิ้น จำนวน และราคารวมของรายการ

กรณีปกติ

- Given สมชายมี 3 รายการในตะกร้า คือเสื้อยืดคอกลม 2 ชิ้น ชิ้นละ 250 บาท และกางเกงขาสั้น 1 ชิ้น 300 บาท จากร้านบ้านผ้า เพิ่มเมื่อ 14:05 กับแก้วเซรามิก 1 ใบ 120 บาท จากร้านดินเผา เพิ่มเมื่อ 14:20
- When สมชายเปิดหน้าตะกร้าเวลา 14:30 จากโทรศัพท์ ซึ่งเป็นคนละเครื่องกับที่ใช้เพิ่มสินค้า
- Then สมชายเห็นกลุ่มร้านดินเผาอยู่บน มี 1 รายการ ราคารวม 120 บาท และกลุ่มร้านบ้านผ้าอยู่ล่าง มี 2 รายการ ราคารวมของเสื้อ 500 บาท ของกางเกง 300 บาท ชื่อร้านกดไปหน้าร้านได้ (ดู SHP-011)

กรณีผิดพลาด

- Given สมชายเข้าสู่ระบบอยู่ เวลา 14:35 มีตะกร้าของบัญชีสมหญิงที่มี 5 รายการ
- When สมชายพยายามเปิดตะกร้าของสมหญิงด้วยการแก้ที่อยู่หน้าเว็บ
- Then สมชายเห็นเฉพาะตะกร้า 3 รายการของตัวเอง ไม่เห็นข้อมูลใดของสมหญิง

### CRT-007 หน้าตะกร้าว่าง

- ลำดับความสำคัญ: ต้องมี
- WHILE ตะกร้าของผู้ซื้อไม่มีรายการ THE SYSTEM SHALL แสดงข้อความ "ตะกร้ายังว่าง" พร้อมปุ่ม "เลือกซื้อสินค้า" ที่พาไปหน้าแรก (ดู BRW-001) และไม่แสดงยอดรวมกับปุ่ม "สั่งซื้อ"

กรณีปกติ

- Given อารีสมัครบัญชีเมื่อ 08:00 และยังไม่เคยเพิ่มสินค้า ตะกร้ามี 0 รายการ
- When อารีเปิดหน้าตะกร้าเวลา 08:05
- Then อารีเห็นข้อความ "ตะกร้ายังว่าง" และปุ่ม "เลือกซื้อสินค้า" ไอคอนตะกร้าไม่แสดงตัวเลข

กรณีผิดพลาด

- Given อารีมีแก้วเซรามิก 1 ใบในตะกร้า ซึ่งเป็นรายการเดียว เวลา 08:40
- When อารีลบรายการนั้น แล้วระบบบันทึกการลบไม่สำเร็จ
- Then อารียังเห็นแก้วเซรามิก 1 ใบในตะกร้าพร้อมข้อความผิดพลาดตาม CRT-009 หน้าไม่เปลี่ยนเป็นหน้าว่าง

### CRT-008 หน้าตะกร้ากำลังโหลด

- ลำดับความสำคัญ: ต้องมี
- WHILE ข้อมูลตะกร้ายังโหลดไม่เสร็จ THE SYSTEM SHALL แสดงโครงหน้าสีเทาแทนรายการ และไม่แสดงข้อความ "ตะกร้ายังว่าง" ยอดรวม หรือปุ่ม "สั่งซื้อ" ที่กดได้

กรณีปกติ

- Given สมชายมี 3 รายการในตะกร้า เวลา 18:00 สัญญาณเน็ตของเขาช้า
- When สมชายเปิดหน้าตะกร้า และข้อมูลใช้เวลา 1.5 วินาทีกว่าจะมา
- Then ระหว่าง 1.5 วินาทีนั้นสมชายเห็นโครงหน้าสีเทา แล้วเห็น 3 รายการเมื่อข้อมูลมาครบ

กรณีผิดพลาด

- Given สมชายมี 3 รายการในตะกร้า เวลา 18:05 ข้อมูลยังไม่มาหลังผ่านไป 10 วินาที
- When ครบ 10 วินาที
- Then โครงหน้าสีเทาหายไป สมชายเห็นข้อความผิดพลาดตาม CRT-009 ไม่เห็นข้อความ "ตะกร้ายังว่าง"

### CRT-009 โหลดหรือบันทึกตะกร้าไม่สำเร็จ

- ลำดับความสำคัญ: ต้องมี
- IF การโหลดตะกร้า หรือการเพิ่ม เปลี่ยนจำนวน ลบ หรือเลือกรายการ ไม่สำเร็จหรือไม่ได้ผลภายใน 10 วินาที THEN THE SYSTEM SHALL แสดงข้อความ "ทำรายการไม่สำเร็จ กรุณาลองใหม่" พร้อมปุ่ม "ลองใหม่" และคงข้อมูลตะกร้าไว้ตามที่บันทึกสำเร็จครั้งล่าสุด

กรณีปกติ

- Given สมหญิงมีเสื้อยืดคอกลม 2 ชิ้นในตะกร้า เวลา 21:00 เน็ตของเธอหลุด
- When สมหญิงกดเพิ่มจำนวนเป็น 3 ชิ้น แล้วเห็นข้อความ "ทำรายการไม่สำเร็จ กรุณาลองใหม่" จากนั้นเน็ตกลับมาเวลา 21:01 และเธอกด "ลองใหม่"
- Then จำนวนเป็น 3 ชิ้น ยอดรวมเปลี่ยนตาม ข้อความผิดพลาดหายไป

กรณีผิดพลาด

- Given สมหญิงมีเสื้อยืดคอกลม 2 ชิ้นในตะกร้า เวลา 21:10 เน็ตของเธอหลุด
- When สมหญิงกดเพิ่มจำนวนเป็น 3 ชิ้น เห็นข้อความผิดพลาด แล้วปิดหน้าไปโดยไม่กด "ลองใหม่"
- Then เมื่อสมหญิงเปิดตะกร้าอีกครั้งเวลา 21:30 จำนวนยังเป็น 2 ชิ้น หน้าจอไม่แสดงจำนวนที่บันทึกไม่สำเร็จ

### CRT-010 เปลี่ยนจำนวน

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อกดปุ่มบวก ปุ่มลบ หรือพิมพ์จำนวนของรายการในตะกร้าเป็นเลขเต็มตั้งแต่ 1 ถึงสต็อก THE SYSTEM SHALL บันทึกจำนวนใหม่ และแสดงราคารวมของรายการกับยอดรวมทั้งหมดตามจำนวนใหม่ โดยแสดงยอดรวมของร้านตามจำนวนใหม่เมื่อร้านนั้นมีรายการที่เลือกไว้มากกว่า 1 รายการและมีร้านที่เลือกไว้มากกว่า 1 ร้าน (กรณีอื่นยอดของร้านเท่ากับราคารวมของรายการหรือยอดรวมทั้งหมดที่แสดงอยู่แล้ว)

กรณีปกติ

- Given สมชายมีเสื้อยืดคอกลม 2 ชิ้น ชิ้นละ 250 บาทในตะกร้า รายการนี้ถูกเลือกไว้ สต็อก 10 ชิ้น เวลา 14:40
- When สมชายกดปุ่มบวก 1 ครั้ง
- Then จำนวนเป็น 3 ชิ้น ราคารวมของรายการเปลี่ยนจาก 500 เป็น 750 บาท และยอดรวมทั้งหมดเพิ่มขึ้น 250 บาท ร้านนี้มีรายการเดียว จึงไม่มียอดรวมของร้านแยกอีกบรรทัด

กรณีผิดพลาด

- Given สมชายเปิดตะกร้าเดียวกันบนโทรศัพท์และคอมพิวเตอร์ เสื้อยืดคอกลมมี 3 ชิ้น เวลา 14:45
- When สมชายเปลี่ยนเป็น 5 ชิ้นบนโทรศัพท์เวลา 14:45:10 แล้วเปลี่ยนเป็น 1 ชิ้นบนคอมพิวเตอร์เวลา 14:45:20 และพยายามกดปุ่มลบต่อจาก 1 ชิ้น
- Then จำนวนที่บันทึกคือ 1 ชิ้นตามการเปลี่ยนครั้งหลังสุด โทรศัพท์แสดง 1 ชิ้นเมื่อเปิดหน้าตะกร้าใหม่หรือทำรายการครั้งถัดไป ปุ่มลบกดไม่ได้เมื่อจำนวนเป็น 1 การเอาออกต้องใช้ปุ่มลบรายการตาม CRT-011

### CRT-011 ลบรายการ

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อกด "ลบ" ที่รายการในตะกร้า แล้วกด "ยืนยัน" ในหน้าต่างถาม "ลบสินค้านี้ออกจากตะกร้า?" THE SYSTEM SHALL เอารายการนั้นออกจากตะกร้า และแสดงยอดรวมกับจำนวนที่ไอคอนตะกร้าใหม่

กรณีปกติ

- Given สมชายมี 3 รายการในตะกร้า ร้านดินเผามีรายการเดียวคือแก้วเซรามิก 1 ใบ 120 บาท ซึ่งถูกเลือกไว้ ยอดรวมทั้งหมด 920 บาท เวลา 15:00
- When สมชายกด "ลบ" ที่แก้วเซรามิก แล้วกด "ยืนยัน"
- Then แก้วเซรามิกและกลุ่มร้านดินเผาหายจากหน้าตะกร้า ไอคอนตะกร้าแสดงเลข 2 ยอดรวมทั้งหมดเป็น 800 บาท

กรณีผิดพลาด

- Given สมชายมี 2 รายการในตะกร้า ยอดรวมทั้งหมด 800 บาท เวลา 15:05
- When สมชายกด "ลบ" ที่กางเกงขาสั้น แล้วกด "ยกเลิก" ในหน้าต่างถาม หรือกดยืนยันลบรายการที่ถูกลบไปแล้วจากอีกเครื่องหนึ่ง
- Then กรณีกด "ยกเลิก" ตะกร้ายังมี 2 รายการและยอดรวม 800 บาทเท่าเดิม กรณีรายการถูกลบไปแล้ว หน้าตะกร้าแสดงรายการที่เหลือจริงโดยไม่มีข้อความผิดพลาด

### CRT-012 เลือกรายการและดูยอดรวม

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อเลือกหรือเลิกเลือกรายการ ทั้งร้าน หรือทั้งตะกร้า THE SYSTEM SHALL จำการเลือกนั้นไว้กับบัญชี และแสดงยอดรวมทั้งหมดกับจำนวนชิ้นรวม โดยคิดจากราคาปัจจุบันคูณจำนวนของรายการที่เลือกไว้เท่านั้น และแสดงยอดรวมของแต่ละร้านเมื่อร้านนั้นมีรายการที่เลือกไว้มากกว่า 1 รายการและมีร้านที่เลือกไว้มากกว่า 1 ร้าน (กรณีอื่นยอดของร้านเท่ากับราคารวมของรายการหรือยอดรวมทั้งหมดที่แสดงอยู่แล้ว)

กรณีปกติ

- Given สมชายมีเสื้อยืดคอกลม 2 ชิ้น ชิ้นละ 250 บาท และกางเกงขาสั้น 1 ชิ้น 300 บาท จากร้านบ้านผ้า กับแก้วเซรามิก 1 ใบ 120 บาท จากร้านดินเผา ทุกรายการถูกเลือกไว้ เวลา 15:20
- When สมชายเลิกเลือกกางเกงขาสั้น
- Then ยอดรวมของร้านบ้านผ้าเป็น 500 บาท ของร้านดินเผา 120 บาท (ทั้งสองร้านเหลือร้านละรายการ จึงเห็นยอดนี้เป็นราคารวมของรายการ) แถบสรุปยอดแสดง "ค่าสินค้า 3 ชิ้น" 620 บาท "ค่าส่ง 2 ร้าน" 80 บาท และ "ยอดรวมที่ต้องจ่าย" 700 บาท และเมื่อสมชายเปิดตะกร้าอีกครั้งเวลา 19:00 กางเกงขาสั้นยังไม่ถูกเลือก

กรณีผิดพลาด

- Given สมชายมี 3 รายการเดิม และมีหมอนอิง 1 ชิ้น 180 บาทที่ซื้อไม่ได้เพราะสินค้าหมด เวลา 15:30
- When สมชายกด "เลือกทั้งหมด" หรือเลิกเลือกทุกรายการ
- Then กรณีกด "เลือกทั้งหมด" มี 3 รายการที่ซื้อได้ถูกเลือก หมอนอิงไม่ถูกเลือกและไม่ถูกนับในยอดรวม 920 บาท กรณีเลิกเลือกทุกรายการ ยอดรวมทั้งหมดเป็น 0 บาท และปุ่ม "สั่งซื้อ" กดไม่ได้

### CRT-013 แจ้งเมื่อราคาเปลี่ยน

- ลำดับความสำคัญ: ต้องมี
- WHILE ราคาปัจจุบันของรายการในตะกร้าต่างจากราคาที่ผู้ซื้อเห็นล่าสุดตอนใส่ตะกร้าหรือตอนไปหน้าสั่งซื้อสำเร็จ THE SYSTEM SHALL แสดงราคาปัจจุบัน ใช้ราคาปัจจุบันคิดยอดรวม และแสดงข้อความแจ้งที่รายการนั้นว่าราคาเปลี่ยนจากเท่าไรเป็นเท่าไร

กรณีปกติ

- Given สมหญิงเพิ่มเสื้อยืดคอกลม 1 ชิ้นลงตะกร้าเมื่อ 09:30 ตอนราคา 250 บาท ร้านบ้านผ้าแก้ราคาเป็น 300 บาทเวลา 10:00
- When สมหญิงเปิดหน้าตะกร้าเวลา 10:15
- Then รายการแสดงราคา 300 บาท พร้อมข้อความ "ราคาเปลี่ยนจาก ฿250 เป็น ฿300" ยอดรวมคิดจาก 300 บาท ข้อความนี้หายไปหลังสมหญิงไปหน้าสั่งซื้อสำเร็จพร้อมรายการนี้

กรณีผิดพลาด

- Given สมหญิงมีเสื้อยืดคอกลมในตะกร้าที่เห็นราคาล่าสุด 250 บาท ร้านแก้ราคาเป็น 300 บาทเวลา 10:00 แล้วแก้กลับเป็น 250 บาทเวลา 10:10
- When สมหญิงเปิดหน้าตะกร้าเวลา 10:15
- Then รายการแสดงราคา 250 บาท ไม่มีข้อความแจ้งราคาเปลี่ยน เพราะราคาปัจจุบันเท่ากับราคาที่เธอเห็นล่าสุด

### CRT-014 รายการที่ซื้อไม่ได้

- ลำดับความสำคัญ: ต้องมี
- WHILE รายการในตะกร้าเป็นแบบย่อยที่สต็อกเป็น 0 แบบย่อยที่ถูกเอาออกจากสินค้า สินค้าที่เป็น `ซ่อน` หรือ `ลบแล้ว` หรือสินค้าของร้านที่ `ถูกระงับ` THE SYSTEM SHALL แสดงรายการนั้นเป็นสีจางพร้อมเหตุผล เลิกเลือกรายการนั้น ไม่นับในยอดรวม ไม่ให้เลือกหรือเปลี่ยนจำนวน และให้ลบได้อย่างเดียว

กรณีปกติ

- Given ปิติมี 4 รายการในตะกร้า เวลา 17:00 รองเท้าผ้าใบ ขนาด 42 สต็อกเป็น 0 ร้านสวนหลังบ้านซ่อนหมอนอิง ร้านดินเผาลบแก้วเซรามิก และผู้ดูแลแพลตฟอร์มระงับร้านของเล่นไม้ที่ปิติมีรถไม้ 1 คัน
- When ปิติเปิดหน้าตะกร้าเวลา 17:10
- Then ทั้ง 4 รายการเป็นสีจาง มีข้อความ "สินค้าหมด" "สินค้านี้ไม่เปิดขายแล้ว" "สินค้านี้ไม่เปิดขายแล้ว" และ "ร้านนี้ไม่เปิดขายตอนนี้" ตามลำดับ รายการที่ถูกลบยังแสดงชื่อและรูปล่าสุด ยอดรวมทั้งหมดเป็น 0 บาท และเมื่อร้านเติมรองเท้าเป็น 5 ชิ้นเวลา 18:00 รายการรองเท้ากลับมาเลือกได้แต่ยังไม่ถูกเลือก

กรณีผิดพลาด

- Given ปิติมีรองเท้าผ้าใบ ขนาด 42 จำนวน 3 ชิ้นในตะกร้า ถูกเลือกไว้ เวลา 17:30 สต็อกลดจาก 3 เหลือ 2 ชิ้นเพราะมีคนอื่นสั่งซื้อไป
- When ปิติเปิดหน้าตะกร้าเวลา 17:35
- Then จำนวนของรายการถูกปรับเป็น 2 ชิ้น พร้อมข้อความ "ปรับจำนวนเหลือ 2 ชิ้น เพราะสินค้าเหลือ 2 ชิ้น" รายการยังเลือกอยู่และยอดรวมคิดจาก 2 ชิ้น

### CRT-015 ไปหน้าสั่งซื้อ

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อกด "สั่งซื้อ" ในหน้าตะกร้าโดยมีรายการที่เลือกไว้อย่างน้อยหนึ่งรายการ THE SYSTEM SHALL ตรวจราคา สต็อก และสถานะของรายการที่เลือกอีกครั้ง แล้วพาไปหน้าสั่งซื้อ (ดู CHK-004) พร้อมรายการที่เลือกเฉพาะเมื่อทุกอย่างตรงกับที่แสดงบนหน้าจอ โดยรายการทั้งหมดยังอยู่ในตะกร้า

กรณีปกติ

- Given สมชายเลือกเสื้อยืดคอกลม 2 ชิ้น ชิ้นละ 250 บาทจากร้านบ้านผ้า และแก้วเซรามิก 1 ใบ 120 บาทจากร้านดินเผา ไม่เลือกกางเกงขาสั้น ยอดรวมทั้งหมด 620 บาท เวลา 15:40 ราคาและสต็อกไม่เปลี่ยนตั้งแต่เปิดหน้า
- When สมชายกด "สั่งซื้อ"
- Then สมชายไปถึงหน้าสั่งซื้อที่มี 2 รายการจาก 2 ร้าน และเมื่อเขากดย้อนกลับเวลา 15:42 โดยยังไม่สั่งซื้อ ตะกร้ายังมี 3 รายการ จำนวนและการเลือกเหมือนเดิม

กรณีผิดพลาด

- Given สมชายเปิดหน้าตะกร้าค้างไว้ตั้งแต่ 15:40 เห็นเสื้อยืดคอกลม 2 ชิ้น ชิ้นละ 250 บาท และแก้วเซรามิก 1 ใบ เวลา 15:50 ร้านบ้านผ้าแก้ราคาเสื้อเป็น 300 บาท และแก้วเซรามิกใบสุดท้ายถูกคนอื่นสั่งซื้อไป
- When สมชายกด "สั่งซื้อ" เวลา 15:55
- Then สมชายยังอยู่ที่หน้าตะกร้า เห็นข้อความ "มีรายการเปลี่ยนแปลง กรุณาตรวจอีกครั้ง" เสื้อแสดงราคา 300 บาทพร้อมข้อความแจ้งราคาเปลี่ยน แก้วเซรามิกเป็นรายการที่ซื้อไม่ได้และถูกเลิกเลือก ยอดรวมทั้งหมดเป็น 600 บาท เขาต้องกด "สั่งซื้อ" อีกครั้งจึงจะไปต่อได้

### CRT-Q01 ความเร็วแสดงหน้าตะกร้า

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อเปิดหน้าตะกร้าที่มี 50 รายการจาก 10 ร้าน THE SYSTEM SHALL แสดงรายการและยอดรวมครบภายใน 2 วินาที ใน 95 จาก 100 ครั้ง ขณะมีผู้ใช้พร้อมกัน 20 คน

กรณีปกติ

- Given บัญชีทดสอบของสมชายมี 50 รายการจาก 10 ร้าน ข้อมูลตัวอย่างมี 50 ร้าน 1,000 สินค้า เวลา 13:00 มีคำขอจำลองผู้ใช้ 20 คนพร้อมกัน
- When เปิดหน้าตะกร้า 100 ครั้ง
- Then อย่างน้อย 95 ครั้งแสดงรายการและยอดรวมครบภายใน 2 วินาที

กรณีผิดพลาด

- Given การวัดชุดเดียวกัน เวลา 13:10
- When มี 6 ครั้งจาก 100 ครั้งที่ใช้เวลาเกิน 2 วินาที
- Then ถือว่าไม่ผ่าน ครั้งที่ช้ายังต้องแสดงโครงหน้าสีเทาตาม CRT-008 ไม่ใช่หน้าขาว

### CRT-Q02 ความเร็วอัปเดตยอดรวม

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อเปลี่ยนจำนวน ลบ เลือก หรือเลิกเลือกรายการในตะกร้าที่มี 50 รายการ THE SYSTEM SHALL แสดงยอดรวมใหม่ภายใน 1 วินาที ใน 95 จาก 100 ครั้ง

กรณีปกติ

- Given บัญชีทดสอบของสมหญิงมี 50 รายการจาก 10 ร้าน เวลา 13:20
- When กดปุ่มบวกที่รายการต่าง ๆ รวม 100 ครั้ง และจับเวลาตั้งแต่กดจนยอดรวมเปลี่ยน
- Then อย่างน้อย 95 ครั้งยอดรวมเปลี่ยนภายใน 1 วินาที และยอดรวมตรงกับผลคูณราคาปัจจุบันกับจำนวนของรายการที่เลือกทุกครั้ง

กรณีผิดพลาด

- Given การวัดชุดเดียวกัน เวลา 13:30
- When มีครั้งที่ยอดรวมยังไม่เปลี่ยนหลัง 1 วินาที
- Then ระหว่างรอ ยอดรวมแสดงสัญลักษณ์กำลังคิด ไม่แสดงยอดเก่าเหมือนเป็นยอดล่าสุด และปุ่ม "สั่งซื้อ" กดไม่ได้จนยอดใหม่แสดง

### CRT-Q03 ใช้บนจอมือถือได้

- ลำดับความสำคัญ: ต้องมี
- THE SYSTEM SHALL แสดงหน้าตะกร้าบนจอกว้าง 360 จุดโดยไม่ต้องเลื่อนซ้ายขวา และปุ่มทุกปุ่มมีขนาดอย่างน้อย 44 คูณ 44 จุด

กรณีปกติ

- Given มานีมี 3 รายการจาก 2 ร้านในตะกร้า เวลา 12:00 เธอเปิดหน้าตะกร้าบนจอกว้าง 360 จุด
- When ผู้ตรวจวัดขนาดปุ่มบวก ปุ่มลบ ช่องเลือก ปุ่ม "ลบ" และปุ่ม "สั่งซื้อ" และลองเลื่อนหน้า
- Then หน้าเลื่อนได้เฉพาะขึ้นลง ปุ่มทั้ง 5 แบบมีขนาดอย่างน้อย 44 คูณ 44 จุด ยอดรวมทั้งหมดและปุ่ม "สั่งซื้อ" เห็นได้ตลอดโดยไม่ต้องเลื่อนไปล่างสุด

กรณีผิดพลาด

- Given มานีมีรายการหนึ่งที่ชื่อสินค้ายาว 120 ตัวอักษร เวลา 12:10 บนจอกว้าง 360 จุด
- When มานีเปิดหน้าตะกร้า ทั้งตอนมีรายการ ตอนว่าง และตอนแสดงข้อความผิดพลาด
- Then ชื่อสินค้าถูกตัดเหลือไม่เกิน 2 บรรทัด ทั้งสามสภาพของหน้ายังไม่ต้องเลื่อนซ้ายขวา

## 5. ข้อมูลและสถานะ

รายการในตะกร้า คือแบบย่อยหนึ่งแบบพร้อมจำนวน ในตะกร้าของบัญชีหนึ่ง สินค้าเดียวกันแต่คนละแบบย่อยนับเป็นคนละรายการ

| ข้อมูล | ใช้ทำอะไร | เก็บนานแค่ไหน |
|---|---|---|
| บัญชีเจ้าของตะกร้า | บอกว่าตะกร้าเป็นของใคร หนึ่งบัญชีมีหนึ่งตะกร้า | ตลอด ระบบไม่ลบเอง |
| สินค้า แบบย่อย และร้านของรายการ | แสดงรายการและจัดกลุ่มตามร้าน | จนผู้ซื้อลบรายการ หรือรายการถูกสั่งซื้อ (ดู CHK-005) |
| จำนวน | คิดราคารวมของรายการ | เท่ากับรายการ |
| เลือกไว้หรือไม่ | บอกว่ารายการไหนจะไปหน้าสั่งซื้อและถูกนับในยอดรวม | เท่ากับรายการ |
| ราคาที่ผู้ซื้อเห็นล่าสุด | เทียบกับราคาปัจจุบันเพื่อแจ้งราคาเปลี่ยน | เท่ากับรายการ |
| ชื่อและรูปล่าสุดของสินค้า | แสดงรายการที่สินค้าถูกลบไปแล้ว | เท่ากับรายการ |
| เวลาที่เพิ่มรายการ | เรียงร้านและรายการจากใหม่ไปเก่า | เท่ากับรายการ |

| จากสถานะ | เหตุการณ์ | ไปสถานะ |
|---|---|---|
| ไม่มีในตะกร้า | ผู้ซื้อเพิ่มสินค้า | ซื้อได้ และเลือกไว้ |
| ซื้อได้ และเลือกไว้ | ผู้ซื้อเลิกเลือก | ซื้อได้ และไม่เลือก |
| ซื้อได้ และไม่เลือก | ผู้ซื้อเลือก | ซื้อได้ และเลือกไว้ |
| ซื้อได้ (เลือกหรือไม่เลือก) | เข้าเงื่อนไขของ CRT-014 | ซื้อไม่ได้ |
| ซื้อไม่ได้ | แบบย่อยกลับมามีสต็อก สินค้ากลับเป็น `ขายอยู่` หรือร้านกลับเป็น `เปิดอยู่` | ซื้อได้ และไม่เลือก |
| ซื้อได้ หรือซื้อไม่ได้ | ผู้ซื้อยืนยันการลบ | ไม่มีในตะกร้า |
| ซื้อได้ และเลือกไว้ | คำสั่งซื้อที่มีรายการนี้ถูกสร้างสำเร็จ (ดู CHK-005) | ไม่มีในตะกร้า |
