## 1. เป้าหมายและตัวเลขความสำเร็จ

- เป้าหมาย: ผู้ซื้อมองแผนที่แล้วรู้ว่าพัสดุออกจากจังหวัดไหน ผ่านจังหวัดไหนมาแล้ว และจะไปจังหวัดไหน โดยไม่ต้องอ่านประวัติการจัดส่งทีละบรรทัด
- วัดความสำเร็จจาก: คน 5 คนที่ไม่เคยใช้ระบบ เปิดหน้าติดตามพัสดุของพัสดุที่ผ่านมาแล้ว 3 จังหวัด แล้วตอบได้ว่าพัสดุอยู่จังหวัดไหนล่าสุด ภายใน 10 วินาที อย่างน้อย 4 จาก 5 คน

## 2. ขอบเขต

### ทำ

- ผู้ขายและผู้ดูแลแพลตฟอร์มเลือกจังหวัดทุกครั้งที่เปลี่ยนสถานะการจัดส่ง เพิ่มจากช่องสถานที่ที่มีอยู่
- แผนที่การจัดส่งบนหน้าติดตามพัสดุ แสดงจังหวัดต้นทาง จังหวัดที่พัสดุผ่านมาแล้ว และจังหวัดปลายทาง
- ข้อความเส้นทางใต้แผนที่ ที่อ่านได้แม้แผนที่ไม่ขึ้น
- ข้อมูลตัวอย่างที่ประวัติการจัดส่งมีจังหวัดครบ

### ไม่ทำ

- ไม่แสดงตำแหน่งปัจจุบันของพัสดุหรือของรถส่งของ เพราะระบบไม่มีบทบาทคนส่งของและไม่ต่อกับผู้ให้บริการจัดส่งจริง
- ไม่บอกเวลาที่คาดว่าของจะถึง เพราะไม่มีข้อมูลจริงให้คำนวณ
- ไม่ปักหมุดละเอียดกว่าระดับจังหวัด เพราะบ้านเลขที่ของผู้ซื้อไม่ควรอยู่บนแผนที่ และผู้ขายไม่ต้องปักหมุดเอง
- ไม่แปลงข้อความสถานที่ที่พิมพ์เองเป็นตำแหน่งบนแผนที่ เพราะข้อความที่คนพิมพ์เองแปลงผิดได้ง่าย
- ไม่เติมจังหวัดย้อนหลังให้ประวัติการจัดส่งที่บันทึกไปแล้ว เพราะประวัติการจัดส่งแก้ไม่ได้ตาม `delivery.md`
- ไม่มีแผนที่บนหน้าอื่น เช่น รายการคำสั่งซื้อ หรือหน้าร้าน

### ข้อจำกัด

- จังหวัดใช้รายชื่อเดียวกับที่อยู่จัดส่งและที่อยู่ต้นทาง
- สถานะการจัดส่ง ลำดับขั้น และกฎการเปลี่ยนสถานะ เป็นไปตาม `delivery.md` ไฟล์นี้เพิ่มเพียงช่องจังหวัด
- ภาพแผนที่มาจาก OpenStreetMap ต้องแสดงเครดิตของ OpenStreetMap บนแผนที่ตามเงื่อนไขการใช้งาน
- เบราว์เซอร์ของผู้ใช้ขอภาพแผนที่จาก OpenStreetMap โดยตรง ระบบไม่ส่งเลขติดตามพัสดุ ชื่อ หรือที่อยู่ ให้ OpenStreetMap

## 3. ผู้ใช้และสิทธิ์

| บทบาท | ทำได้ | ทำไม่ได้ |
|---|---|---|
| ผู้ซื้อ | ดูแผนที่การจัดส่งของพัสดุในคำสั่งซื้อตัวเอง | เลือกหรือแก้จังหวัด ดูแผนที่ของพัสดุคนอื่น |
| ผู้ขาย | ดูแผนที่การจัดส่งของพัสดุในร้านตัวเอง เลือกจังหวัดตอนเปลี่ยนสถานะการจัดส่ง | ดูหรือเปลี่ยนพัสดุของร้านอื่น แก้จังหวัดที่บันทึกแล้ว |
| ผู้ดูแลแพลตฟอร์ม | ดูแผนที่การจัดส่งของพัสดุทุกร้าน เลือกจังหวัดตอนเปลี่ยนสถานะการจัดส่ง | แก้จังหวัดที่บันทึกแล้ว |
| คนที่ยังไม่เข้าสู่ระบบ | ไม่มี | ดูแผนที่การจัดส่ง |

## 4. Requirements

ตัวอย่างในส่วนนี้ใช้คนชุดเดียวกับ `delivery.md`: สมชายเป็นผู้ขาย เจ้าของร้าน "สมชายการช่าง" ที่อยู่ต้นทางอยู่จังหวัดเชียงใหม่ สมหญิงเป็นผู้ซื้อ ที่อยู่จัดส่งอยู่จังหวัดกรุงเทพมหานคร วิชัยเป็นผู้ดูแลแพลตฟอร์ม มานะเป็นผู้ขาย เจ้าของร้าน "มานะสปอร์ต"

### MAP-001 เลือกจังหวัดตอนเปลี่ยนสถานะการจัดส่ง

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายหรือผู้ดูแลแพลตฟอร์มบันทึกการเปลี่ยนสถานะการจัดส่งพร้อมจังหวัดที่เลือกจากรายชื่อจังหวัด THE SYSTEM SHALL บันทึกจังหวัดนั้นไว้กับรายการใหม่ในประวัติการจัดส่ง คู่กับสถานที่ที่กรอก

กรณีปกติ

- Given พัสดุ `BS0000000123` ของร้านสมชายการช่าง เป็น `ร้านส่งของแล้ว` วันที่ 2026-11-25
- When สมชายกด "เปลี่ยนเป็น อยู่ระหว่างขนส่ง" กรอกสถานที่ "ศูนย์คัดแยกลำปาง" เลือกจังหวัด "ลำปาง" แล้วกดบันทึก เวลา 13:20
- Then พัสดุเป็น `อยู่ระหว่างขนส่ง` ประวัติการจัดส่งมีรายการใหม่ เวลา 25 พ.ย. 13:20 สถานที่ "ศูนย์คัดแยกลำปาง" จังหวัด "ลำปาง"

กรณีผิดพลาด

- Given พัสดุ `BS0000000123` เป็น `ร้านส่งของแล้ว` และประวัติการจัดส่งมี 2 รายการ
- When สมชายกรอกสถานที่ "ศูนย์คัดแยกลำปาง" แต่ไม่เลือกจังหวัด หรือส่งชื่อจังหวัดที่ไม่มีในรายชื่อ แล้วกดบันทึก เวลา 13:20
- Then สมชายเห็นข้อความใต้ช่องว่า "เลือกจังหวัด" สถานที่ที่กรอกไว้ยังอยู่ในช่อง พัสดุยังเป็น `ร้านส่งของแล้ว` และประวัติยังมี 2 รายการ

### MAP-002 จังหวัดที่เลือกไว้ให้ก่อน

- ลำดับความสำคัญ: ควรมี
- WHEN ผู้ขายหรือผู้ดูแลแพลตฟอร์มเปิดฟอร์มเปลี่ยนสถานะการจัดส่ง THE SYSTEM SHALL เลือกจังหวัดของรายการล่าสุดในประวัติการจัดส่งที่มีจังหวัดไว้ให้ก่อน และถ้าไม่มีรายการไหนมีจังหวัด ให้เลือกจังหวัดของที่อยู่ต้นทางของพัสดุ

กรณีปกติ

- Given พัสดุ `BS0000000123` มีรายการล่าสุดในประวัติการจัดส่งที่จังหวัด "ลำปาง"
- When สมชายเปิดฟอร์ม "เปลี่ยนเป็น กำลังนำส่ง" วันที่ 2026-11-26 เวลา 09:00
- Then ช่องจังหวัดเลือก "ลำปาง" ไว้แล้ว และสมชายเปลี่ยนเป็น "กรุงเทพมหานคร" ได้

กรณีผิดพลาด

- Given พัสดุ `BS0000000777` ถูกสร้างก่อนมีช่องจังหวัด ประวัติการจัดส่ง 2 รายการไม่มีจังหวัดเลย และที่อยู่ต้นทางของพัสดุอยู่จังหวัดเชียงใหม่
- When สมชายเปิดฟอร์ม "เปลี่ยนเป็น อยู่ระหว่างขนส่ง" วันที่ 2026-11-25 เวลา 10:00
- Then ช่องจังหวัดเลือก "เชียงใหม่" ไว้แล้ว

### MAP-003 จังหวัดของรายการแรกในประวัติการจัดส่ง

- ลำดับความสำคัญ: ต้องมี
- WHEN ระบบสร้างพัสดุและบันทึกรายการแรกในประวัติการจัดส่งตาม DLV-001 THE SYSTEM SHALL บันทึกจังหวัดของที่อยู่ต้นทางของร้าน ณ เวลานั้น ไว้กับรายการแรก

กรณีปกติ

- Given คำสั่งซื้อของสมหญิงจากร้านสมชายการช่าง เปลี่ยนเป็น `จ่ายแล้ว` วันที่ 2026-11-25 เวลา 09:00
- When ระบบสร้างพัสดุ `BS0000000123`
- Then รายการแรกในประวัติการจัดส่งมีสถานที่ "สมชายการช่าง" จังหวัด "เชียงใหม่"

กรณีผิดพลาด

- Given พัสดุ `BS0000000123` ถูกสร้างแล้วตอนที่อยู่ต้นทางของร้านอยู่จังหวัดเชียงใหม่
- When สมชายแก้ที่อยู่ต้นทางของร้านเป็นจังหวัดลำพูน วันที่ 2026-11-25 เวลา 11:00
- Then รายการแรกในประวัติการจัดส่งของ `BS0000000123` ยังเป็นจังหวัด "เชียงใหม่"

### MAP-004 แผนที่การจัดส่งบนหน้าติดตามพัสดุ

- ลำดับความสำคัญ: ต้องมี
- WHEN บัญชีที่มีสิทธิ์ดูหน้าติดตามพัสดุเปิดหน้านั้น THE SYSTEM SHALL แสดงแผนที่การจัดส่งที่มีหมุดของจังหวัดต้นทาง จังหวัดของทุกรายการในประวัติการจัดส่งที่มีจังหวัด และจังหวัดของที่อยู่จัดส่ง โดยลากเส้นทึบตามลำดับเวลาระหว่างจังหวัดที่พัสดุผ่านมาแล้ว ลากเส้นประจากจังหวัดล่าสุดไปจังหวัดของที่อยู่จัดส่ง เน้นหมุดของจังหวัดล่าสุด และแสดงข้อความ "แผนที่แสดงจังหวัดที่พัสดุผ่านมาแล้ว ไม่ใช่ตำแหน่งปัจจุบัน"

กรณีปกติ

- Given พัสดุ `BS0000000123` เป็น `อยู่ระหว่างขนส่ง` ประวัติการจัดส่งมีจังหวัด เชียงใหม่ เชียงใหม่ และลำปาง ตามลำดับเวลา ที่อยู่จัดส่งอยู่กรุงเทพมหานคร
- When สมหญิงเปิดหน้าติดตามพัสดุวันที่ 2026-11-25 เวลา 14:00
- Then สมหญิงเห็นแผนที่ที่มีหมุด 3 จังหวัด คือเชียงใหม่ ลำปาง และกรุงเทพมหานคร เส้นทึบจากเชียงใหม่ถึงลำปาง เส้นประจากลำปางถึงกรุงเทพมหานคร หมุดลำปางถูกเน้น และเห็นข้อความ "แผนที่แสดงจังหวัดที่พัสดุผ่านมาแล้ว ไม่ใช่ตำแหน่งปัจจุบัน"

กรณีผิดพลาด

- Given มานะเป็นผู้ขายของร้านอื่น และเข้าสู่ระบบอยู่
- When มานะเปิดหน้าติดตามพัสดุของ `BS0000000123` วันที่ 2026-11-25 เวลา 14:05
- Then มานะเห็นหน้า "ไม่พบ" ตาม `delivery.md` และไม่เห็นแผนที่หรือชื่อจังหวัดใดของพัสดุนี้

### MAP-005 แผนที่กำลังโหลดและแผนที่ที่แสดงไม่ได้

- ลำดับความสำคัญ: ต้องมี
- IF ภาพแผนที่โหลดไม่สำเร็จ หรือโหลดไม่เสร็จภายใน 10 วินาที THEN THE SYSTEM SHALL แสดงข้อความ "แสดงแผนที่ไม่ได้ ลองใหม่อีกครั้ง" พร้อมปุ่ม "ลองใหม่" ในที่ของแผนที่ โดยสถานะการจัดส่ง ประวัติการจัดส่ง ข้อความเส้นทาง และปุ่ม "ได้รับสินค้าแล้ว" ยังแสดงและใช้ได้ครบ

กรณีปกติ

- Given สมหญิงเปิดหน้าติดตามพัสดุของ `BS0000000123` วันที่ 2026-11-25 เวลา 14:00
- When ภาพแผนที่ยังโหลดไม่เสร็จ
- Then สมหญิงเห็นกรอบสีพื้นขนาดเท่าแผนที่ในที่ของแผนที่ และเห็นสถานะการจัดส่ง ประวัติการจัดส่ง กับข้อความเส้นทางแล้ว

กรณีผิดพลาด

- Given OpenStreetMap ไม่ตอบ
- When สมหญิงเปิดหน้าติดตามพัสดุของ `BS0000000123` วันที่ 2026-11-25 เวลา 14:00 และรอ 10 วินาที
- Then สมหญิงเห็น "แสดงแผนที่ไม่ได้ ลองใหม่อีกครั้ง" กับปุ่ม "ลองใหม่" ในที่ของแผนที่ ประวัติการจัดส่งและข้อความเส้นทางยังอยู่ครบ และเมื่อกด "ลองใหม่" ระบบขอภาพแผนที่อีกครั้งโดยไม่โหลดหน้าใหม่

### MAP-006 ข้อความเส้นทาง

- ลำดับความสำคัญ: ต้องมี
- WHEN บัญชีที่มีสิทธิ์ดูหน้าติดตามพัสดุเปิดหน้านั้น THE SYSTEM SHALL แสดงข้อความเส้นทางเป็นชื่อจังหวัดเรียงตามลำดับเวลา โดยไม่ซ้ำจังหวัดที่ติดกัน บอกว่าจังหวัดไหนคือล่าสุด และจังหวัดไหนคือปลายทาง ให้อ่านได้โดยไม่ต้องใช้แผนที่

กรณีปกติ

- Given พัสดุ `BS0000000123` มีประวัติการจัดส่งที่จังหวัด เชียงใหม่ เชียงใหม่ และลำปาง ที่อยู่จัดส่งอยู่กรุงเทพมหานคร
- When สมหญิงเปิดหน้าติดตามพัสดุวันที่ 2026-11-25 เวลา 14:00
- Then สมหญิงเห็นข้อความเส้นทาง "เชียงใหม่ → ลำปาง (ล่าสุด) → กรุงเทพมหานคร (ปลายทาง)"

กรณีผิดพลาด

- Given สมหญิงปิดการใช้งาน JavaScript ในเบราว์เซอร์
- When สมหญิงเปิดหน้าติดตามพัสดุของ `BS0000000123` วันที่ 2026-11-25 เวลา 14:00

### MAP-007 ประวัติการจัดส่งที่ไม่มีจังหวัด

- ลำดับความสำคัญ: ต้องมี
- IF รายการในประวัติการจัดส่งไม่มีจังหวัด THEN THE SYSTEM SHALL ข้ามรายการนั้นบนแผนที่และในข้อความเส้นทาง โดยยังแสดงรายการนั้นในประวัติการจัดส่งตามเดิม

กรณีปกติ

- Given พัสดุ `BS0000000777` มีประวัติการจัดส่ง 3 รายการ สองรายการแรกไม่มีจังหวัด รายการที่สามมีจังหวัด "ลำปาง" ที่อยู่ต้นทางอยู่เชียงใหม่ ที่อยู่จัดส่งอยู่กรุงเทพมหานคร
- When สมหญิงเปิดหน้าติดตามพัสดุวันที่ 2026-11-25 เวลา 15:00
- Then แผนที่มีหมุดเชียงใหม่ ลำปาง และกรุงเทพมหานคร ข้อความเส้นทางคือ "เชียงใหม่ → ลำปาง (ล่าสุด) → กรุงเทพมหานคร (ปลายทาง)" และประวัติการจัดส่งยังมี 3 รายการ

กรณีผิดพลาด

- Given พัสดุ `BS0000000888` มีประวัติการจัดส่ง 2 รายการที่ไม่มีจังหวัดเลย ที่อยู่ต้นทางอยู่เชียงใหม่ ที่อยู่จัดส่งอยู่กรุงเทพมหานคร
- When สมหญิงเปิดหน้าติดตามพัสดุวันที่ 2026-11-25 เวลา 15:00
- Then แผนที่มีหมุดเชียงใหม่และกรุงเทพมหานคร หมุดเชียงใหม่ถูกเน้น และข้อความเส้นทางคือ "เชียงใหม่ (ล่าสุด) → กรุงเทพมหานคร (ปลายทาง)"

### MAP-008 ต้นทางและปลายทางอยู่จังหวัดเดียวกัน

- ลำดับความสำคัญ: ต้องมี
- IF ทุกจุดของพัสดุอยู่จังหวัดเดียวกัน THEN THE SYSTEM SHALL แสดงหมุดเดียวของจังหวัดนั้นโดยไม่มีเส้น และข้อความเส้นทางบอกว่าเป็นการจัดส่งภายในจังหวัดนั้น

กรณีปกติ

- Given พัสดุ `BS0000000456` มีที่อยู่ต้นทาง ประวัติการจัดส่งทุกรายการ และที่อยู่จัดส่ง อยู่กรุงเทพมหานครทั้งหมด
- When สมหญิงเปิดหน้าติดตามพัสดุวันที่ 2026-11-25 เวลา 16:00
- Then แผนที่มีหมุดเดียวที่กรุงเทพมหานคร ไม่มีเส้น และข้อความเส้นทางคือ "จัดส่งภายในกรุงเทพมหานคร"

กรณีผิดพลาด

- Given พัสดุ `BS0000000456` ออกจากกรุงเทพมหานคร ไปผ่านนนทบุรี แล้วกลับมากรุงเทพมหานคร ที่อยู่จัดส่งอยู่กรุงเทพมหานคร
- When สมหญิงเปิดหน้าติดตามพัสดุวันที่ 2026-11-25 เวลา 16:00
- Then แผนที่มีหมุด 2 จังหวัด เส้นทึบไปและกลับระหว่างสองจังหวัด และข้อความเส้นทางคือ "กรุงเทพมหานคร → นนทบุรี → กรุงเทพมหานคร (ล่าสุด และปลายทาง)"

### MAP-009 แผนที่เมื่อการจัดส่งจบแล้ว

- ลำดับความสำคัญ: ต้องมี
- WHILE พัสดุเป็น `ส่งสำเร็จ` หรือ `ส่งไม่สำเร็จ` THE SYSTEM SHALL แสดงแผนที่การจัดส่งโดยไม่มีเส้นประ

กรณีปกติ

- Given พัสดุ `BS0000000123` เป็น `ส่งสำเร็จ` รายการล่าสุดอยู่กรุงเทพมหานคร
- When สมหญิงเปิดหน้าติดตามพัสดุวันที่ 2026-11-26 เวลา 16:00
- Then แผนที่มีเส้นทึบจากเชียงใหม่ผ่านลำปางถึงกรุงเทพมหานคร ไม่มีเส้นประ และข้อความเส้นทางคือ "เชียงใหม่ → ลำปาง → กรุงเทพมหานคร (ล่าสุด และปลายทาง)"

กรณีผิดพลาด

- Given พัสดุ `BS0000000999` เป็น `ส่งไม่สำเร็จ` รายการล่าสุดอยู่ลำปาง ที่อยู่จัดส่งอยู่กรุงเทพมหานคร
- When สมหญิงเปิดหน้าติดตามพัสดุวันที่ 2026-11-26 เวลา 16:00
- Then แผนที่มีเส้นทึบจากเชียงใหม่ถึงลำปาง มีหมุดกรุงเทพมหานครแต่ไม่มีเส้นประไปถึง และข้อความเส้นทางคือ "เชียงใหม่ → ลำปาง (ล่าสุด) · ปลายทาง กรุงเทพมหานคร"

### MAP-010 ข้อมูลตัวอย่าง

- ลำดับความสำคัญ: ควรมี
- THE SYSTEM SHALL มีพัสดุในข้อมูลตัวอย่างอย่างน้อย 2 ชิ้นที่ประวัติการจัดส่งผ่านอย่างน้อย 3 จังหวัด

กรณีปกติ

- Given ผู้ทดลองสร้างข้อมูลตัวอย่างใหม่วันที่ 2026-11-25
- When ผู้ทดลองเข้าสู่ระบบด้วยบัญชีผู้ซื้อตัวอย่าง แล้วเปิดหน้าติดตามพัสดุของคำสั่งซื้อที่เป็น `กำลังจัดส่ง`
- Then เห็นแผนที่ที่มีหมุดอย่างน้อย 3 จังหวัดและเส้นระหว่างหมุด

กรณีผิดพลาด

- Given ข้อมูลตัวอย่างถูกสร้างแล้ว
- When ผู้ทดลองสร้างข้อมูลตัวอย่างซ้ำอีกครั้งโดยไม่ล้างฐานข้อมูล
- Then ประวัติการจัดส่งของพัสดุตัวอย่างไม่มีรายการเพิ่มหรือซ้ำ
