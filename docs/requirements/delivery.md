## 1. เป้าหมายและตัวเลขความสำเร็จ

- เป้าหมาย: ผู้ซื้อเห็นได้ตลอดว่าพัสดุของตัวเองอยู่ขั้นไหน อยู่ที่ไหน และใครเป็นคนรับ โดยผู้ขายและผู้ดูแลแพลตฟอร์มเป็นคนเปลี่ยนสถานะการจัดส่งทีละขั้นจนถึง `ส่งสำเร็จ`
- วัดความสำเร็จจาก: คนหนึ่งคนใช้สองบัญชี เปลี่ยนสถานะพัสดุหนึ่งชิ้นจาก `รอร้านจัดของ` ถึง `ส่งสำเร็จ` แล้วกด "ได้รับสินค้าแล้ว" จบได้ภายใน 3 นาที โดยไม่มีใครช่วย และการเปลี่ยนสถานะทั้ง 4 ครั้งขึ้นบนหน้าติดตามพัสดุครบ 4 จาก 4 ครั้ง

## 2. ขอบเขต

### ทำ

- สร้างพัสดุและเลขติดตามพัสดุ เมื่อคำสั่งซื้อเป็น `จ่ายแล้ว`
- ผู้ขายและผู้ดูแลแพลตฟอร์มเปลี่ยนสถานะการจัดส่งทีละขั้น พร้อมกรอกสถานที่
- กรอกชื่อผู้รับตอน `ส่งสำเร็จ` และกรอกเหตุผลตอน `ส่งไม่สำเร็จ`
- หน้าติดตามพัสดุ และการค้นหาพัสดุด้วยเลขติดตามพัสดุ
- ผู้ซื้อกด "ได้รับสินค้าแล้ว" และการปิดคำสั่งซื้ออัตโนมัติเมื่อครบ 7 วัน
- การเปลี่ยนสถานะคำสั่งซื้อที่เกิดจากการจัดส่ง: เป็น `กำลังจัดส่ง` เป็น `สำเร็จ` และเป็น `ยกเลิก` เมื่อ `ส่งไม่สำเร็จ`

### ไม่ทำ

- ไม่ต่อกับผู้ให้บริการจัดส่งจริง เพราะ product.md กำหนดว่ารุ่นนี้ไม่ต่อระบบภายนอก
- ไม่มีบทบาทคนส่งของ เพราะผู้ขายและผู้ดูแลแพลตฟอร์มเปลี่ยนสถานะการจัดส่งแทน
- ไม่มีแผนที่และตำแหน่งปัจจุบันของพัสดุ เพราะสถานที่เป็นข้อความที่คนกรอกเอง
- ไม่บอกเวลาที่คาดว่าของจะถึง เพราะไม่มีข้อมูลจริงให้คำนวณ
- ไม่ทำการคืนสินค้า การคืนเงิน และการจัดส่งใหม่หลัง `ส่งไม่สำเร็จ` เพราะอยู่ใน RFD
- ไม่ส่งแจ้งเตือนเมื่อสถานะการจัดส่งเปลี่ยน เพราะอยู่ใน NTF ผู้ซื้อต้องเปิดหน้าติดตามพัสดุดูเอง
- ไม่กันผู้ขายกด `ส่งสำเร็จ` ทั้งที่ของยังไม่ถึง เพราะ product.md ยอมรับเรื่องนี้ในรุ่นนี้
- ไม่ให้ดูหน้าติดตามพัสดุโดยไม่เข้าสู่ระบบ เพราะหน้านี้มีชื่อผู้รับ
- ไม่ให้แก้หรือลบประวัติการจัดส่งที่บันทึกแล้ว เพราะสถานะย้อนกลับไม่ได้
- ไม่มีหน้ารวมพัสดุทุกชิ้นของผู้ดูแลแพลตฟอร์ม เพราะอยู่ใน ADM รุ่นนี้ผู้ดูแลแพลตฟอร์มเข้าถึงพัสดุด้วยการค้นหาเลขติดตามพัสดุ

### ข้อจำกัด

- หนึ่งคำสั่งซื้อมีหนึ่งพัสดุ ตาม product.md
- สถานะการจัดส่งมี 6 ค่าตาม product.md เพิ่มหรือเปลี่ยนชื่อไม่ได้
- รายการคำสั่งซื้อของร้านอยู่ใน ORD หน้าคำสั่งซื้อของผู้ซื้ออยู่ใน CHK สองหน้านั้นพาเข้ามาที่หน้าติดตามพัสดุของไฟล์นี้ (ORD-009 และ CHK-010)
- คำสั่งซื้อเก็บสำเนาชื่อสินค้า แบบย่อย ราคา รูปปก และที่อยู่จัดส่ง ณ ตอนสั่งซื้อ (ดู CHK-005) ไฟล์นี้ไม่เปลี่ยนสำเนานั้น
- การคืนสต็อกทำตาม INV-013 ไฟล์นี้บอกเพียงว่าคืนเมื่อไร

## 3. ผู้ใช้และสิทธิ์

| บทบาท | ทำได้ | ทำไม่ได้ |
|---|---|---|
| ผู้ซื้อ | ดูหน้าติดตามพัสดุของคำสั่งซื้อตัวเอง ค้นหาพัสดุของตัวเองด้วยเลขติดตามพัสดุ กด "ได้รับสินค้าแล้ว" หลังพัสดุเป็น `ส่งสำเร็จ` | เปลี่ยนสถานะการจัดส่ง ดูพัสดุของคนอื่น |
| ผู้ขาย | ดูและเปลี่ยนสถานะการจัดส่งของพัสดุในร้านตัวเอง | ดูหรือเปลี่ยนพัสดุของร้านอื่น ย้อนหรือข้ามขั้น กด "ได้รับสินค้าแล้ว" แทนผู้ซื้อ |
| ผู้ดูแลแพลตฟอร์ม | ดูและเปลี่ยนสถานะการจัดส่งของพัสดุทุกร้าน | ย้อนหรือข้ามขั้น กด "ได้รับสินค้าแล้ว" แทนผู้ซื้อ แก้หรือลบประวัติการจัดส่ง |
| คนที่ยังไม่เข้าสู่ระบบ | ไม่มี | ดูหน้าติดตามพัสดุ ค้นหาพัสดุ |

## 4. Requirements

ตัวอย่างในส่วนนี้ใช้คนชุดเดียวกัน: สมชายเป็นผู้ขาย เจ้าของร้าน "สมชายการช่าง" สมหญิงเป็นผู้ซื้อ วิชัยเป็นผู้ดูแลแพลตฟอร์ม มานะเป็นผู้ขาย เจ้าของร้าน "มานะสปอร์ต"

### DLV-001 สร้างพัสดุและเลขติดตามพัสดุ

- ลำดับความสำคัญ: ต้องมี
- WHEN คำสั่งซื้อเปลี่ยนเป็น `จ่ายแล้ว` THE SYSTEM SHALL สร้างพัสดุหนึ่งชิ้นของคำสั่งซื้อนั้นที่สถานะ `รอร้านจัดของ` พร้อมเลขติดตามพัสดุที่ไม่ซ้ำกับพัสดุอื่น ในรูปแบบ `BS` ตามด้วยตัวเลข 10 หลัก เก็บสำเนาที่อยู่ต้นทางของร้าน ณ เวลานั้นไว้กับพัสดุ (ดู SHP-009) และบันทึกรายการแรกในประวัติการจัดส่งด้วยเวลาที่สร้างและชื่อร้านเป็นสถานที่

กรณีปกติ

- Given สมหญิงสั่งค้อน 2 อันจากร้าน "สมชายการช่าง" รวม 340 บาท และคำสั่งซื้อยังเป็น `รอจ่ายเงิน`
- When การจ่ายเงินของสมหญิงสำเร็จ และคำสั่งซื้อเปลี่ยนเป็น `จ่ายแล้ว` วันที่ 2026-11-25 เวลา 09:00
- Then หน้าติดตามพัสดุของคำสั่งซื้อนี้แสดงเลขติดตามพัสดุ `BS0000000123` สถานะ `รอร้านจัดของ` และประวัติ 1 รายการ เวลา 25/11/2026 09:00 สถานที่ "สมชายการช่าง"

กรณีผิดพลาด

- Given สมหญิงจ่ายเงินครั้งเดียวสำหรับ 2 คำสั่งซื้อ จากร้าน "สมชายการช่าง" และร้าน "มานะสปอร์ต" เวลา 09:00
- When ระบบได้รับผลจ่ายเงินสำเร็จของการจ่ายครั้งเดียวกันซ้ำ 2 ครั้ง เวลา 09:00 และ 09:01
- Then มีพัสดุ 2 ชิ้นเท่านั้น คือหนึ่งชิ้นต่อหนึ่งคำสั่งซื้อ เลขติดตามพัสดุไม่ซ้ำกัน และไม่มีพัสดุชิ้นที่ 3 หรือ 4 เกิดขึ้น (ดู PAY-015)

### DLV-002 สิทธิ์เปลี่ยนสถานะการจัดส่ง

- ลำดับความสำคัญ: ต้องมี
- IF บัญชีที่ไม่ใช่ผู้ขายเจ้าของร้านของพัสดุนั้น และไม่ใช่ผู้ดูแลแพลตฟอร์ม พยายามเปลี่ยนสถานะการจัดส่ง THEN THE SYSTEM SHALL ปฏิเสธ แสดงข้อความ "คุณไม่มีสิทธิ์เปลี่ยนสถานะการจัดส่งของพัสดุนี้" และคงสถานะกับประวัติการจัดส่งไว้เหมือนเดิม

กรณีปกติ

- Given พัสดุ `BS0000000123` ของร้าน "สมชายการช่าง" อยู่ที่ `รอร้านจัดของ` มีประวัติ 1 รายการ
- When วิชัยซึ่งเป็นผู้ดูแลแพลตฟอร์ม เปลี่ยนเป็น `ร้านส่งของแล้ว` กรอกสถานที่ "จุดรับพัสดุบางนา" เวลา 10:00
- Then พัสดุเป็น `ร้านส่งของแล้ว` และประวัติมี 2 รายการ

กรณีผิดพลาด

- Given พัสดุ `BS0000000123` ของร้าน "สมชายการช่าง" อยู่ที่ `รอร้านจัดของ` มีประวัติ 1 รายการ
- When มานะซึ่งเป็นผู้ขายของร้านอื่น ส่งคำขอเปลี่ยนเป็น `ร้านส่งของแล้ว` เวลา 10:05 และสมหญิงซึ่งเป็นผู้ซื้อ ส่งคำขอแบบเดียวกันเวลา 10:06
- Then ทั้งสองคนเห็นข้อความ "คุณไม่มีสิทธิ์เปลี่ยนสถานะการจัดส่งของพัสดุนี้" พัสดุยังเป็น `รอร้านจัดของ` ประวัติยังมี 1 รายการ และหน้าติดตามพัสดุที่สมหญิงเห็นไม่มีปุ่มเปลี่ยนสถานะ

### DLV-003 เดินหน้าทีละขั้น ไม่ย้อน ไม่ข้าม

- ลำดับความสำคัญ: ต้องมี
- IF สถานะที่ขอเปลี่ยนไม่ใช่ขั้นถัดไปของสถานะปัจจุบันตามตารางในส่วนที่ 5 THEN THE SYSTEM SHALL ปฏิเสธ แสดงข้อความ "เปลี่ยนสถานะได้ทีละขั้น และย้อนกลับไม่ได้" พร้อมสถานะปัจจุบัน และคงสถานะกับประวัติการจัดส่งไว้เหมือนเดิม

กรณีปกติ

- Given พัสดุ `BS0000000123` อยู่ที่ `ร้านส่งของแล้ว` มีประวัติ 2 รายการ
- When สมชายเปิดหน้าเปลี่ยนสถานะเวลา 11:00
- Then หน้าแสดงปุ่มเดียวคือ "เปลี่ยนเป็น อยู่ระหว่างขนส่ง" และเมื่อพัสดุอยู่ที่ `กำลังนำส่ง` หน้าแสดง 2 ปุ่มคือ "เปลี่ยนเป็น ส่งสำเร็จ" และ "เปลี่ยนเป็น ส่งไม่สำเร็จ"

กรณีผิดพลาด

- Given พัสดุ `BS0000000123` อยู่ที่ `ร้านส่งของแล้ว` มีประวัติ 2 รายการ
- When สมชายส่งคำขอเปลี่ยนเป็น `ส่งสำเร็จ` เวลา 11:02 และส่งคำขอเปลี่ยนกลับเป็น `รอร้านจัดของ` เวลา 11:03
- Then ทั้ง 2 คำขอถูกปฏิเสธ สมชายเห็นข้อความ "เปลี่ยนสถานะได้ทีละขั้น และย้อนกลับไม่ได้" พัสดุยังเป็น `ร้านส่งของแล้ว` และประวัติยังมี 2 รายการ

### DLV-004 บันทึกเวลา สถานที่ และคนเปลี่ยน ทุกครั้ง

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายหรือผู้ดูแลแพลตฟอร์มบันทึกการเปลี่ยนสถานะการจัดส่งพร้อมสถานที่ยาว 1 ถึง 100 ตัวอักษร THE SYSTEM SHALL เปลี่ยนสถานะ และเพิ่มหนึ่งรายการในประวัติการจัดส่งที่มีสถานะใหม่ เวลาที่ระบบรับการเปลี่ยน สถานที่ที่กรอก และบัญชีที่เปลี่ยน

กรณีปกติ

- Given พัสดุ `BS0000000123` อยู่ที่ `ร้านส่งของแล้ว` มีประวัติ 2 รายการ
- When สมชายกด "เปลี่ยนเป็น อยู่ระหว่างขนส่ง" กรอกสถานที่ "ศูนย์คัดแยกลาดกระบัง" แล้วกดบันทึก เวลา 13:20
- Then สมชายเห็นข้อความ "บันทึกแล้ว" พัสดุเป็น `อยู่ระหว่างขนส่ง` ประวัติมี 3 รายการ รายการบนสุดคือ `อยู่ระหว่างขนส่ง` 25/11/2026 13:20 "ศูนย์คัดแยกลาดกระบัง" และสมหญิงเห็นรายการเดียวกันบนหน้าติดตามพัสดุ

กรณีผิดพลาด

- Given พัสดุ `BS0000000123` อยู่ที่ `ร้านส่งของแล้ว` มีประวัติ 2 รายการ
- When สมชายกดบันทึกเวลา 13:20 โดยเว้นช่องสถานที่ว่าง หรือกรอกแต่ช่องว่าง 5 ตัว หรือกรอกยาว 101 ตัวอักษร
- Then สมชายเห็นข้อความใต้ช่องว่า "กรอกสถานที่ 1 ถึง 100 ตัวอักษร" พัสดุยังเป็น `ร้านส่งของแล้ว` ประวัติยังมี 2 รายการ และถ้าสมชายปิดหน้าเปลี่ยนสถานะโดยไม่กดบันทึก ก็ไม่มีอะไรเปลี่ยนเช่นกัน

### DLV-005 `ส่งสำเร็จ` ต้องมีชื่อผู้รับ

- ลำดับความสำคัญ: ต้องมี
- IF คนเปลี่ยนสถานะขอเปลี่ยนเป็น `ส่งสำเร็จ` โดยไม่กรอกชื่อผู้รับยาว 1 ถึง 100 ตัวอักษร THEN THE SYSTEM SHALL ปฏิเสธ แสดงข้อความ "กรอกชื่อผู้รับ 1 ถึง 100 ตัวอักษร" และคงสถานะ `กำลังนำส่ง` ไว้

กรณีปกติ

- Given พัสดุ `BS0000000123` อยู่ที่ `กำลังนำส่ง` มีประวัติ 4 รายการ
- When สมชายกด "เปลี่ยนเป็น ส่งสำเร็จ" กรอกสถานที่ "บ้านเลขที่ 12 ซอยอ่อนนุช 17" กรอกชื่อผู้รับ "สมหญิง ใจดี" แล้วกดบันทึก วันที่ 2026-11-26 เวลา 15:30
- Then พัสดุเป็น `ส่งสำเร็จ` ประวัติมี 5 รายการ และสมหญิงเห็นบนหน้าติดตามพัสดุว่า `ส่งสำเร็จ` 26/11/2026 15:30 "บ้านเลขที่ 12 ซอยอ่อนนุช 17" ผู้รับ "สมหญิง ใจดี"

กรณีผิดพลาด

- Given พัสดุ `BS0000000123` อยู่ที่ `กำลังนำส่ง` มีประวัติ 4 รายการ
- When สมชายกรอกสถานที่ "บ้านเลขที่ 12 ซอยอ่อนนุช 17" แต่เว้นชื่อผู้รับว่าง แล้วกดบันทึก เวลา 15:30
- Then สมชายเห็นข้อความ "กรอกชื่อผู้รับ 1 ถึง 100 ตัวอักษร" สถานที่ที่กรอกไว้ยังอยู่ในช่อง พัสดุยังเป็น `กำลังนำส่ง` และประวัติยังมี 4 รายการ

### DLV-006 `ส่งไม่สำเร็จ` ต้องมีเหตุผล และยกเลิกคำสั่งซื้อ

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายหรือผู้ดูแลแพลตฟอร์มเปลี่ยนพัสดุจาก `กำลังนำส่ง` เป็น `ส่งไม่สำเร็จ` พร้อมสถานที่และเหตุผลยาว 1 ถึง 200 ตัวอักษร THE SYSTEM SHALL บันทึกเหตุผลลงประวัติการจัดส่ง ปิดการเปลี่ยนสถานะของพัสดุนั้นถาวร และเปลี่ยนคำสั่งซื้อเป็น `ยกเลิก` (การคืนสต็อกของคำสั่งซื้อนั้น ดู INV-013)

กรณีปกติ

- Given พัสดุ `BS0000000456` ของร้าน "สมชายการช่าง" อยู่ที่ `กำลังนำส่ง` คำสั่งซื้อมีไขควง 3 อัน และสต็อกไขควงเหลือ 7 อัน
- When สมชายกด "เปลี่ยนเป็น ส่งไม่สำเร็จ" กรอกสถานที่ "หน้าบ้านผู้ซื้อ ซอยอ่อนนุช 17" กรอกเหตุผล "ไม่มีคนรับ โทรไม่ติด 2 ครั้ง" แล้วกดบันทึก เวลา 16:00
- Then พัสดุเป็น `ส่งไม่สำเร็จ` คำสั่งซื้อเป็น `ยกเลิก` สต็อกไขควงเป็น 10 อัน สมหญิงเห็นเหตุผลบนหน้าติดตามพัสดุ และหน้าเปลี่ยนสถานะไม่มีปุ่มเปลี่ยนสถานะอีก

กรณีผิดพลาด

- Given พัสดุ `BS0000000456` อยู่ที่ `กำลังนำส่ง` และสต็อกไขควงเหลือ 7 อัน
- When สมชายกดบันทึกเป็น `ส่งไม่สำเร็จ` เวลา 16:00 โดยเว้นเหตุผลว่าง และวิชัยส่งคำขอเปลี่ยนพัสดุที่เป็น `ส่งไม่สำเร็จ` อีกชิ้นให้เป็น `ส่งสำเร็จ` เวลา 16:05
- Then สมชายเห็นข้อความ "กรอกเหตุผล 1 ถึง 200 ตัวอักษร" พัสดุยังเป็น `กำลังนำส่ง` สต็อกยังเป็น 7 อัน ส่วนวิชัยเห็นข้อความ "พัสดุนี้จบการจัดส่งแล้ว เปลี่ยนสถานะไม่ได้" และพัสดุชิ้นนั้นยังเป็น `ส่งไม่สำเร็จ`

### DLV-007 คำสั่งซื้อเป็น `กำลังจัดส่ง` เมื่อร้านส่งของ

- ลำดับความสำคัญ: ต้องมี
- WHEN พัสดุเปลี่ยนเป็น `ร้านส่งของแล้ว` THE SYSTEM SHALL เปลี่ยนคำสั่งซื้อของพัสดุนั้นจาก `จ่ายแล้ว` เป็น `กำลังจัดส่ง` ในการบันทึกครั้งเดียวกัน

กรณีปกติ

- Given คำสั่งซื้อของสมหญิง ยอด 340 บาท เป็น `จ่ายแล้ว` และพัสดุ `BS0000000123` อยู่ที่ `รอร้านจัดของ`
- When สมชายเปลี่ยนพัสดุเป็น `ร้านส่งของแล้ว` กรอกสถานที่ "จุดรับพัสดุบางนา" เวลา 10:00
- Then สมหญิงเห็นคำสั่งซื้อเป็น `กำลังจัดส่ง` และพัสดุเป็น `ร้านส่งของแล้ว` ตั้งแต่เวลา 10:00

กรณีผิดพลาด

- Given คำสั่งซื้อของสมหญิงเป็น `จ่ายแล้ว` และพัสดุ `BS0000000123` อยู่ที่ `รอร้านจัดของ` มีประวัติ 1 รายการ
- When สมชายกดบันทึกเป็น `ร้านส่งของแล้ว` เวลา 10:00 แต่ระบบบันทึกไม่สำเร็จ
- Then สมชายเห็นข้อความ "บันทึกไม่สำเร็จ ลองใหม่อีกครั้ง" คำสั่งซื้อยังเป็น `จ่ายแล้ว` พัสดุยังเป็น `รอร้านจัดของ` ประวัติยังมี 1 รายการ ไม่มีกรณีที่เปลี่ยนไปเพียงอย่างเดียว

### DLV-008 เปลี่ยนพร้อมกัน กดซ้ำ และหน้าที่เปิดค้างไว้

- ลำดับความสำคัญ: ต้องมี
- IF สถานะปัจจุบันของพัสดุตอนที่ระบบรับคำขอ ไม่ตรงกับสถานะที่หน้าของคนเปลี่ยนแสดงอยู่ตอนกดบันทึก THEN THE SYSTEM SHALL ปฏิเสธคำขอนั้น แสดงข้อความ "สถานะถูกเปลี่ยนไปแล้ว" พร้อมสถานะล่าสุด และไม่เพิ่มรายการในประวัติการจัดส่ง

กรณีปกติ

- Given พัสดุ `BS0000000123` อยู่ที่ `อยู่ระหว่างขนส่ง` มีประวัติ 3 รายการ สมชายและวิชัยเปิดหน้าเปลี่ยนสถานะไว้ทั้งคู่ตอน 14:00
- When ทั้งสองคนกดบันทึก "เปลี่ยนเป็น กำลังนำส่ง" เวลา 14:01 พร้อมกัน โดยระบบรับของสมชายก่อน
- Then สมชายเห็น "บันทึกแล้ว" วิชัยเห็น "สถานะถูกเปลี่ยนไปแล้ว" พร้อมสถานะ `กำลังนำส่ง` พัสดุเป็น `กำลังนำส่ง` และประวัติมี 4 รายการ ไม่ใช่ 5

กรณีผิดพลาด

- Given พัสดุ `BS0000000123` อยู่ที่ `กำลังนำส่ง` มีประวัติ 4 รายการ
- When สมชายกดปุ่มบันทึก "เปลี่ยนเป็น ส่งสำเร็จ" 2 ครั้งติดกันภายใน 1 วินาที เวลา 15:30 และวิชัยซึ่งเปิดหน้าค้างไว้ตั้งแต่ 15:00 กดบันทึก "เปลี่ยนเป็น ส่งไม่สำเร็จ" เวลา 15:40
- Then ประวัติมี 5 รายการ มี `ส่งสำเร็จ` รายการเดียว วิชัยเห็น "สถานะถูกเปลี่ยนไปแล้ว" พร้อมสถานะ `ส่งสำเร็จ` คำสั่งซื้อไม่ถูกยกเลิก และสต็อกไม่ถูกคืน

### DLV-009 พัสดุของคำสั่งซื้อที่ยกเลิกแล้ว

- ลำดับความสำคัญ: ต้องมี
- WHILE คำสั่งซื้อเป็น `ยกเลิก` THE SYSTEM SHALL ปฏิเสธการเปลี่ยนสถานะการจัดส่งของพัสดุในคำสั่งซื้อนั้นด้วยข้อความ "คำสั่งซื้อนี้ถูกยกเลิกแล้ว เปลี่ยนสถานะการจัดส่งไม่ได้" และแสดงคำว่า "คำสั่งซื้อถูกยกเลิก" บนหน้าติดตามพัสดุ โดยคงประวัติการจัดส่งเดิมไว้

กรณีปกติ

- Given คำสั่งซื้อของสมหญิง ยอด 340 บาท ถูกยกเลิกเวลา 09:30 (ดู RFD) ขณะที่พัสดุ `BS0000000789` อยู่ที่ `รอร้านจัดของ` มีประวัติ 1 รายการ
- When สมหญิงเปิดหน้าติดตามพัสดุเวลา 09:45
- Then สมหญิงเห็นคำว่า "คำสั่งซื้อถูกยกเลิก" เห็นประวัติเดิม 1 รายการ และไม่มีปุ่ม "ได้รับสินค้าแล้ว"

กรณีผิดพลาด

- Given สมชายเปิดหน้าเปลี่ยนสถานะของพัสดุ `BS0000000789` ไว้ตั้งแต่ 09:20 และคำสั่งซื้อถูกยกเลิกเวลา 09:30
- When สมชายกดบันทึก "เปลี่ยนเป็น ร้านส่งของแล้ว" กรอกสถานที่ "จุดรับพัสดุบางนา" เวลา 09:40
- Then สมชายเห็นข้อความ "คำสั่งซื้อนี้ถูกยกเลิกแล้ว เปลี่ยนสถานะการจัดส่งไม่ได้" พัสดุยังเป็น `รอร้านจัดของ` ประวัติยังมี 1 รายการ และคำสั่งซื้อยังเป็น `ยกเลิก`

### DLV-010 หน้าติดตามพัสดุ

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อเจ้าของคำสั่งซื้อ ผู้ขายเจ้าของร้านของพัสดุ หรือผู้ดูแลแพลตฟอร์ม เปิดหน้าติดตามพัสดุ THE SYSTEM SHALL แสดงเลขติดตามพัสดุ ชื่อร้าน สถานะการจัดส่งปัจจุบัน สถานะคำสั่งซื้อ และประวัติการจัดส่งทุกรายการเรียงจากใหม่ไปเก่า โดยแต่ละรายการมีสถานะ วันและเวลาแบบ วัน/เดือน/ปี ชั่วโมง:นาที ตามเวลาไทย สถานที่ ชื่อผู้รับของรายการ `ส่งสำเร็จ` และเหตุผลของรายการ `ส่งไม่สำเร็จ`

ผู้ขายเจ้าของร้านและผู้ดูแลแพลตฟอร์มเห็นปุ่มเปลี่ยนสถานะ (DLV-003) และที่อยู่ต้นทางของพัสดุบนหน้านี้ ผู้ซื้อไม่เห็นสองอย่างนี้ หน้าคำสั่งซื้อของผู้ซื้อ (CHK-010) และของร้าน (ORD-009) มีลิงก์มาหน้านี้

กรณีปกติ

- Given พัสดุ `BS0000000123` ของสมหญิง ผ่านมา 5 ขั้นจนเป็น `ส่งสำเร็จ` เมื่อ 26/11/2026 15:30
- When สมหญิงเข้าสู่ระบบแล้วเปิดหน้าติดตามพัสดุเวลา 16:00
- Then สมหญิงเห็นสถานะปัจจุบัน `ส่งสำเร็จ` และประวัติ 5 รายการ รายการบนสุดคือ `ส่งสำเร็จ` 26/11/2026 15:30 "บ้านเลขที่ 12 ซอยอ่อนนุช 17" ผู้รับ "สมหญิง ใจดี" รายการล่างสุดคือ `รอร้านจัดของ` 25/11/2026 09:00 "สมชายการช่าง" ส่วนพัสดุที่เพิ่งสร้างแสดงประวัติ 1 รายการพร้อมข้อความ "ร้านกำลังเตรียมของ ยังไม่มีความเคลื่อนไหวอื่น"

กรณีผิดพลาด

- Given พัสดุ `BS0000000123` เป็นของคำสั่งซื้อของสมหญิง จากร้าน "สมชายการช่าง"
- When มานะซึ่งไม่ใช่ผู้ซื้อและไม่ใช่เจ้าของร้านนี้ เปิดหน้าติดตามพัสดุของพัสดุนี้เวลา 16:10 และคนที่ยังไม่เข้าสู่ระบบเปิดหน้าเดียวกันเวลา 16:11
- Then มานะเห็นข้อความ "ไม่พบพัสดุนี้" โดยไม่เห็นข้อมูลใดของพัสดุ ส่วนคนที่ยังไม่เข้าสู่ระบบถูกพาไปหน้าเข้าสู่ระบบ (ดู ACC-008)

### DLV-011 ค้นหาพัสดุด้วยเลขติดตามพัสดุ

- ลำดับความสำคัญ: ต้องมี
- WHEN บัญชีที่เข้าสู่ระบบแล้วค้นหาด้วยเลขติดตามพัสดุ THE SYSTEM SHALL เปิดหน้าติดตามพัสดุของพัสดุนั้นถ้าบัญชีมีสิทธิ์ดูตาม DLV-010 และแสดงข้อความ "ไม่พบพัสดุนี้" ถ้าไม่มีพัสดุเลขนั้นหรือบัญชีไม่มีสิทธิ์ดู

กรณีปกติ

- Given วิชัยซึ่งเป็นผู้ดูแลแพลตฟอร์ม เข้าสู่ระบบแล้ว และมีพัสดุ `BS0000000123` ของร้าน "สมชายการช่าง"
- When วิชัยพิมพ์ `bs0000000123` มีช่องว่างท้าย 1 ตัว แล้วกดค้นหา เวลา 10:30
- Then ระบบตัดช่องว่างและไม่สนตัวพิมพ์เล็กใหญ่ แล้วเปิดหน้าติดตามพัสดุ `BS0000000123` พร้อมปุ่มเปลี่ยนสถานะ ส่วนหน้าค้นหาก่อนพิมพ์อะไรแสดงข้อความ "พิมพ์เลขติดตามพัสดุ เช่น BS0000000123"

กรณีผิดพลาด

- Given สมหญิงเข้าสู่ระบบแล้ว มีพัสดุของตัวเอง 1 ชิ้น และพัสดุ `BS0000000999` เป็นของผู้ซื้อคนอื่น
- When สมหญิงค้นหา `BS0000000999` เวลา 10:35 แล้วค้นหา `BS12` เวลา 10:36
- Then ครั้งแรกสมหญิงเห็น "ไม่พบพัสดุนี้" เหมือนกรณีที่ไม่มีเลขนั้นอยู่จริง ครั้งที่สองเห็น "เลขติดตามพัสดุต้องเป็น BS ตามด้วยตัวเลข 10 หลัก" และไม่เห็นข้อมูลของพัสดุคนอื่นทั้งสองครั้ง

### DLV-012 ผู้ซื้อกด "ได้รับสินค้าแล้ว"

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ซื้อเจ้าของคำสั่งซื้อกด "ได้รับสินค้าแล้ว" และกดยืนยันอีกครั้ง ขณะที่พัสดุเป็น `ส่งสำเร็จ` และคำสั่งซื้อเป็น `กำลังจัดส่ง` THE SYSTEM SHALL เปลี่ยนคำสั่งซื้อเป็น `สำเร็จ` และแสดงบนหน้าติดตามพัสดุว่า "ผู้ซื้อยืนยันรับสินค้าแล้ว" พร้อมวันและเวลา

กรณีปกติ

- Given พัสดุ `BS0000000123` ของสมหญิงเป็น `ส่งสำเร็จ` ตั้งแต่ 26/11/2026 15:30 และคำสั่งซื้อ ยอด 340 บาท เป็น `กำลังจัดส่ง`
- When สมหญิงกด "ได้รับสินค้าแล้ว" แล้วกด "ยืนยัน" ในหน้าต่างถามยืนยัน วันที่ 2026-11-26 เวลา 18:00
- Then คำสั่งซื้อเป็น `สำเร็จ` หน้าติดตามพัสดุแสดง "ผู้ซื้อยืนยันรับสินค้าแล้ว 26/11/2026 18:00" และปุ่ม "ได้รับสินค้าแล้ว" หายไป ถ้าสมหญิงกด "ยกเลิก" ในหน้าต่างถามยืนยัน คำสั่งซื้อยังเป็น `กำลังจัดส่ง`

กรณีผิดพลาด

- Given พัสดุ `BS0000000456` ของสมหญิงอยู่ที่ `กำลังนำส่ง` คำสั่งซื้อเป็น `กำลังจัดส่ง` และพัสดุ `BS0000000123` ถูกยืนยันรับไปแล้วตอน 18:00
- When สมหญิงส่งคำขอ "ได้รับสินค้าแล้ว" ของพัสดุ `BS0000000456` เวลา 18:05 สมหญิงกดยืนยันของ `BS0000000123` ซ้ำจากอีกหน้าหนึ่งที่เปิดค้างไว้ เวลา 18:06 และสมชายส่งคำขอเดียวกันแทนสมหญิง เวลา 18:07
- Then ครั้งแรกสมหญิงเห็น "กดได้หลังพัสดุเป็น ส่งสำเร็จ" และคำสั่งซื้อยังเป็น `กำลังจัดส่ง` ครั้งที่สองเห็น "คำสั่งซื้อนี้สำเร็จแล้ว" โดยเวลา 18:00 เดิมไม่เปลี่ยน ส่วนสมชายเห็น "เฉพาะผู้ซื้อกดได้" และไม่มีอะไรเปลี่ยน

### DLV-013 ปิดคำสั่งซื้ออัตโนมัติเมื่อครบ 7 วัน

- ลำดับความสำคัญ: ต้องมี
- WHEN ครบ 7 วัน (168 ชั่วโมง) นับจากเวลาที่พัสดุเปลี่ยนเป็น `ส่งสำเร็จ` และคำสั่งซื้อยังเป็น `กำลังจัดส่ง` THE SYSTEM SHALL เปลี่ยนคำสั่งซื้อเป็น `สำเร็จ` และแสดงบนหน้าติดตามพัสดุว่า "ระบบยืนยันรับสินค้าให้อัตโนมัติ เพราะครบ 7 วัน" พร้อมวันและเวลา

กรณีปกติ

- Given พัสดุ `BS0000000123` ของสมหญิงเป็น `ส่งสำเร็จ` ตั้งแต่ 26/11/2026 15:30 คำสั่งซื้อ ยอด 340 บาท เป็น `กำลังจัดส่ง` และสมหญิงไม่ได้กดอะไร
- When ถึงวันที่ 2026-12-03 เวลา 15:30
- Then ภายในเวลา 15:35 คำสั่งซื้อเป็น `สำเร็จ` หน้าติดตามพัสดุแสดง "ระบบยืนยันรับสินค้าให้อัตโนมัติ เพราะครบ 7 วัน" และก่อนถึงเวลานั้นหน้าติดตามพัสดุแสดง "ถ้าไม่กดยืนยัน ระบบจะยืนยันให้อัตโนมัติวันที่ 03/12/2026 15:30"

กรณีผิดพลาด

- Given พัสดุ `BS0000000123` เป็น `ส่งสำเร็จ` ตั้งแต่ 26/11/2026 15:30 และสมหญิงกด "ได้รับสินค้าแล้ว" ไปแล้วเมื่อ 26/11/2026 18:00
- When ถึงวันที่ 2026-12-03 เวลา 15:30 หรือสมหญิงกดยืนยันในวินาทีเดียวกับที่ครบ 7 วัน
- Then คำสั่งซื้อเป็น `สำเร็จ` ครั้งเดียว หน้าติดตามพัสดุแสดงข้อความยืนยันเพียง 1 บรรทัดของเหตุการณ์ที่ระบบรับก่อน และเวลา 18:00 เดิมไม่ถูกเขียนทับ

### DLV-014 หน้ากำลังโหลดและหน้าผิดพลาด

- ลำดับความสำคัญ: ต้องมี
- IF หน้าติดตามพัสดุ หน้าค้นหาพัสดุ หรือหน้าเปลี่ยนสถานะ โหลดหรือบันทึกข้อมูลไม่สำเร็จ หรือไม่ได้คำตอบภายใน 10 วินาที THEN THE SYSTEM SHALL แสดงข้อความ "โหลดข้อมูลไม่ได้ตอนนี้" หรือ "บันทึกไม่สำเร็จ ลองใหม่อีกครั้ง" พร้อมปุ่ม "ลองใหม่" คงข้อมูลที่ผู้ใช้กรอกไว้ในช่อง และไม่แสดงสถานะการจัดส่งที่ยังไม่ได้บันทึกจริง

กรณีปกติ

- Given สมหญิงเปิดหน้าติดตามพัสดุ `BS0000000123` ที่มีประวัติ 3 รายการ เวลา 14:05
- When ข้อมูลยังมาไม่ถึง
- Then สมหญิงเห็นโครงหน้าพร้อมคำว่า "กำลังโหลด" แทนประวัติ และเมื่อข้อมูลมาถึงเห็นประวัติครบ 3 รายการ ส่วนสมชายที่กดบันทึกการเปลี่ยนสถานะเวลา 14:06 เห็นปุ่มบันทึกเป็น "กำลังบันทึก" และกดซ้ำไม่ได้จนกว่าจะได้ผล

กรณีผิดพลาด

- Given สมชายกรอกสถานที่ "ศูนย์คัดแยกลาดกระบัง" เพื่อเปลี่ยนพัสดุ `BS0000000123` จาก `ร้านส่งของแล้ว` ที่มีประวัติ 2 รายการ
- When สมชายกดบันทึกเวลา 13:20 แล้วไม่ได้คำตอบภายใน 10 วินาที
- Then สมชายเห็น "บันทึกไม่สำเร็จ ลองใหม่อีกครั้ง" พร้อมปุ่ม "ลองใหม่" ช่องสถานที่ยังมีคำว่า "ศูนย์คัดแยกลาดกระบัง" และเมื่อกด "ลองใหม่" เวลา 13:21 ประวัติมี 3 รายการ ไม่ใช่ 4 แม้คำขอแรกจะไปถึงระบบช้า

### DLV-Q01 ความเร็วของหน้าและการบันทึก

- ลำดับความสำคัญ: ต้องมี
- THE SYSTEM SHALL แสดงหน้าติดตามพัสดุและผลการค้นหาพัสดุ และตอบผลการบันทึกการเปลี่ยนสถานะ ภายใน 2 วินาที ใน 95 จาก 100 ครั้ง ขณะมีผู้ใช้พร้อมกัน 20 คน

กรณีปกติ

- Given ข้อมูลตัวอย่าง 50 ร้าน 1,000 สินค้า และพัสดุ 500 ชิ้น มีผู้ใช้จำลอง 20 คนใช้งานพร้อมกัน
- When สมหญิงเปิดหน้าติดตามพัสดุ `BS0000000123` 100 ครั้ง ระหว่างเวลา 14:00 ถึง 14:05
- Then อย่างน้อย 95 ครั้งแสดงผลครบภายใน 2 วินาที

กรณีผิดพลาด

- Given สภาพเดียวกับกรณีปกติ
- When การเปิดหน้าครั้งหนึ่งของสมหญิงเวลา 14:03 ใช้เวลาเกิน 2 วินาที
- Then สมหญิงยังเห็นคำว่า "กำลังโหลด" ตาม DLV-014 และถ้าเกิน 10 วินาทีเห็น "โหลดข้อมูลไม่ได้ตอนนี้" พร้อมปุ่ม "ลองใหม่" ไม่เห็นหน้าเปล่า

### DLV-Q02 ไม่มีรายการซ้ำเมื่อเปลี่ยนพร้อมกัน

- ลำดับความสำคัญ: ต้องมี
- THE SYSTEM SHALL รับการเปลี่ยนสถานะของพัสดุหนึ่งชิ้นได้เพียงหนึ่งคำขอต่อหนึ่งขั้น ใน 100 จาก 100 ครั้งที่มีคำขอเข้ามาพร้อมกัน

กรณีปกติ

- Given พัสดุทดสอบ 100 ชิ้น อยู่ที่ `รอร้านจัดของ` แต่ละชิ้นมีประวัติ 1 รายการ
- When สมชายและวิชัยส่งคำขอเปลี่ยนเป็น `ร้านส่งของแล้ว` ของพัสดุชิ้นเดียวกันพร้อมกัน ทำซ้ำกับทั้ง 100 ชิ้น เวลา 11:00
- Then ทั้ง 100 ชิ้นมีประวัติ 2 รายการพอดี แต่ละชิ้นมีคนได้ "บันทึกแล้ว" 1 คน และอีกคนได้ "สถานะถูกเปลี่ยนไปแล้ว"

กรณีผิดพลาด

- Given พัสดุทดสอบ 100 ชิ้นเดิม หลังการทดสอบเวลา 11:00
- When ตรวจนับเวลา 11:10 แล้วพบพัสดุแม้แต่ 1 ชิ้นที่มีประวัติ 3 รายการ หรือข้ามไปเป็น `อยู่ระหว่างขนส่ง`
- Then ถือว่าไม่ผ่านข้อนี้ และ feature นี้ยังส่งมอบไม่ได้

### DLV-Q03 ความตรงเวลาของการปิดคำสั่งซื้ออัตโนมัติ

- ลำดับความสำคัญ: ต้องมี
- THE SYSTEM SHALL เปลี่ยนคำสั่งซื้อเป็น `สำเร็จ` ภายใน 5 นาทีหลังครบ 7 วันตาม DLV-013 ใน 100 จาก 100 คำสั่งซื้อ

กรณีปกติ

- Given คำสั่งซื้อทดสอบ 100 รายการของสมหญิง ที่พัสดุเป็น `ส่งสำเร็จ` ตั้งแต่ 26/11/2026 15:30 และยังไม่มีการกดยืนยัน
- When ถึงวันที่ 2026-12-03 เวลา 15:35
- Then คำสั่งซื้อทั้ง 100 รายการเป็น `สำเร็จ`

กรณีผิดพลาด

- Given คำสั่งซื้อทดสอบ 100 รายการเดิม และระบบถูกปิดอยู่ระหว่าง 2026-12-03 เวลา 15:00 ถึง 16:00
- When ระบบเปิดกลับมาเวลา 16:00
- Then ภายในเวลา 16:05 คำสั่งซื้อทั้ง 100 รายการเป็น `สำเร็จ` ไม่มีรายการใดค้างที่ `กำลังจัดส่ง`

- agent ตัดสินใจ: หน้าติดตามพัสดุต้องเข้าสู่ระบบก่อน ดูด้วยเลขติดตามพัสดุโดยไม่เข้าสู่ระบบไม่ได้ เพราะหน้านี้มีชื่อผู้รับ และ product.md กำหนดว่าผู้ซื้อเห็นได้เฉพาะคำสั่งซื้อของตัวเอง (2026-11-24)
- agent ตัดสินใจ: คนที่ดูหน้าติดตามพัสดุได้คือผู้ซื้อเจ้าของคำสั่งซื้อ ผู้ขายเจ้าของร้านของพัสดุ และผู้ดูแลแพลตฟอร์ม คนอื่นเห็น "ไม่พบพัสดุนี้" เหมือนกรณีไม่มีพัสดุนั้น (2026-11-24)
- agent ตัดสินใจ: มีช่องค้นหาพัสดุด้วยเลขติดตามพัสดุสำหรับบัญชีที่เข้าสู่ระบบแล้ว เป็นทางที่ผู้ดูแลแพลตฟอร์มเข้าถึงพัสดุในชุด 1 เพราะหน้ารวมของผู้ดูแลแพลตฟอร์มอยู่ใน ADM ซึ่งเป็นชุด 2 (2026-11-24)
- agent ตัดสินใจ: พัสดุเก็บสำเนาที่อยู่ต้นทางของร้านตอนสร้างพัสดุ ตามที่ SHP-009 อ้างถึง แสดงเฉพาะผู้ขายเจ้าของร้านและผู้ดูแลแพลตฟอร์ม (2026-11-24)
- agent ตัดสินใจ: สถานที่เป็นข้อความที่คนเปลี่ยนสถานะพิมพ์เอง ยาว 1 ถึง 100 ตัวอักษร ต้องกรอกทุกครั้ง รายการแรกตอนสร้างพัสดุใช้ชื่อร้านเป็นสถานที่ (2026-11-24)
- agent ตัดสินใจ: เวลาในประวัติการจัดส่งคือเวลาที่ระบบรับการเปลี่ยน คนเปลี่ยนสถานะกรอกหรือแก้เวลาเองไม่ได้ แสดงเป็นเวลาไทย (2026-11-24)
- agent ตัดสินใจ: ชื่อผู้รับยาว 1 ถึง 100 ตัวอักษร เหตุผลที่ส่งไม่สำเร็จเป็นข้อความพิมพ์เอง ยาว 1 ถึง 200 ตัวอักษร (2026-11-24)
- agent ตัดสินใจ: ประวัติการจัดส่งที่บันทึกแล้วแก้และลบไม่ได้ แม้พิมพ์สถานที่หรือชื่อผู้รับผิด (2026-11-24)
- agent ตัดสินใจ: เมื่อมีสองคนเปลี่ยนพัสดุชิ้นเดียวกันพร้อมกัน หรือกดซ้ำ หรือกดจากหน้าที่เปิดค้างไว้ คำขอที่ระบบรับก่อนเป็นผล คำขอที่เหลือถูกปฏิเสธพร้อมสถานะล่าสุด (2026-11-24)
- agent ตัดสินใจ: เมื่อคำสั่งซื้อเป็น `ยกเลิก` พัสดุคงสถานะการจัดส่งสุดท้ายไว้ เปลี่ยนต่อไม่ได้ และหน้าติดตามพัสดุแสดงว่า "คำสั่งซื้อถูกยกเลิก" ไม่เพิ่มสถานะการจัดส่งค่าใหม่ (2026-11-24)
- agent ตัดสินใจ: ปุ่ม "ได้รับสินค้าแล้ว" มีหน้าต่างถามยืนยันหนึ่งครั้ง กดแล้วยกเลิกไม่ได้ และกดได้เฉพาะผู้ซื้อเจ้าของคำสั่งซื้อ (2026-11-24)
- agent ตัดสินใจ: 7 วันนับเป็น 168 ชั่วโมงจากเวลาที่พัสดุเป็น `ส่งสำเร็จ` และระบบปิดคำสั่งซื้อภายใน 5 นาทีหลังครบกำหนด ถ้าระบบปิดอยู่ตอนครบกำหนด ให้ปิดคำสั่งซื้อภายใน 5 นาทีหลังระบบเปิดกลับมา (2026-11-24)
- agent ตัดสินใจ: เมื่อพัสดุเป็น `ส่งไม่สำเร็จ` feature นี้ทำเพียงยกเลิกคำสั่งซื้อและคืนสต็อก การคืนเงินให้ผู้ซื้ออยู่ใน RFD (2026-11-24)
