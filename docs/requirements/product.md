## 1. เป้าหมายที่วัดได้

- เป้าหมาย: เจ้าของโปรเจคได้เห็นและลองธุรกิจซื้อขายของออนไลน์ด้วยตัวเองครบทุกขั้น ตั้งแต่เปิดร้าน จัดการหลังบ้าน จนถึงติดตามการจัดส่ง
- วัดความสำเร็จจาก: คนหนึ่งคนใช้สองบัญชีเดินเส้นทางหลักจบได้ภายใน 10 นาที โดยไม่มีใครช่วย คือบัญชีแรกเปิดร้านและลงสินค้า 1 ชิ้น บัญชีที่สองสั่งซื้อและจ่ายเงิน แล้วเห็นการจัดส่งถึงสถานะ `ส่งสำเร็จ`

## 2. ผู้ใช้และบทบาท

ยังไม่มีผู้ใช้จริง บัญชีเดียวเป็นได้ทั้งผู้ซื้อและผู้ขาย

| บทบาท | เป็นใคร | ต้องการอะไรจากระบบ |
|---|---|---|
| ผู้ซื้อ | บัญชีที่เลือกซื้อสินค้า | ดูสินค้า สั่งซื้อจากหลายร้าน ติดตามการจัดส่ง กดยืนยันว่าได้รับสินค้าแล้ว |
| ผู้ขาย | บัญชีที่เป็นเจ้าของร้าน | เปิดร้าน ลงสินค้า จัดการสต็อกและคำสั่งซื้อ เปลี่ยนสถานะการจัดส่งของร้านตัวเอง |
| ผู้ดูแลแพลตฟอร์ม | คนของแพลตฟอร์ม | ดูแลร้านและบัญชีทั้งหมด เปลี่ยนสถานะการจัดส่งได้ |

ไม่มีบทบาทคนส่งของ ผู้ซื้อเปลี่ยนสถานะการจัดส่งไม่ได้

สิทธิ์ที่ใช้ทั้งระบบ

- หนึ่งบัญชีเปิดได้หนึ่งร้าน และเปิดได้ทันทีไม่ต้องรออนุมัติ
- ผู้ขายเห็นและแก้ได้เฉพาะร้าน สินค้า และคำสั่งซื้อของร้านตัวเอง
- ผู้ซื้อเห็นได้เฉพาะคำสั่งซื้อของตัวเอง
- ผู้ขายซื้อของจากร้านตัวเองไม่ได้
- ผู้ดูแลแพลตฟอร์มระงับร้านและบัญชีได้ แต่แก้สินค้าหรือราคาแทนร้านไม่ได้

## 3. ขอบเขต

### ทำ

- แพลตฟอร์มแบบหลายร้านในที่เดียว ผู้ซื้อเลือกซื้อจากหลายร้านได้
- feature 18 ข้อตามส่วนที่ 7 ทุกข้ออยู่ในรุ่นแรก
- บัญชี ร้าน สินค้า สต็อก และคำสั่งซื้อ เก็บข้อมูลจริง สต็อกลดจริง
- ข้อมูลตัวอย่าง: มีร้าน สินค้า และคำสั่งซื้อตัวอย่างตั้งแต่เปิดระบบ
- ใช้ผ่านเว็บ เปิดบนมือถือได้ ภาษาไทย ราคาเป็นบาท ขายและส่งในไทย

### ไม่ทำ

- ไม่ใช้เงินจริง เพราะไม่มีงบและยังไม่มีผู้ใช้จริง
- ไม่ต่อกับบริษัทขนส่งจริง เพราะยังไม่มีการใช้งานจริง
- ไม่มีบทบาทคนส่งของ เพราะให้ผู้ขายและผู้ดูแลแพลตฟอร์มเปลี่ยนสถานะการจัดส่งแทน
- ไม่ทำไลฟ์ขายของ โฆษณา เกมและเหรียญสะสม เพราะไม่ช่วยให้เห็นเส้นทางซื้อขายและจัดส่ง แต่ใช้งานมาก
- ไม่ทำแอปมือถือ เพราะเว็บเปิดบนมือถือได้อยู่แล้ว
- ไม่กันผู้ขายกด `ส่งสำเร็จ` ทั้งที่ของยังไม่ถึง เพราะรุ่นนี้ไม่มีเงินจริง ผู้ซื้อแจ้งปัญหาผ่าน feature ยกเลิก คืนสินค้า และคืนเงิน

## 4. ข้อจำกัด

- ไม่มีงบ
- คนทำคือเจ้าของโปรเจคหนึ่งคนกับ agent หลายตัวที่ทำพร้อมกัน
- งานต้องแบ่งเป็นชิ้นที่แยกกันทำและทำพร้อมกันได้
- requirement ต้องเสร็จภายในคืนวันที่ 2026-11-24 และเช้าวันที่ 2026-11-25 ต้องมีทั้งหน้าบ้านและหลังบ้าน โดยต้องได้ feature ชุด 1 ที่เดินเส้นทางหลักจบได้ ชุด 2 และชุด 3 ทำต่อหลังจากนั้น
- Omise โหมดทดลองไม่มีการแบ่งเงินให้หลายร้านตอนจ่าย ระบบต้องคิดยอดของแต่ละร้านเอง

## 5. ภาพรวมการทำงาน

- ข้อมูลหลัก: บัญชี ร้าน สินค้า สต็อก ตะกร้า คำสั่งซื้อ การจ่ายเงิน การจัดส่ง
- คำสั่งซื้อ:
  - ตะกร้าเดียวมีของหลายร้านได้ จ่ายเงินครั้งเดียว แล้วระบบแยกเป็นหนึ่งคำสั่งซื้อต่อหนึ่งร้าน
  - หนึ่งคำสั่งซื้อมีหนึ่งการจัดส่ง
  - สถานะ: `รอจ่ายเงิน` → `จ่ายแล้ว` → `กำลังจัดส่ง` → `สำเร็จ` และเปลี่ยนเป็น `ยกเลิก` เมื่อผู้ซื้อยกเลิกก่อนร้านส่งของ เมื่อไม่จ่ายเงินภายในเวลา หรือเมื่อพัสดุเป็น `ส่งไม่สำเร็จ`
- สต็อก: ถูกจองตอนกดสั่งซื้อ ถ้าไม่จ่ายภายใน 30 นาที ระบบยกเลิกคำสั่งซื้อและคืนสต็อก
- สถานะการจัดส่ง: `รอร้านจัดของ` → `ร้านส่งของแล้ว` → `อยู่ระหว่างขนส่ง` → `กำลังนำส่ง` → `ส่งสำเร็จ`
  - `กำลังนำส่ง` เปลี่ยนเป็น `ส่งไม่สำเร็จ` ได้ เช่น ไม่มีคนรับ
  - เดินหน้าได้ทีละขั้น ย้อนกลับไม่ได้
  - ตอนเปลี่ยนเป็น `ส่งสำเร็จ` ต้องกรอกชื่อผู้รับ
  - ทุกครั้งที่เปลี่ยน ระบบเก็บเวลาและสถานที่ไว้ให้ผู้ซื้อเห็น
  - หลัง `ส่งสำเร็จ` ผู้ซื้อกด "ได้รับสินค้าแล้ว" ยืนยันอีกชั้น
- เส้นทางหลัก: ผู้ขายสมัครบัญชี เปิดร้าน ลงสินค้า ตั้งสต็อก → ผู้ซื้อค้นหาสินค้า ใส่ตะกร้า สั่งซื้อ จ่ายเงิน → ผู้ขายเปลี่ยนสถานะการจัดส่งจนถึง `ส่งสำเร็จ` → ผู้ซื้อกด "ได้รับสินค้าแล้ว"
- ระบบภายนอก:
  - การจ่ายเงิน: Omise โหมดทดลอง รับบัตรและ PromptPay รับเงินจริงไม่ได้ ถ้า Omise ล่มหรือไม่ตอบภายใน 10 วินาที ระบบแสดงว่าจ่ายเงินไม่ได้ตอนนี้ คำสั่งซื้อและสต็อกที่จองยังอยู่
  - การจัดส่ง: ไม่ต่อระบบภายนอก
  - ระบบส่งอีเมล: ใช้ส่งลิงก์ตั้งรหัสผ่านใหม่ รายละเอียดอยู่ใน `account.md`
- กรณีขอบที่ใช้ทั้งระบบ:
  - ของเหลือ 1 ชิ้น มีสองคนกดสั่งซื้อพร้อมกัน: คนที่ระบบรับก่อนได้ของ อีกคนเห็นข้อความว่าของหมด
  - จ่ายเงินไม่ผ่าน: คำสั่งซื้อยังอยู่ที่ `รอจ่ายเงิน` และจ่ายใหม่ได้จนครบ 30 นาที
  - ร้านแก้ราคาหลังของอยู่ในตะกร้า: ผู้ซื้อเห็นราคาใหม่พร้อมข้อความแจ้งก่อนสั่งซื้อ

## 8. สมมติฐาน คำถามค้าง และบันทึก

### สมมติฐาน

- เจ้าของโปรเจคมอบให้ agent ตัดสินใจเรื่องที่เปลี่ยนระหว่างทางได้เอง แล้วสรุปให้ฟังหลังหน้าบ้านและหลังบ้านเสร็จ ข้อที่ agent ตัดสินใจเองในไฟล์ feature ให้เขียนไว้ที่ส่วนสมมติฐานของไฟล์นั้น พร้อมคำว่า "agent ตัดสินใจ" (2026-11-24)

- agent ตัดสินใจ: เมื่อคำสั่งซื้อเปลี่ยนเป็น `จ่ายแล้ว` ระบบสร้างพัสดุที่สถานะ `รอร้านจัดของ` พร้อมเลขติดตามพัสดุ รูปแบบ `BS` ตามด้วยตัวเลข 10 หลัก (2026-11-24)
- agent ตัดสินใจ: คำสั่งซื้อเปลี่ยนเป็น `กำลังจัดส่ง` เมื่อพัสดุเป็น `ร้านส่งของแล้ว` และเปลี่ยนเป็น `สำเร็จ` เมื่อผู้ซื้อกด "ได้รับสินค้าแล้ว" หรือครบ 7 วันหลังพัสดุเป็น `ส่งสำเร็จ` (2026-11-24)
- agent ตัดสินใจ: พัสดุที่เป็น `ส่งไม่สำเร็จ` เป็นสถานะปลายทาง คำสั่งซื้อเปลี่ยนเป็น `ยกเลิก` และสต็อกคืนกลับ (2026-11-24)
- agent ตัดสินใจ: ในชุด 1 ผู้ซื้อยกเลิกคำสั่งซื้อเองได้เฉพาะตอน `รอจ่ายเงิน` การยกเลิกหลังจ่ายเงินอยู่ใน feature RFD (2026-11-24)
- agent ตัดสินใจ: ค่าส่งคงที่ 40 บาทต่อหนึ่งคำสั่งซื้อ (2026-11-24)
