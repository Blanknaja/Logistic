## 1. เป้าหมายและตัวเลขความสำเร็จ

- เป้าหมาย: ผู้ขายรู้ว่าร้านตัวเองมีคำสั่งซื้ออะไรบ้าง ข้อไหนต้องจัดของ และไปถึงขั้นตอนการจัดส่งได้โดยไม่ต้องถามใคร
- วัดความสำเร็จจาก: ผู้ขายที่เพิ่งเข้าหลังบ้านของร้าน หาคำสั่งซื้อที่ `จ่ายแล้ว` ข้อแรกและไปถึงหน้าติดตามพัสดุของคำสั่งซื้อนั้นได้ภายใน 30 วินาที โดยกดไม่เกิน 3 ครั้ง วัดจากการให้คนหนึ่งคนลองทำ 5 รอบกับข้อมูลตัวอย่าง

## 2. ขอบเขต

### ทำ

- หน้ารายการคำสั่งซื้อของร้านตัวเอง เรียงจากใหม่ไปเก่า แบ่งหน้าละ 20 รายการ
- กรองรายการตามสถานะคำสั่งซื้อ: `รอจ่ายเงิน` `จ่ายแล้ว` `กำลังจัดส่ง` `สำเร็จ` `ยกเลิก`
- ค้นหาด้วยเลขคำสั่งซื้อ
- ตัวเลขจำนวนคำสั่งซื้อที่รอจัดของ
- หน้ารายละเอียดคำสั่งซื้อ: สินค้า แบบย่อย จำนวน ยอดเงิน ที่อยู่จัดส่งและผู้รับ ผลการจ่ายเงิน เลขติดตามพัสดุ และสถานะการจัดส่ง
- ปุ่มจากคำสั่งซื้อไปหน้าติดตามพัสดุของ DLV
- การแจ้งเมื่อมีคำสั่งซื้อใหม่ หรือคำสั่งซื้อเปลี่ยนสถานะ ขณะผู้ขายเปิดหน้าค้างไว้
- การกันไม่ให้เห็นคำสั่งซื้อของร้านอื่น

### ไม่ทำ

- ไม่เปลี่ยนสถานะการจัดส่ง และไม่แสดงลำดับเหตุการณ์การจัดส่ง เพราะ DLV เป็นเจ้าของการเปลี่ยนสถานะการจัดส่งทั้งหมด ORD แสดงสถานะล่าสุดและพาไปหน้าติดตามพัสดุ (DLV-010) เท่านั้น
- ไม่ให้ผู้ขายเปลี่ยนสถานะคำสั่งซื้อเอง เพราะสถานะคำสั่งซื้อเปลี่ยนได้จากการจ่ายเงิน (PAY) การจัดส่ง (DLV) เส้นตาย 30 นาที (CHK-008) และการยกเลิกของผู้ซื้อ (CHK-011) เท่านั้น
- ไม่ทำการยกเลิกและคืนเงินจากฝั่งร้าน เพราะอยู่ใน RFD
- ไม่ทำรายงานยอดขาย เพราะอยู่ใน RPT
- ไม่พิมพ์ใบปะหน้าพัสดุ เพราะรุ่นนี้ไม่ต่อกับบริษัทจัดส่งจริง จึงไม่มีใบที่ต้องติด
- ไม่ส่งออกรายการคำสั่งซื้อเป็นไฟล์ เพราะยังไม่มีผู้ใช้จริงที่ต้องนำข้อมูลไปใช้ต่อ
- ไม่ทำหน้าคำสั่งซื้อของผู้ซื้อ เพราะอยู่ใน CHK
- ไม่ทำหน้าดูคำสั่งซื้อของผู้ดูแลแพลตฟอร์ม เพราะอยู่ใน ADM
- ไม่ส่งการแจ้งเตือนออกนอกหน้านี้ เช่น อีเมล เพราะอยู่ใน NTF

### ข้อจำกัด

- ต้องเสร็จในชุด 1 เพื่อให้เดินเส้นทางหลักจบได้ในเช้าวันที่ 2026-11-25
- ORD อ่านข้อมูลที่ feature อื่นสร้าง: คำสั่งซื้อและที่อยู่จัดส่งจาก CHK ผลการจ่ายเงินจาก PAY พัสดุจาก DLV ร้านจาก SHP การเข้าสู่ระบบจาก ACC
- หนึ่งบัญชีมีได้หนึ่งร้าน หน้านี้จึงไม่มีปุ่มสลับร้าน

## 3. ผู้ใช้และสิทธิ์

| บทบาท | ทำได้ | ทำไม่ได้ |
|---|---|---|
| ผู้ขาย | ดูรายการ กรอง ค้นหา และเปิดรายละเอียดคำสั่งซื้อของร้านตัวเอง กดไปหน้าติดตามพัสดุ | เห็นคำสั่งซื้อของร้านอื่น เปลี่ยนสถานะคำสั่งซื้อ แก้สินค้า ยอดเงิน หรือที่อยู่จัดส่งในคำสั่งซื้อ |
| ผู้ซื้อ (บัญชีที่ยังไม่มีร้าน) | ไม่มี | เข้าหน้าของ ORD ทุกหน้า |
| ผู้ดูแลแพลตฟอร์ม | ไม่มีใน ORD ดูคำสั่งซื้อผ่าน ADM | เข้าหน้าของ ORD ในฐานะผู้ดูแลแพลตฟอร์ม |
| คนที่ยังไม่เข้าสู่ระบบ | ไม่มี | เข้าหน้าของ ORD ทุกหน้า |

## 4. Requirements

ตัวอย่างทุกข้อใช้ข้อมูลชุดเดียวกัน: สมชายเป็นผู้ขาย เจ้าของร้าน "สมชายเสื้อผ้า" สมหญิงเป็นผู้ซื้อ วิชัยเป็นผู้ขาย เจ้าของร้าน "วิชัยรองเท้า" เลขคำสั่งซื้อในตัวอย่างมีไว้อธิบายเท่านั้น รูปแบบจริงดู CHK-005

### ORD-001 แสดงรายการคำสั่งซื้อของร้านตัวเอง

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายเปิดหน้ารายการคำสั่งซื้อ THE SYSTEM SHALL แสดงเฉพาะคำสั่งซื้อของร้านตัวเอง เรียงตามเวลาสั่งซื้อจากใหม่ไปเก่า หน้าละ 20 รายการ โดยแต่ละรายการมีเลขคำสั่งซื้อ เวลาสั่งซื้อ ชื่อผู้รับ จำนวนชิ้นรวม ยอดรวม และสถานะคำสั่งซื้อ

กรณีปกติ

- Given ร้าน "สมชายเสื้อผ้า" มีคำสั่งซื้อ 45 รายการ และร้าน "วิชัยรองเท้า" มี 12 รายการ วันที่ 2026-11-24 เวลา 09:00
- When สมชายเปิดหน้ารายการคำสั่งซื้อ
- Then สมชายเห็น 20 รายการที่ใหม่ที่สุดของร้านตัวเอง เห็นว่ามีทั้งหมด 3 หน้า และไม่เห็นคำสั่งซื้อของร้าน "วิชัยรองเท้า" เลย เหนือรายการมีบรรทัด "รอจัดของ N รายการ" ที่กดแล้วไปตัวกรอง `จ่ายแล้ว` รายการบนสุดคือเลข `2611240045` สั่งเมื่อ 08:52 ผู้รับ "สมหญิง ใจดี" 2 ชิ้น ยอดรวม 540 บาท สถานะ `จ่ายแล้ว` พร้อมปุ่ม "จัดส่ง"

กรณีผิดพลาด

- Given ร้าน "สมชายเสื้อผ้า" เพิ่งเปิดเมื่อ 08:30 และยังไม่มีคำสั่งซื้อเลย (0 รายการ)
- When สมชายเปิดหน้ารายการคำสั่งซื้อเวลา 09:00
- Then สมชายเห็นข้อความ "ร้านยังไม่มีคำสั่งซื้อ" กับ "คำสั่งซื้อจะขึ้นที่นี่เมื่อผู้ซื้อสั่งสินค้าของร้าน" แทนตารางเปล่า ตัวกรองทุกสถานะแสดงจำนวน 0 และไม่มีข้อความแจ้งข้อผิดพลาด

กรณีผิดพลาด (ข้อมูลซ้ำตอนเปลี่ยนหน้า)

- Given สมชายเปิดหน้า 1 ค้างไว้ตั้งแต่ 09:00 ร้านมี 45 รายการ แล้วเวลา 09:03 มีคำสั่งซื้อใหม่เข้ามา 1 รายการ
- When สมชายกดไปหน้า 2 เวลา 09:04
- Then หน้า 2 ไม่แสดงคำสั่งซื้อที่สมชายเห็นไปแล้วในหน้า 1 ซ้ำอีก และคำสั่งซื้อทั้ง 45 รายการเดิมยังดูได้ครบเมื่อไล่จนถึงหน้าสุดท้าย

### ORD-002 กรองรายการตามสถานะ

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายเลือกตัวกรองสถานะ `ทั้งหมด` `รอจ่ายเงิน` `จ่ายแล้ว` `กำลังจัดส่ง` `สำเร็จ` หรือ `ยกเลิก` THE SYSTEM SHALL แสดงเฉพาะคำสั่งซื้อของร้านตัวเองที่อยู่ในสถานะนั้น พร้อมจำนวนคำสั่งซื้อของแต่ละสถานะกำกับที่ตัวกรอง

กรณีปกติ

- Given ร้าน "สมชายเสื้อผ้า" มีคำสั่งซื้อ 45 รายการ: `รอจ่ายเงิน` 3 `จ่ายแล้ว` 5 `กำลังจัดส่ง` 7 `สำเร็จ` 26 `ยกเลิก` 4 เวลา 09:00 และหน้าเปิดมาที่ตัวกรอง `ทั้งหมด`
- When สมชายกดตัวกรอง `จ่ายแล้ว`
- Then สมชายเห็น 5 รายการที่เป็น `จ่ายแล้ว` เท่านั้น ตัวกรองแสดงจำนวน 45, 3, 5, 7, 26, 4 ตามลำดับ และเมื่อโหลดหน้าเว็บใหม่ ตัวกรองยังอยู่ที่ `จ่ายแล้ว`

กรณีผิดพลาด

- Given ร้าน "สมชายเสื้อผ้า" มีคำสั่งซื้อ 10 รายการ ไม่มีรายการไหนเป็น `ยกเลิก` เวลา 09:00
- When สมชายกดตัวกรอง `ยกเลิก`
- Then สมชายเห็นข้อความ "ไม่มีคำสั่งซื้อในสถานะ ยกเลิก" ตัวกรองอื่นยังกดได้ และจำนวนที่ตัวกรอง `ยกเลิก` เป็น 0

### ORD-003 ค้นหาด้วยเลขคำสั่งซื้อ

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายพิมพ์เลขคำสั่งซื้อทั้งเลขหรือบางส่วนอย่างน้อย 3 ตัวอักษรแล้วกดค้นหา THE SYSTEM SHALL แสดงคำสั่งซื้อของร้านตัวเองทุกสถานะที่เลขคำสั่งซื้อมีข้อความนั้นอยู่ โดยไม่สนช่องว่างหน้าหลังและตัวพิมพ์เล็กใหญ่

กรณีปกติ

- Given ร้าน "สมชายเสื้อผ้า" มีคำสั่งซื้อเลข `2611240045` สถานะ `จ่ายแล้ว` และสมชายอยู่ที่ตัวกรอง `สำเร็จ` เวลา 10:15
- When สมชายพิมพ์ ` 0045 ` (มีช่องว่างหน้าหลัง) แล้วกดค้นหา
- Then สมชายเห็นคำสั่งซื้อเลข `2611240045` 1 รายการ แม้จะไม่ได้อยู่ในสถานะ `สำเร็จ` และเมื่อสมชายกดล้างคำค้น รายการกลับไปเป็นตัวกรอง `สำเร็จ` เหมือนก่อนค้นหา

กรณีผิดพลาด

- Given ร้าน "วิชัยรองเท้า" มีคำสั่งซื้อเลข `2611240099` และร้าน "สมชายเสื้อผ้า" ไม่มีเลขนี้ เวลา 10:20
- When สมชายค้นหา `2611240099`
- Then สมชายเห็นข้อความ "ไม่พบคำสั่งซื้อเลข 2611240099 ในร้านของคุณ" ไม่เห็นข้อมูลใดของคำสั่งซื้อร้าน "วิชัยรองเท้า" และข้อความที่เห็นเหมือนกับตอนค้นหาเลขที่ไม่มีอยู่จริงทุกตัวอักษร

กรณีผิดพลาด (คำค้นสั้นเกิน)

- Given สมชายอยู่หน้ารายการคำสั่งซื้อ เวลา 10:22
- When สมชายพิมพ์ `45` (2 ตัวอักษร) แล้วกดค้นหา
- Then สมชายเห็นข้อความ "พิมพ์อย่างน้อย 3 ตัวอักษร" และรายการที่แสดงอยู่ไม่เปลี่ยน

### ORD-004 แสดงจำนวนคำสั่งซื้อที่รอจัดของ

- ลำดับความสำคัญ: ต้องมี
- WHILE ผู้ขายอยู่ในหน้าใดก็ตามของหลังบ้านของร้าน THE SYSTEM SHALL แสดงจำนวนคำสั่งซื้อของร้านตัวเองที่อยู่ในสถานะ `จ่ายแล้ว` เป็นตัวเลข "รอจัดของ" ที่กดแล้วไปหน้ารายการคำสั่งซื้อที่กรอง `จ่ายแล้ว`

กรณีปกติ

- Given ร้าน "สมชายเสื้อผ้า" มีคำสั่งซื้อ `จ่ายแล้ว` 5 รายการ เวลา 09:00
- When สมชายเข้าหน้าหลังบ้านของร้าน แล้วกดตัวเลข "รอจัดของ 5"
- Then สมชายไปถึงหน้ารายการคำสั่งซื้อที่กรอง `จ่ายแล้ว` และเห็น 5 รายการ

กรณีผิดพลาด

- Given ร้าน "สมชายเสื้อผ้า" ไม่มีคำสั่งซื้อ `จ่ายแล้ว` เลย (0 รายการ) เวลา 09:00
- When สมชายเข้าหน้าหลังบ้านของร้าน
- Then สมชายเห็น "รอจัดของ 0" ไม่ใช่ช่องว่างหรือข้อความแจ้งข้อผิดพลาด และถ้าระบบนับจำนวนไม่ได้ สมชายเห็นเครื่องหมาย "–" แทนตัวเลข โดยส่วนอื่นของหน้ายังใช้งานได้

### ORD-005 แสดงสินค้าและยอดเงินในหน้ารายละเอียด

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายเปิดคำสั่งซื้อของร้านตัวเอง THE SYSTEM SHALL แสดงเลขคำสั่งซื้อ เวลาสั่งซื้อ สถานะคำสั่งซื้อ รายการสินค้าพร้อมรูปปก ชื่อ แบบย่อย ราคาต่อชิ้น จำนวน และยอดของแต่ละรายการตามสำเนาที่คำสั่งซื้อเก็บไว้ตอนสั่งซื้อ (ดู CHK-005) รวมถึงยอดรวมสินค้า ค่าส่ง และยอดรวมทั้งหมด

กรณีปกติ

- Given สมหญิงสั่ง "เสื้อยืดคอกลม" แบบย่อย สีดำ ขนาด L ราคา 250 บาท จำนวน 2 ชิ้น จากร้าน "สมชายเสื้อผ้า" เมื่อ 2026-11-24 เวลา 08:52 เป็นคำสั่งซื้อเลข `2611240045`
- When สมชายเปิดคำสั่งซื้อนี้เวลา 09:05
- Then สมชายเห็น "เสื้อยืดคอกลม สีดำ ขนาด L" พร้อมรูปปก "฿250 × 2" และยอดของรายการ "฿500" ยอดรวมสินค้า 500 บาท ค่าส่ง 40 บาท ยอดรวมทั้งหมด 540 บาท และเวลาสั่งซื้อ "24/11/2026 08:52" หัวเรื่องของหน้าคือสถานะ `จ่ายแล้ว` และเลขคำสั่งซื้ออยู่บรรทัดใต้หัวเรื่อง

กรณีผิดพลาด (ข้อมูลสินค้าเปลี่ยนหลังสั่งซื้อ)

- Given คำสั่งซื้อเลข `2611240045` ข้างบน และเวลา 09:30 สมชายแก้ราคา "เสื้อยืดคอกลม" เป็น 300 บาท แล้วเวลา 09:40 ลบค่าตัวเลือก L ออกจากตัวเลือก ขนาด ทำให้แบบย่อย สีดำ ขนาด L หายจากสินค้า
- When สมชายเปิดคำสั่งซื้อนี้เวลา 09:45
- Then สมชายยังเห็น "เสื้อยืดคอกลม สีดำ ขนาด L" "฿250 × 2" "฿500" และยอดรวมทั้งหมด 540 บาท เหมือนตอนสั่งซื้อ

### ORD-006 แสดงที่อยู่จัดส่งและผู้รับ

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายเปิดคำสั่งซื้อของร้านตัวเอง THE SYSTEM SHALL แสดงชื่อผู้รับ เบอร์โทรผู้รับ และที่อยู่จัดส่งตามสำเนาที่คำสั่งซื้อเก็บไว้ตอนสั่งซื้อ (ดู CHK-005) โดยไม่แสดงอีเมลหรือข้อมูลบัญชีอื่นของผู้ซื้อ

กรณีปกติ

- Given คำสั่งซื้อเลข `2611240045` ยอด 540 บาท สมหญิงเลือกผู้รับ "สมหญิง ใจดี" เบอร์ 081-234-5678 ที่อยู่ "99/1 ถนนสุขุมวิท แขวงคลองเตย เขตคลองเตย กรุงเทพฯ 10110" ตอนสั่งซื้อเวลา 08:52
- When สมชายเปิดคำสั่งซื้อนี้เวลา 09:05
- Then สมชายเห็นชื่อผู้รับ เบอร์โทร และที่อยู่ครบตามข้างบน และไม่เห็นอีเมลของสมหญิง

กรณีผิดพลาด (ผู้ซื้อแก้ที่อยู่ทีหลัง)

- Given คำสั่งซื้อเลข `2611240045` ข้างบน และเวลา 10:00 สมหญิงแก้ที่อยู่ที่บันทึกไว้ในบัญชีเป็นจังหวัดเชียงใหม่
- When สมชายเปิดคำสั่งซื้อนี้เวลา 10:05
- Then สมชายยังเห็นที่อยู่ "99/1 ถนนสุขุมวิท ... กรุงเทพฯ 10110" ซึ่งเป็นที่อยู่ตอนสั่งซื้อ ยอด 540 บาทเท่าเดิม

### ORD-007 แสดงผลการจ่ายเงิน

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายเปิดคำสั่งซื้อของร้านตัวเอง THE SYSTEM SHALL แสดงว่า "จ่ายแล้ว" พร้อมวิธีจ่ายและเวลาที่จ่าย เมื่อมีการจ่ายเงินที่เป็น `สำเร็จ` ครอบคลุมคำสั่งซื้อนั้น (ดู PAY-005) และแสดงว่า "ยังไม่จ่าย" ในกรณีอื่น โดยไม่แสดงเลขบัตรหรือข้อมูลการจ่ายเงินอื่นของผู้ซื้อ

กรณีปกติ

- Given สมหญิงจ่ายคำสั่งซื้อเลข `2611240045` ยอด 540 บาท ด้วย PromptPay สำเร็จเมื่อ 08:55
- When สมชายเปิดคำสั่งซื้อนี้เวลา 09:05
- Then สมชายเห็น "จ่ายแล้ว PromptPay 24/11/2026 08:55" และสถานะคำสั่งซื้อ `จ่ายแล้ว`

กรณีผิดพลาด (ข้อมูลมาช้า)

- Given สมหญิงสั่งคำสั่งซื้อเลข `2611240046` ยอด 290 บาท เมื่อ 09:10 และกดจ่ายเมื่อ 09:12 แต่ผลการจ่ายเงินยังมาไม่ถึงระบบ (ดู PAY-004)
- When สมชายเปิดคำสั่งซื้อนี้เวลา 09:13
- Then สมชายเห็น "ยังไม่จ่าย" และสถานะ `รอจ่ายเงิน` ไม่มีปุ่มไปหน้าติดตามพัสดุ และเมื่อผลการจ่ายเงินมาถึงเวลา 09:14 หน้านี้เปลี่ยนเป็น "จ่ายแล้ว" ตาม ORD-011

### ORD-008 แสดงเลขติดตามพัสดุและสถานะการจัดส่ง

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายเปิดคำสั่งซื้อของร้านตัวเองที่มีพัสดุแล้ว THE SYSTEM SHALL แสดงเลขติดตามพัสดุ สถานะการจัดส่งล่าสุด และเวลาที่เปลี่ยนเป็นสถานะนั้น

กรณีปกติ

- Given คำสั่งซื้อเลข `2611240040` ยอด 790 บาท ของร้าน "สมชายเสื้อผ้า" มีพัสดุเลข `BS0000001234` ซึ่งเปลี่ยนเป็น `อยู่ระหว่างขนส่ง` เมื่อ 2026-11-24 เวลา 07:30
- When สมชายเปิดคำสั่งซื้อนี้เวลา 09:05
- Then สมชายเห็นเลขติดตามพัสดุ `BS0000001234` สถานะการจัดส่ง `อยู่ระหว่างขนส่ง` เวลา "24/11/2026 07:30" และสถานะคำสั่งซื้อ `กำลังจัดส่ง`

กรณีผิดพลาด (ยังไม่มีพัสดุ)

- Given คำสั่งซื้อเลข `2611240046` ยอด 290 บาท อยู่ที่ `รอจ่ายเงิน` จึงยังไม่มีพัสดุ เวลา 09:13
- When สมชายเปิดคำสั่งซื้อนี้
- Then ส่วนการจัดส่งแสดงข้อความ "ยังไม่มีพัสดุ จะมีเมื่อผู้ซื้อจ่ายเงินแล้ว" ไม่ใช่ช่องว่างหรือข้อความแจ้งข้อผิดพลาด

กรณีผิดพลาด (ข้อมูลมาไม่ครบ)

- Given คำสั่งซื้อเลข `2611240040` ยอด 790 บาท เวลา 09:05 และระบบอ่านข้อมูลพัสดุไม่ได้ชั่วคราว
- When สมชายเปิดคำสั่งซื้อนี้
- Then สมชายยังเห็นสินค้า ยอดเงิน ที่อยู่จัดส่ง และผลการจ่ายเงินครบ ส่วนการจัดส่งแสดง "โหลดข้อมูลการจัดส่งไม่ได้" พร้อมปุ่ม "ลองใหม่" และไม่แสดงสถานะการจัดส่งที่ไม่แน่ใจว่าถูก

### ORD-009 ไปหน้าติดตามพัสดุจากคำสั่งซื้อ

- ลำดับความสำคัญ: ต้องมี
- WHEN ผู้ขายกดปุ่ม "จัดส่ง" ที่คำสั่งซื้อของร้านตัวเองซึ่งอยู่ในสถานะ `จ่ายแล้ว` THE SYSTEM SHALL พาผู้ขายไปหน้าติดตามพัสดุของพัสดุในคำสั่งซื้อนั้น (ดู DLV-010) โดยการกดปุ่มนี้ไม่เปลี่ยนสถานะใด

กรณีปกติ

- Given คำสั่งซื้อเลข `2611240045` ยอด 540 บาท สถานะ `จ่ายแล้ว` พัสดุเลข `BS0000001250` อยู่ที่ `รอร้านจัดของ` เวลา 09:05
- When สมชายกดปุ่ม "จัดส่ง" จากหน้ารายการ หรือจากหน้ารายละเอียด
- Then สมชายไปถึงหน้าติดตามพัสดุของพัสดุ `BS0000001250` (ดู DLV-010) สถานะคำสั่งซื้อยังเป็น `จ่ายแล้ว` และพัสดุยังเป็น `รอร้านจัดของ` จนกว่าสมชายจะเปลี่ยนตาม DLV-004

กรณีผิดพลาด (สองคนทำพร้อมกัน)

- Given สมชายเปิดหน้ารายละเอียดคำสั่งซื้อเลข `2611240045` ยอด 540 บาท ค้างไว้ตั้งแต่ 09:05 ตอนสถานะ `จ่ายแล้ว` แล้วเวลา 09:06 คำสั่งซื้อนี้ถูกยกเลิก (ดู RFD)
- When สมชายกดปุ่ม "จัดส่ง" เวลา 09:06 ก่อนที่หน้าจะอัปเดตเอง
- Then สมชายไม่ถูกพาไปหน้าติดตามพัสดุ เห็นข้อความ "คำสั่งซื้อนี้ถูกยกเลิกแล้ว จัดส่งไม่ได้" หน้ารายละเอียดแสดงสถานะ `ยกเลิก` และปุ่ม "จัดส่ง" หายไป

กรณีผิดพลาด (สถานะอื่นไม่มีปุ่มจัดส่ง)

- Given คำสั่งซื้อเลข `2611240040` ยอด 790 บาท สถานะ `กำลังจัดส่ง` และเลข `2611240046` ยอด 290 บาท สถานะ `รอจ่ายเงิน` เวลา 09:13
- When สมชายเปิดคำสั่งซื้อทั้งสองรายการ
- Then รายการ `กำลังจัดส่ง` ไม่มีปุ่ม "จัดส่ง" แต่มีลิงก์ "ดูการจัดส่ง" ไปหน้าติดตามพัสดุ (ดู DLV-010) ส่วนรายการ `รอจ่ายเงิน` ไม่มีทั้งปุ่มและลิงก์

### ORD-010 แจ้งคำสั่งซื้อใหม่ขณะเปิดหน้ารายการ

- ลำดับความสำคัญ: ต้องมี
- WHEN มีคำสั่งซื้อใหม่ของร้านเข้ามาขณะที่ผู้ขายเปิดหน้ารายการคำสั่งซื้อค้างไว้ THE SYSTEM SHALL แสดงแถบ "มีคำสั่งซื้อใหม่ N รายการ กดเพื่อแสดง" และอัปเดตจำนวนที่ตัวกรองกับตัวเลข "รอจัดของ" ภายใน 30 วินาที โดยไม่เลื่อนหรือแทรกรายการที่ผู้ขายกำลังดูอยู่เอง

กรณีปกติ

- Given สมชายเปิดหน้ารายการคำสั่งซื้อค้างไว้ตั้งแต่ 09:00 ตัวกรอง `ทั้งหมด` 45 รายการ "รอจัดของ 5" แล้วเวลา 09:20:00 สมหญิงสั่งซื้อและจ่ายเงินคำสั่งซื้อใหม่ยอด 540 บาท สำเร็จ
- When เวลาผ่านไปถึง 09:20:30 โดยสมชายไม่ได้กดอะไร
- Then สมชายเห็นแถบ "มีคำสั่งซื้อใหม่ 1 รายการ กดเพื่อแสดง" ตัวกรอง `ทั้งหมด` เป็น 46 "รอจัดของ" เป็น 6 รายการที่สมชายกำลังดูอยู่ไม่ขยับ และเมื่อสมชายกดแถบ คำสั่งซื้อใหม่ขึ้นเป็นรายการบนสุด

กรณีผิดพลาด (เชื่อมต่อขาดช่วง)

- Given สมชายเปิดหน้ารายการค้างไว้ตั้งแต่ 09:00 แล้วอินเทอร์เน็ตของสมชายหลุดตั้งแต่ 09:19 ถึง 09:25 ระหว่างนั้นมีคำสั่งซื้อใหม่เข้ามา 2 รายการ
- When อินเทอร์เน็ตกลับมาเวลา 09:25
- Then ระหว่างที่หลุด สมชายเห็นข้อความ "อัปเดตข้อมูลไม่ได้ ข้อมูลที่เห็นเป็นของเวลา 09:18" โดยรายการเดิมยังอ่านได้ และภายใน 30 วินาทีหลังอินเทอร์เน็ตกลับมา สมชายเห็นแถบ "มีคำสั่งซื้อใหม่ 2 รายการ กดเพื่อแสดง" ครั้งเดียว ไม่นับซ้ำ

### ORD-011 อัปเดตเมื่อคำสั่งซื้อเปลี่ยนสถานะขณะเปิดดู

- ลำดับความสำคัญ: ต้องมี
- WHEN คำสั่งซื้อที่ผู้ขายกำลังเปิดดูในหน้ารายการหรือหน้ารายละเอียดเปลี่ยนสถานะคำสั่งซื้อ ผลการจ่ายเงิน หรือสถานะการจัดส่ง THE SYSTEM SHALL แสดงสถานะใหม่และปรับปุ่มให้ตรงกับสถานะใหม่ภายใน 30 วินาที โดยผู้ขายไม่ต้องโหลดหน้าใหม่เอง

กรณีปกติ

- Given สมชายเปิดหน้ารายละเอียดคำสั่งซื้อเลข `2611240046` ยอด 290 บาท ค้างไว้ตั้งแต่ 09:13 ตอนสถานะ `รอจ่ายเงิน` แล้วผลการจ่ายเงินของสมหญิงมาถึงเวลา 09:14:00
- When เวลาผ่านไปถึง 09:14:30
- Then หน้ารายละเอียดแสดงสถานะ `จ่ายแล้ว` ผลการจ่ายเงิน "จ่ายแล้ว" เลขติดตามพัสดุ สถานะการจัดส่ง `รอร้านจัดของ` และมีปุ่ม "จัดส่ง" ขึ้นมา

กรณีผิดพลาด (ถูกยกเลิกขณะเปิดดู)

- Given สมชายเปิดหน้ารายละเอียดคำสั่งซื้อเลข `2611240047` ยอด 420 บาท ที่สมหญิงสั่งเมื่อ 09:00 ค้างไว้ตั้งแต่ 09:25 ตอนสถานะ `รอจ่ายเงิน` และสมหญิงไม่จ่ายเงินจนครบ 30 นาทีเวลา 09:30:00 ระบบจึงยกเลิกคำสั่งซื้อ (ดู CHK-008)
- When เวลาผ่านไปถึง 09:30:30
- Then สมชายเห็นข้อความ "คำสั่งซื้อนี้ถูกยกเลิกแล้ว" สถานะเปลี่ยนเป็น `ยกเลิก` ข้อมูลสินค้า ยอดเงิน และที่อยู่ยังอ่านได้ครบ ไม่มีปุ่ม "จัดส่ง" และจำนวนที่ตัวกรอง `รอจ่ายเงิน` ลดลง 1 `ยกเลิก` เพิ่มขึ้น 1

### ORD-012 กันการเปิดคำสั่งซื้อของร้านอื่น

- ลำดับความสำคัญ: ต้องมี
- IF ผู้ขายพยายามเปิดคำสั่งซื้อที่ไม่ใช่ของร้านตัวเอง หรือคำสั่งซื้อที่ไม่มีอยู่จริง THEN THE SYSTEM SHALL แสดงหน้า "ไม่พบคำสั่งซื้อ" แบบเดียวกันทั้งสองกรณี โดยไม่เปิดเผยข้อมูลใดของคำสั่งซื้อนั้น

กรณีปกติ

- Given คำสั่งซื้อเลข `2611240045` ยอด 540 บาท เป็นของร้าน "สมชายเสื้อผ้า" เวลา 11:00
- When สมชายเปิดลิงก์ของคำสั่งซื้อนี้ที่บันทึกไว้
- Then สมชายเห็นหน้ารายละเอียดของคำสั่งซื้อเลข `2611240045` ตามปกติ

กรณีผิดพลาด

- Given คำสั่งซื้อเลข `2611240045` ยอด 540 บาท เป็นของร้าน "สมชายเสื้อผ้า" และวิชัยเข้าสู่ระบบอยู่ในฐานะเจ้าของร้าน "วิชัยรองเท้า" เวลา 11:00
- When วิชัยเปิดลิงก์ของคำสั่งซื้อเลข `2611240045` โดยแก้เลขในลิงก์เอง
- Then วิชัยเห็นหน้า "ไม่พบคำสั่งซื้อ" พร้อมปุ่มกลับไปหน้ารายการของร้านตัวเอง ไม่เห็นสินค้า ยอดเงิน ชื่อผู้รับ ที่อยู่ หรือสถานะของคำสั่งซื้อนั้น และหน้าที่เห็นเหมือนกับตอนเปิดเลข `9999999999` ที่ไม่มีอยู่จริงทุกตัวอักษร

### ORD-013 กันคนที่ไม่ใช่ผู้ขายเข้าหน้าคำสั่งซื้อของร้าน

- ลำดับความสำคัญ: ต้องมี
- IF คนที่ยังไม่เข้าสู่ระบบ หรือบัญชีที่ยังไม่มีร้าน พยายามเปิดหน้าใดของ ORD THEN THE SYSTEM SHALL ไม่แสดงข้อมูลคำสั่งซื้อใดเลย และพาคนที่ยังไม่เข้าสู่ระบบไปหน้าเข้าสู่ระบบ (ดู ACC-008) หรือพาบัญชีที่ยังไม่มีร้านไปหน้าเปิดร้าน (ดู SHP-001)

กรณีปกติ

- Given สมชายยังไม่ได้เข้าสู่ระบบ และมีลิงก์หน้ารายละเอียดคำสั่งซื้อเลข `2611240045` ยอด 540 บาท เวลา 11:10
- When สมชายเปิดลิงก์นั้น แล้วเข้าสู่ระบบสำเร็จ
- Then สมชายถูกพาไปหน้าเข้าสู่ระบบก่อน และหลังเข้าสู่ระบบแล้วไปถึงหน้ารายละเอียดของคำสั่งซื้อเลข `2611240045`

กรณีผิดพลาด

- Given สมหญิงเข้าสู่ระบบอยู่ บัญชีของสมหญิงยังไม่มีร้าน (0 ร้าน) เวลา 11:15
- When สมหญิงเปิดลิงก์หน้ารายการคำสั่งซื้อของร้าน
- Then สมหญิงถูกพาไปหน้าเปิดร้าน ไม่เห็นรายการ จำนวน หรือตัวกรองคำสั่งซื้อใดเลย

### ORD-014 แสดงสถานะกำลังโหลดและโหลดไม่สำเร็จ

- ลำดับความสำคัญ: ต้องมี
- IF หน้ารายการหรือหน้ารายละเอียดคำสั่งซื้อยังโหลดข้อมูลไม่เสร็จ หรือโหลดไม่สำเร็จภายใน 10 วินาที THEN THE SYSTEM SHALL แสดงเครื่องหมายกำลังโหลดระหว่างรอ และเมื่อโหลดไม่สำเร็จให้แสดงข้อความ "โหลดคำสั่งซื้อไม่ได้ตอนนี้" พร้อมปุ่ม "ลองใหม่" โดยไม่แสดงหน้าว่างหรือข้อความว่าไม่มีคำสั่งซื้อ

กรณีปกติ

- Given ร้าน "สมชายเสื้อผ้า" มีคำสั่งซื้อ 45 รายการ เวลา 09:00 และอินเทอร์เน็ตของสมชายช้า
- When สมชายเปิดหน้ารายการคำสั่งซื้อ และข้อมูลมาถึงหลังผ่านไป 4 วินาที
- Then ระหว่าง 4 วินาทีนั้นสมชายเห็นเครื่องหมายกำลังโหลดในตำแหน่งของรายการ ไม่เห็นข้อความ "ร้านยังไม่มีคำสั่งซื้อ" และเมื่อข้อมูลมาถึงเห็น 20 รายการแรก

กรณีผิดพลาด

- Given ร้าน "สมชายเสื้อผ้า" มีคำสั่งซื้อ 45 รายการ เวลา 09:00 และระบบตอบไม่ได้ชั่วคราว
- When สมชายเปิดหน้ารายละเอียดคำสั่งซื้อเลข `2611240045` และผ่านไป 10 วินาทีโดยยังไม่ได้ข้อมูล
- Then สมชายเห็นข้อความ "โหลดคำสั่งซื้อไม่ได้ตอนนี้" พร้อมปุ่ม "ลองใหม่" ตัวกรองและคำค้นที่เลือกไว้ยังอยู่ และเมื่อกด "ลองใหม่" เวลา 09:01 ตอนที่ระบบกลับมาแล้ว สมชายเห็นรายละเอียดคำสั่งซื้อครบ

กรณีผิดพลาด (ยกเลิกกลางทาง)

- Given สมชายกดตัวกรอง `สำเร็จ` (26 รายการ) เวลา 09:02 และข้อมูลยังโหลดไม่เสร็จ
- When สมชายกดตัวกรอง `จ่ายแล้ว` (5 รายการ) ทันทีก่อนผลของตัวกรองแรกมาถึง
- Then สมชายเห็นเฉพาะ 5 รายการของ `จ่ายแล้ว` ผลของตัวกรอง `สำเร็จ` ที่มาถึงทีหลังไม่ถูกแสดงทับ

### ORD-015 ผู้ขายเปลี่ยนสถานะคำสั่งซื้อเองไม่ได้

- ลำดับความสำคัญ: ต้องมี
- THE SYSTEM SHALL ไม่มีปุ่มหรือช่องทางใดในหน้าของ ORD ให้ผู้ขายเปลี่ยนสถานะคำสั่งซื้อ แก้สินค้า แก้ยอดเงิน หรือแก้ที่อยู่จัดส่งของคำสั่งซื้อ และปฏิเสธคำขอเปลี่ยนสถานะคำสั่งซื้อโดยตรงทุกคำขอ

กรณีปกติ

- Given คำสั่งซื้อเลข `2611240045` ยอด 540 บาท สถานะ `จ่ายแล้ว` เวลา 09:05
- When สมชายเปิดหน้ารายละเอียดคำสั่งซื้อนี้
- Then สิ่งเดียวที่สมชายกดได้เกี่ยวกับคำสั่งซื้อนี้คือปุ่ม "จัดส่ง" และปุ่มกลับไปหน้ารายการ ไม่มีปุ่มเปลี่ยนสถานะ ไม่มีปุ่มยกเลิก และไม่มีช่องแก้ข้อมูล

กรณีผิดพลาด

- Given คำสั่งซื้อเลข `2611240046` ยอด 290 บาท สถานะ `รอจ่ายเงิน` เวลา 09:13
- When สมชายส่งคำขอเปลี่ยนสถานะคำสั่งซื้อนี้เป็น `จ่ายแล้ว` ตรงเข้าระบบโดยไม่ผ่านหน้าเว็บ
- Then ระบบปฏิเสธคำขอ คำสั่งซื้อยังเป็น `รอจ่ายเงิน` ผลการจ่ายเงินยังเป็น "ยังไม่จ่าย" และไม่มีพัสดุถูกสร้าง

## 5. ข้อมูลและสถานะ

ORD ไม่สร้างและไม่แก้ข้อมูลใด ข้อมูลทั้งหมดเป็นของ feature อื่น ORD อ่านมาแสดงเท่านั้น

| ข้อมูล | ใช้ทำอะไร | เก็บนานแค่ไหน |
|---|---|---|
| คำสั่งซื้อ: เลข เวลาสั่งซื้อ สถานะ ร้านเจ้าของ (จาก CHK) | แสดงในรายการ กรอง ค้นหา และตรวจว่าเป็นของร้านไหน | ตลอด ระบบไม่ลบเอง |
| สินค้าในคำสั่งซื้อ: รูปปก ชื่อ แบบย่อย ราคาต่อชิ้น จำนวน ตามตอนสั่งซื้อ (จาก CHK) | แสดงในหน้ารายละเอียด | ตลอด |
| ยอดเงิน: ยอดรวมสินค้า ค่าส่ง ยอดรวมทั้งหมด (จาก CHK) | แสดงในรายการและหน้ารายละเอียด | ตลอด |
| ผู้รับ: ชื่อ เบอร์โทร ที่อยู่จัดส่ง ตามตอนสั่งซื้อ (จาก CHK) | ให้ผู้ขายรู้ว่าต้องส่งให้ใคร ที่ไหน | ตลอด |
| การจ่ายเงิน: จ่ายแล้วหรือยัง วิธีจ่าย เวลาที่จ่าย (จาก PAY) | แสดงในหน้ารายละเอียด | ตลอด |
| พัสดุ: เลขติดตามพัสดุ สถานะการจัดส่งล่าสุด เวลาที่เปลี่ยน (จาก DLV) | แสดงในหน้ารายละเอียด และลิงก์ไป DLV | ตลอด |
| ตัวกรองและคำค้นที่ผู้ขายเลือกไว้ | คงหน้าเดิมไว้เมื่อโหลดใหม่หรือกลับจากหน้ารายละเอียด | เฉพาะช่วงที่ผู้ขายยังเปิดหน้าอยู่ |

สถานะคำสั่งซื้อที่ ORD แสดง เหตุการณ์ทุกข้อเป็นของ feature อื่น ไม่มีเหตุการณ์ใดเกิดจาก ORD

| จากสถานะ | เหตุการณ์ | ไปสถานะ |
|---|---|---|
| `รอจ่ายเงิน` | ผู้ซื้อจ่ายเงินสำเร็จ (PAY) | `จ่ายแล้ว` |
| `รอจ่ายเงิน` | ไม่จ่ายภายใน 30 นาที หรือผู้ซื้อยกเลิกเอง (CHK) | `ยกเลิก` |
| `จ่ายแล้ว` | พัสดุเปลี่ยนเป็น `ร้านส่งของแล้ว` (DLV) | `กำลังจัดส่ง` |
| `จ่ายแล้ว` | ยกเลิกหลังจ่ายเงิน (RFD) | `ยกเลิก` |
| `กำลังจัดส่ง` | ผู้ซื้อกด "ได้รับสินค้าแล้ว" หรือครบ 7 วันหลังพัสดุเป็น `ส่งสำเร็จ` (DLV) | `สำเร็จ` |
| `กำลังจัดส่ง` | พัสดุเป็น `ส่งไม่สำเร็จ` (DLV) | `ยกเลิก` |

## 8. สมมติฐาน คำถามค้าง และบันทึก

### สมมติฐาน

- agent ตัดสินใจ: รายการคำสั่งซื้อเรียงตามเวลาสั่งซื้อจากใหม่ไปเก่า หน้าละ 20 รายการ ไม่มีการเรียงแบบอื่น (2026-11-24)
- agent ตัดสินใจ: หน้ารายการเปิดมาที่ตัวกรอง `ทั้งหมด` และผู้ขายเห็นคำสั่งซื้อ `รอจ่ายเงิน` ของร้านตัวเองด้วย (2026-11-24)
- agent ตัดสินใจ: การค้นหาใช้เลขคำสั่งซื้อเท่านั้น ค้นได้ทั้งเลขเต็มและบางส่วนอย่างน้อย 3 ตัวอักษร และค้นข้ามทุกสถานะโดยไม่สนตัวกรองที่เลือกอยู่ (2026-11-24)
- agent ตัดสินใจ: "รอจัดของ" นับจากคำสั่งซื้อที่อยู่ในสถานะ `จ่ายแล้ว` เพราะคำสั่งซื้อ `จ่ายแล้ว` ทุกรายการมีพัสดุที่ `รอร้านจัดของ` (2026-11-24)
- agent ตัดสินใจ: หน้าที่เปิดค้างไว้อัปเดตเองภายใน 30 วินาที คำสั่งซื้อใหม่แสดงเป็นแถบให้กดก่อน ไม่แทรกเข้ารายการเอง (2026-11-24)
- agent ตัดสินใจ: คำสั่งซื้อของร้านอื่นกับคำสั่งซื้อที่ไม่มีอยู่จริง แสดงหน้า "ไม่พบคำสั่งซื้อ" แบบเดียวกัน เพื่อไม่ให้เดาได้ว่าเลขไหนมีอยู่ (2026-11-24)
- agent ตัดสินใจ: ผู้ขายเห็นชื่อผู้รับ เบอร์โทร และที่อยู่จัดส่ง แต่ไม่เห็นอีเมล เลขบัตร หรือข้อมูลบัญชีอื่นของผู้ซื้อ (2026-11-24)
