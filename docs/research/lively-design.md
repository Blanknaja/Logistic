# ทำให้ Blanksong มีชีวิต: งานวิจัยและทิศทางหน้าตารอบ 3

วันที่ดู: 26 พ.ย. 2026

เจ้าของโปรเจคไม่รับหน้าตารอบ 2 (พื้นขาว สีเขียวสีเดียว ไม่มีเงา แทบไม่มีอะไรขยับ) และขอให้เว็บ "มีชีวิต น่าใช้" โดยดูตัวอย่างจาก Apple, three.js, Dribbble, GSAP และ Motion เป้าเดิมยังอยู่ครบ: อ่านง่าย ผู้ใช้ได้ข้อมูลที่มาหา และใช้ได้บนจอกว้าง 360 จุด

เอกสารนี้เป็นงานวิจัยกับข้อเสนอ ยังไม่มีการแก้โค้ด

## วิธีเก็บข้อมูลและข้อจำกัด

- ภาพของเรา: เปิดภาพใน `docs/screenshots/design/` ทีละหน้า ทั้งจอ 1440 และ 390 (หน้าแรก ผลค้นหา หน้าสินค้า ตะกร้า หน้าสั่งซื้อ หน้าจ่ายเงิน คำสั่งซื้อ ติดตามพัสดุ หลังบ้านร้าน)
- เว็บอ้างอิง: ดึงหน้าเว็บจริงมาอ่าน หน้าของ Apple ดึงทั้ง HTML และไฟล์ CSS แล้วนับของที่อยู่ในไฟล์ **ไม่ได้เปิดดูการขยับในเบราว์เซอร์จริง** ทุกข้อที่เขียนว่า Apple "ทำ" จึงหมายถึง "มีในโค้ดที่เซิร์ฟเวอร์ส่งมา"
- ขนาดไลบรารี: ตัวเลข "gzip" มาจาก bundlephobia หรือจากการดาวน์โหลดไฟล์ `.min.js` จาก jsDelivr แล้วบีบด้วย gzip เอง (บอกไว้ในตาราง)
- Next.js กับ React: อ่านเอกสารที่ติดมากับรุ่นที่ติดตั้งใน repo (`node_modules/next/dist/docs/`) และเช็คว่า React 19.3.0 ที่ติดตั้งมี `ViewTransition` กับ `addTransitionType` ให้ใช้จริง
- หน้าที่ดึงไม่ได้หรือได้ไม่ครบ อยู่ในส่วน "ยังไม่ได้ยืนยัน" ท้ายเอกสาร

## (a) ทำไมหน้าตาตอนนี้ดูไม่มีชีวิต

### ปัญหาที่เจอทุกหน้า

1. **ไม่มีอะไรบอกว่าเว็บนี้คือใคร** ทุกหน้าเริ่มด้วยแถบขาว โลโก้ตัวหนังสือ แล้วเข้าเนื้อหาเลย ไม่มีสี ภาพ หรือประโยคที่เป็นของ Blanksong เอาโลโก้ออกแล้วจะเป็นเว็บของใครก็ได้
2. **สีมีแค่ขาว เทา และเขียวเข้ม 1 จุด** สีเขียว `#24543f` เข้มและหม่น ใช้กับปุ่มเดียวต่อหน้า ที่เหลือเป็นตัวหนังสือดำบนพื้นขาว ทั้งหน้าจึงดูเหมือนเอกสาร
3. **ทุกอย่างแบนและขอบคม** ไม่มีเงา ไม่มีชั้น รูปไม่มีมุมโค้ง ของที่กดได้กับของที่อ่านเฉยๆ หน้าตาเหมือนกัน ตาไม่รู้ว่าควรมองตรงไหนก่อน
4. **ขนาดตัวหนังสือแคบ** มี 4 ขนาด (14 16 20/24 28/40) หัวเรื่องใหญ่สุด 40px ไม่มีตัวไหนที่ "พูดเสียงดัง" ได้เลย
5. **ครึ่งจอว่างเปล่า** บนจอ 1440 หลายหน้ามีเนื้อหาแค่ 1 ใน 3 ของจอ ที่เหลือเป็นพื้นขาวล้วน (หน้าตะกร้า หลังบ้านร้าน หน้าเปลี่ยนสถานะพัสดุ หน้าคำสั่งซื้อ) ที่ว่างนี้ไม่ได้ตั้งใจ มันดูเหมือนหน้ายังทำไม่เสร็จ
6. **รูปสำรองทำให้เว็บดูพัง** สินค้าที่ไม่มีรูปได้รูปวงกลมกับขีดบนพื้นสีอ่อน ซึ่งหน้าตาเหมือนรูปคนที่ยังไม่ตั้งรูปโปรไฟล์ ในหน้าแรก 20 ใบแรกมี 5 ใบเป็นรูปนี้
7. **ไม่มีอะไรตอบเมื่อผู้ใช้ทำอะไร** ทั้งแอปมี `transition` 15 จุดใน CSS เกือบทั้งหมดคือการเปลี่ยนสีขอบ สีพื้น หรือเส้นใต้ 0.2 วินาที กับ `@keyframes` ตัวเดียวคือโครงสีระหว่างโหลด กดใส่ตะกร้าแล้วเลขตะกร้าเปลี่ยนเฉยๆ เปลี่ยนหน้าแล้วหน้าเก่าหายหน้าใหม่โผล่ สถานะพัสดุเปลี่ยนแล้วไม่มีอะไรบอก

### สรุปสาเหตุ

รอบ 2 แก้เรื่อง "ข้อมูลรกและหาไม่เจอ" ได้ดี และข้อนั้นควรเก็บไว้ แต่กฎที่ใช้แก้คือ "เอาออก" ทุกอย่าง: เอาสีออก เอาเงาออก เอากรอบออก เอาการขยับออก ผลคือหน้าที่ถูกต้องแต่ไม่มีอารมณ์ รอบ 2 ลอกหน้าร้านของ Apple (หน้าซื้อของ) ซึ่งตั้งใจให้เงียบ แต่ไม่ได้ลอกหน้าแนะนำสินค้าของ Apple ซึ่งเป็นส่วนที่คนจำได้ (ดูข้อ b)

## (b) เว็บอ้างอิงทำอะไร และเราควรยืมอะไร

### Apple หน้าแนะนำสินค้า

ที่มา: [apple.com/iphone-18-pro](https://www.apple.com/iphone-18-pro/) [apple.com/airpods-pro](https://www.apple.com/airpods-pro/) [apple.com/macbook-air](https://www.apple.com/macbook-air/) และไฟล์ CSS ของหน้า iPhone 18 Pro ที่ `https://www.apple.com/v/iphone-18-pro/e/built/styles/overview.built.css` (นับจากไฟล์ที่ดึงมา)

| สิ่งที่พบในโค้ด | ตัวเลข | เรายืมอะไร |
|---|---|---|
| หน้าแบ่งเป็น "ฉาก" ที่ผูกกับการเลื่อน | `data-anim-scroll-group` 24 จุด ชื่อเช่น "Media Hero" "Highlights" "Product Viewer" "Battery" | หน้าแรกและหน้าสินค้าเล่าเป็นฉากสั้นๆ ไม่ใช่ตารางยาวอย่างเดียว |
| ของที่ค้างบนจอระหว่างเลื่อน | `position:sticky` 8 จุดใน CSS | กล่องซื้อและกล่องสรุปยอดค้างข้างจอ รูปค้างขณะข้อความเลื่อน |
| หัวเรื่องใหญ่มาก | มีขนาด 96, 89, 80, 64, 56, 48px | เพิ่มขนาด "ตัวโชว์" สำหรับประโยคเดียวต่อฉาก |
| ไม่ได้แบน | `box-shadow` 36 จุด `linear-gradient` 23 จุด `backdrop-filter` 52 จุด | เลิกกฎ "ไม่มีเงา ไม่มี gradient" ใช้เงาบอกชั้นและบอกว่ากดได้ |
| มุมโค้งใหญ่และปุ่มเม็ดยา | `border-radius: 28px` 9 จุด `999px` 14 จุด | การ์ดมุม 16 ถึง 24px chip เป็นเม็ดยา |
| ส่วนพื้นเข้มสลับพื้นอ่อน | `section` 17 จาก 26 ส่วนมี class `theme-dark` | มีแถบพื้นเข้มหนึ่งแถบต่อหน้ายาวเพื่อสร้างจังหวะ |
| มีจังหวะเด้ง | `cubic-bezier(0.34,2.16,0.64,1)` และ `cubic-bezier(0.3,2,0.5,1)` (ค่าตัวที่สองเกิน 1 คือเลยเป้าแล้วกลับ) | ของที่ตอบการกดเด้งเล็กน้อยได้ งานวิจัยรอบก่อนสรุปว่า "ไม่มีอะไรเด้ง" จากหน้าร้านอย่างเดียว ซึ่งไม่ครบ |
| ค่าที่ใช้บ่อย | `opacity 400ms ease-in-out` (8 จุด) `opacity 100ms linear, transform .2s ease` (7 จุด) | ของกดบ่อยตอบใน 100 ถึง 200ms ของที่โผล่ใช้ 400ms |
| วิดีโอมีปุ่มหยุดเสมอ | `<video` 13 ตัว ปุ่ม `play-pause-button` พร้อม `aria-label` เช่น "Play Highlights Gallery" | ของที่ขยับเองนานกว่า 5 วินาทีต้องมีปุ่มหยุด |

| แกลเลอรีเลื่อนซ้ายขวาแบบดูดเข้าที่ | `scroll-snap-type` 3 จุด | ชั้นวางสินค้าแบบเลื่อนข้างด้วย CSS ล้วน |

หน้า [apple.com/iphone](https://www.apple.com/iphone/) เรียงเป็น: หัวเรื่อง แถบเลือกรุ่น แกลเลอรีเด่น 2 สไลด์ "Explore the lineup" (การ์ดรุ่น) การ์ดเหตุผลที่ควรซื้อ แล้วของที่ใช้ร่วมกัน คือ **ของเด่นก่อน ตารางทีหลัง**

สิ่งที่ไม่ลอก: ฟอนต์ สีน้ำเงิน ถ้อยคำ และหน้าที่ยาวหลายหมื่นจุดต่อสินค้าหนึ่งตัว (เหตุผลเดิมใน `docs/research/apple-store-design.md` ข้อ 1.8 ยังใช้ได้ เรามีสินค้าหลักพันและรูปมาจากผู้ขาย)

### ความรู้สึก

Blanksong ควรรู้สึกเหมือนเดินเข้าตลาดเช้าที่จัดร้านเรียบร้อย: พื้นอุ่นแบบกระดาษ ของแต่ละแผงมีสีของตัวเอง ของสดวางเด่นอยู่หน้าแผง หยิบอะไรก็มีการตอบรับ และของที่ซื้อแล้ว "ออกเดินทาง" ให้เห็นจริงๆ ความมีชีวิตมาจากสามอย่างตามลำดับ: **สีและชั้นของพื้นผิว** (ทำให้หน้าไม่แบน) **จังหวะของหน้า** (ของเด่นก่อน ตารางทีหลัง ตัวหนังสือมีเสียงดังเบา) และ **การตอบสนอง** (ทุกการกระทำของผู้ใช้มีคำตอบที่มองเห็นภายใน 0.2 วินาที) การขยับเป็นภาษาสำหรับบอกว่า "เกิดอะไรขึ้น" ไม่ใช่ของประดับ ถ้าปิดการขยับทั้งหมด หน้าต้องยังดูอุ่นและมีจังหวะจากสีและตัวหนังสืออยู่ ส่วนเรื่องที่เป็นของ Blanksong คนเดียวคือ **พัสดุที่เดินทาง** ซึ่งใช้เป็นภาพประจำเว็บตั้งแต่หน้าแรกถึงหน้าติดตามพัสดุ

ฟอนต์: Noto Sans Thai Looped (ตัวมีหัว) อ่านง่ายในเนื้อหา จึงคงไว้ แต่ที่ขนาดใหญ่ดูเป็นทางการแบบเอกสาร เสนอให้ลองฟอนต์ไม่มีหัวหนึ่งตัวสำหรับ `--text-display` กับ `h1` เท่านั้น ตัวเลือกที่มีใน Google Fonts (เช็คแล้วว่าโหลดได้): [Anuphan](https://fonts.google.com/specimen/Anuphan) [Noto Sans Thai](https://fonts.google.com/noto/specimen/Noto+Sans+Thai) [IBM Plex Sans Thai](https://fonts.google.com/specimen/IBM+Plex+Sans+Thai) ตัวไหนดีที่สุด **ยังไม่ได้ยืนยัน** ต้องทำต้นแบบเทียบกัน ถ้าเทียบแล้วไม่ต่างชัด ให้ใช้ Noto Sans Thai Looped น้ำหนัก 700 ต่อ จะได้ไม่ต้องโหลดฟอนต์เพิ่ม

### รูป

- รูปในการ์ดยังเป็นสี่เหลี่ยมจัตุรัสแบบ `cover` (กฎเดิมดีอยู่) เพิ่มมุม `--radius-m` และวางในการ์ดพื้นขาวที่มี `--shadow-1`
- **รูปสำรองต้องเปลี่ยน** เลิกใช้วงกลมกับขีด ใช้พื้น `--tint-*` ตามหมวดกับไอคอนของหมวด (เสื้อ กระเป๋า หนังสือ ...) วาดด้วยเส้นสี `--color-ink` ผู้ใช้จะอ่านว่า "ยังไม่มีรูป" ไม่ใช่ "รูปพัง"
- รูปใหญ่ในหน้าสินค้าอยู่บนกรอบ `--color-surface-sunken` มุม `--radius-l` ชี้แล้วซูมตามตำแหน่งเมาส์บนจอที่มีเมาส์
- การ์ดสินค้าที่มีรูปที่สอง: ชี้แล้วค่อยๆ เปลี่ยนเป็นรูปที่สอง (บนจอที่มีเมาส์เท่านั้น)
- การ์ดหมวดในหน้าแรกเป็นรูปสินค้าตัวอย่างของหมวดบนพื้น `--tint-*` ไม่ใช่ chip ตัวหนังสือ
- รูปที่โหลดไม่ทันแสดงโครงสี `--color-surface-sunken` ขนาดเท่ารูปจริง แล้วรูปค่อยๆ ชัดขึ้นใน 240ms

### 3 มิติ: ที่ไหนคุ้ม ที่ไหนห้าม

| ที่ | ใช้ไหม | ทำอย่างไร |
|---|---|---|
| หน้าสินค้าที่ร้านอัปโหลดโมเดล | **ใช้ และยกให้เด่น** | ใช้ `<model-viewer>` ที่มีอยู่ เปลี่ยนจากปุ่มเล็กท้ายแถวรูปย่อ เป็นป้าย "หมุนดูได้ 3 มิติ" บนรูปใหญ่ เมื่อเปิดแล้วโมเดลหมุนเองช้าๆ หนึ่งรอบ (`auto-rotate`) แล้วหยุดรอให้ผู้ใช้หมุน |
| ส่วนต้อนรับของหน้าแรก | **ใช้ แบบมีเงื่อนไข** | สินค้าเด่นหนึ่งชิ้นที่มีโมเดล แสดงเป็นรูปนิ่งก่อน (รูปสินค้าปกติ) แล้วเปลี่ยนเป็น `<model-viewer>` ที่หมุนเองช้าๆ เมื่อสคริปต์พร้อม บนจอกว้าง 900 ขึ้นไป ไม่ประหยัดข้อมูล และผู้ใช้ไม่ได้ขอลดการขยับ จอเล็กใช้รูปนิ่ง ไม่มีสินค้าที่มีโมเดลก็ใช้รูปนิ่ง |
| เส้นทางพัสดุ (หน้าแรกและหน้าติดตาม) | **ไม่ใช้ 3 มิติจริง** | ใช้ภาพ 2 มิติที่ขยับ: กล่องพัสดุเดินตามเส้นประจากร้านถึงบ้าน วาดด้วย SVG กับ CSS เบากว่ามากและอ่านออกทันที บนแผนที่จริงใช้เส้นของ Leaflet ที่วาดตัวเองด้วย `stroke-dashoffset` |
| ตาราง การ์ดสินค้า ตะกร้า หน้าสั่งซื้อ หน้าจ่ายเงิน ฟอร์ม หลังบ้าน | **ห้าม** | หน้าเหล่านี้ผู้ใช้มาทำงานให้เสร็จ 3 มิติมีแต่ทำให้ช้า |
| พื้นหลังที่เป็นฉาก 3 มิติ อนุภาค หรือ shader | **ห้าม** | ไม่ได้ให้ข้อมูล และกินแบตบนมือถือ เอกสารของ fiber เตือนว่าการวาด 60 ครั้งต่อวินาทีตลอดเวลาเปลืองแบต ([ที่มา](https://r3f.docs.pmnd.rs/advanced/scaling-performance)) |

กฎของ 3 มิติทุกจุด: โหลดหลังจากหน้าแสดงแล้วเท่านั้น มีรูปนิ่งขนาดเท่ากันจองที่ไว้ก่อน หยุดหมุนเมื่อเลื่อนพ้นจอ และไม่เริ่มเองถ้าผู้ใช้ขอลดการขยับ

## (f) แผนทีละหน้า

### 5 อย่างที่เปลี่ยนความรู้สึกแรกมากที่สุด

1. **สีและพื้นผิวใหม่ทั้งแอป** พื้นกระดาษอุ่น การ์ดขาวมีเงาและมุมโค้ง เขียวสดขึ้น มีสีดอกดาวเรืองเป็นสีที่สอง ป้ายสถานะมีสี แก้ที่ token ใน `globals.css` ที่เดียว ทุกหน้าเปลี่ยนพร้อมกัน
2. **หน้าแรกมีส่วนต้อนรับและชั้นวาง** ประโยคเดียวตัวใหญ่ ช่องค้นหาใหญ่ สินค้าเด่นที่หมุนได้ การ์ดหมวดเป็นรูป ชั้น "มาใหม่" กับ "ร้านเด่น" ก่อนตารางทั้งหมด
3. **การ์ดสินค้าใหม่กับรูปสำรองใหม่** การ์ดยกตัวเมื่อชี้ รูปขยาย ราคาตัวหนา รูปสำรองเป็นไอคอนหมวดบนพื้นสี ของที่ดูพังหายไป
4. **การเปลี่ยนหน้าและการใส่ตะกร้าที่มองเห็น** รูปในการ์ดขยายเป็นรูปใหญ่ของหน้าสินค้า กดใส่ตะกร้าแล้วของลอยไปที่ตะกร้าและเลขเด้ง
5. **เส้นทางพัสดุที่มีชีวิต** เส้นบนแผนที่วาดตัวเอง จุดล่าสุดเต้น เส้นเวลาเติมสี และ "จ่ายเงินสำเร็จ" กับ "ส่งสำเร็จ" มีการฉลอง

### ทีละหน้า เรียงตามผล

**หน้าแรก**

1. ส่วนต้อนรับ: ประโยค `--text-display` หนึ่งประโยค ช่องค้นหาสูง 56px (ของเดิมในแถบบนยังอยู่) ด้านขวาบนจอกว้างเป็นสินค้าเด่นหนึ่งชิ้น (3 มิติเมื่อมีโมเดล) บนจอเล็กเป็นรูปนิ่งใต้ประโยค สูงไม่เกิน 45% ของจอ
2. แถวหมวดเป็นการ์ดรูปบนพื้น `--tint-*` เลื่อนข้างแบบดูดเข้าที่ แทน chip ตัวหนังสือ 12 อัน
3. ชั้นวางเลื่อนข้าง 2 ชั้น: "มาใหม่" และ "ร้านเด่น" (โลโก้ร้านกับสินค้า 3 ชิ้น)
4. แถบพื้น `--color-ink` หนึ่งแถบ: "ซื้อจากหลายร้าน ตามพัสดุได้ทุกชิ้น" กับภาพกล่องที่เดินตามเส้นประขณะเลื่อน
5. ตารางสินค้าทั้งหมดอยู่ท้าย การ์ดโผล่ทีละแถวเมื่อเข้าจอ
6. ชื่อร้านใต้การ์ดแสดงเฉพาะเมื่อต่างจากใบก่อนหน้า หรือย้ายเป็นป้ายเล็กมุมรูป (ต้องตัดสินใจตอนทำต้นแบบ)

**ผลค้นหา**

1. ไม่มีส่วนต้อนรับ ผู้ใช้มาหาของ รูปใบแรกต้องอยู่ในจอแรก
2. chip หมวดเป็นเม็ดยา อันที่เลือกอยู่เป็นพื้น `--color-primary-soft` กับเครื่องหมายถูก
3. เปลี่ยนตัวกรองแล้วตารางจางสลับกัน จำนวนผลลัพธ์เลื่อนแบบมาตรวัด
4. แถบตัวกรองค้างใต้แถบบนเมื่อเลื่อน และได้เงา
5. หน้าไม่พบผลลัพธ์: ภาพประกอบเล็กกับหมวดแนะนำ 4 ใบ

**หน้าสินค้า**

1. รูปในการ์ดขยายเป็นรูปใหญ่ตอนเข้าหน้า (ต้องให้หน้าสินค้าถูกโหลดล่วงหน้า ไม่เช่นนั้นจะได้แค่เนื้อหาเลื่อนขึ้น ตามที่เอกสารของ Next ระบุ)
2. กล่องซื้อเป็นการ์ดขาวมีเงา ค้างข้างจอบนจอกว้าง ราคา `--text-price` หนา
3. ป้าย "หมุนดูได้ 3 มิติ" บนรูปใหญ่ เปิดแล้วหมุนหนึ่งรอบ
4. กดใส่ตะกร้า: ปุ่มเปลี่ยนเป็น "ใส่แล้ว" ของลอยไปตะกร้า เลขเด้ง
5. เปลี่ยนตัวเลือกสีหรือขนาด: รูปจางสลับ ราคาเลื่อนแบบมาตรวัด
6. ใต้รายละเอียด: การ์ดร้าน (โลโก้ ชื่อ ปุ่มไปหน้าร้าน) กับชั้น "สินค้าอื่นของร้านนี้" เติมที่ว่างและชวนดูต่อ

**ตะกร้า**

1. แถวสินค้าของแต่ละร้านอยู่ในการ์ดขาวหนึ่งใบ หัวการ์ดเป็นโลโก้กับชื่อร้าน
2. กดบวกลบ: จำนวนกับยอดเลื่อนแบบมาตรวัด ยอดรวมในกล่องสรุปกระพริบพื้น `--color-primary-soft` หนึ่งครั้ง
3. ลบแถว: ยุบและจาง แถวล่างเลื่อนขึ้น
4. กล่องสรุปยอดเป็นการ์ดมีเงา ค้างข้างจอ
5. ตะกร้าว่าง: ภาพประกอบตะกร้ากับชั้น "มาใหม่"

**หน้าสั่งซื้อ**

1. แถบบอกขั้น 3 ขั้นใต้แถบบน (ตะกร้า ที่อยู่และยอด จ่ายเงิน) ขั้นที่ผ่านแล้วเป็นสีเขียวมีเครื่องหมายถูก
2. เข้าหน้านี้จากตะกร้า: เนื้อหาเลื่อนเข้าจากขวา กล่องสรุปยอดอยู่กับที่ (เป็นของชิ้นเดียวกันข้ามหน้า)
3. การ์ดที่อยู่: อันที่เลือกเป็นพื้น `--color-primary-soft` มีเครื่องหมายถูกที่เด้งเข้า
4. ไม่มีการขยับอื่น หน้านี้คือหน้าตรวจความถูกต้อง

**จ่ายเงิน**

1. รอผล: วงแหวนเวลารอบ QR ที่สั้นลงเรื่อยๆ เปลี่ยนเป็น `--color-sale` เมื่อเหลือไม่เกิน 5 นาที ข้อความ "กำลังรอผล" มีจุดสามจุดที่เต้น
2. สำเร็จ: หัวเรื่อง `--text-display` เครื่องหมายถูกในวงกลมเขียววาดตัวเอง กระดาษสีครั้งเดียว แล้วปุ่ม "ดูคำสั่งซื้อของฉัน" ปุ่มกดได้ตั้งแต่เฟรมแรก
3. ไม่สำเร็จหรือหมดเวลา: ไอคอนกับพื้นสีอ่อนของสถานะนั้น ไม่มีการสั่น ไม่มีการฉลอง
4. ส่วนตัวจำลองการจ่ายเงินอยู่ในกล่อง `--color-surface-sunken` แยกจากเนื้อหาจริงชัดเจน

**คำสั่งซื้อ**

1. ป้ายสถานะมีสี: รอจ่ายเงิน (`--color-accent-soft`) จ่ายแล้วกับกำลังจัดส่ง (`--color-primary-soft`) สำเร็จ (เขียวเข้มตัวขาว) ยกเลิก (เทา) ข้อความสถานะยังอยู่ครบ สีเป็นแค่ตัวช่วย
2. แต่ละคำสั่งซื้อเป็นการ์ด แถว "กำลังจัดส่ง" มีแถบเส้นทางเล็กๆ 4 จุด
3. หน้าคำสั่งซื้อเดี่ยว: เส้นเวลาแนวนอนของคำสั่งซื้ออยู่ใต้หัวเรื่อง เติมที่ว่าง
4. สลับ chip สถานะ: รายการจางสลับ

**ติดตามพัสดุ (มีแผนที่)**

1. เส้นทางบนแผนที่วาดตัวเองจากต้นทางถึงจุดล่าสุดใน 700ms หลังแผนที่พร้อม เส้นเป็น `--color-primary` ส่วนที่ยังไม่ถึงเป็นเส้นประ
2. หมุดล่าสุดเป็นสี `--color-accent` มีวงแหวนขยายออก 2 รอบ
3. เส้นเวลา: จุดที่ผ่านแล้วเป็นสีเขียว จุดล่าสุดใหญ่กว่า เส้นระหว่างจุดเติมสีจากล่างขึ้นบนตามลำดับเวลา
4. หัวเรื่องสถานะมีไอคอน (กล่อง รถ บ้าน เครื่องหมายถูก) "ส่งสำเร็จ" ได้การฉลองแบบเดียวกับจ่ายเงินสำเร็จ ครั้งแรกที่เปิดเท่านั้น
5. ข้อความเส้นทางใต้แผนที่กับข้อความเมื่อแผนที่โหลดไม่ได้ยังอยู่ครบตามเดิม (MAP-005, MAP-006)

**หลังบ้านร้าน**

1. ตัวเลข 4 ตัวเป็นการ์ด ตัวเลขนับขึ้นจาก 0 ใน 600ms ครั้งเดียว การ์ด "รอจัดของ" เป็นพื้น `--color-accent-soft` เมื่อมากกว่า 0
2. ใต้การ์ด: รายการ "ต้องทำตอนนี้" (คำสั่งซื้อที่รอจัดของ 3 รายการแรก สต็อกใกล้หมด) เติมที่ว่างด้วยงานจริง
3. เมนูหลังบ้านมีเส้นใต้ที่เลื่อนตามแท็บที่เลือก
4. หน้าเปลี่ยนสถานะพัสดุ: แถบเส้นทางบอกว่าตอนนี้อยู่ขั้นไหน กดเปลี่ยนแล้วจุดถัดไปเติมสี
5. หลังบ้านขยับน้อยที่สุดในแอป ผู้ขายใช้ทุกวัน ไม่มีการฉลอง ไม่มีส่วนต้อนรับ

### ลำดับการทำที่แนะนำ

1. ทำต้นแบบ 3 หน้า (หน้าแรก หน้าสินค้า ติดตามพัสดุ) ด้วย token ใหม่และการขยับชุดเต็ม ให้เจ้าของดูก่อนแก้ทั้งแอป
2. เปลี่ยน token กับ class กลางใน `globals.css` แล้วไล่ module ทีละ feature
3. เพิ่ม `<ViewTransition>` ในเส้นทางซื้อ
4. เขียน `docs/design-system.md` ใหม่พร้อม test (ข้อ g)

**กฎที่ต้องคงไว้** เพราะเป็นส่วนที่รอบ 2 ทำถูก: ค่าทุกตัวผ่าน token ปุ่มหลักหน้าละหนึ่งปุ่มและกดได้ในจอแรก ความสูงที่กดได้ 44px วงโฟกัส จอ 360 ไม่ล้น breakpoint สามค่า "จอแรกมีสิ่งที่ผู้ใช้มาหา" "ตัวเลขเดียวกันไม่พูดสองครั้ง" "ช่องกรอกกว้างตามข้อมูล" รูปในรายการเป็นสี่เหลี่ยมจัตุรัสแบบ `cover` รูปแบบวันเวลา และกฎไม่ใช้ `@media (scripting)`

**test ที่ควรเพิ่มพร้อมกฎใหม่** (ตามหลักของ `AGENTS.md` ที่ให้เครื่องตรวจแทนการเขียนกฎ): ห้าม animation บน property ที่ทำให้หน้ากระตุก `infinite` ใช้ได้เฉพาะรายการที่อนุญาต ทุกไฟล์ที่มี `@keyframes` ต้องอยู่ใต้กฎลดการขยับ และ e2e สามตัวในข้อ (e) (ลดการขยับ ปิด JavaScript กดปุ่มหลักทันที)

## ยังไม่ได้ยืนยัน

- การขยับจริงของ apple.com ไม่ได้เปิดดูในเบราว์เซอร์ ข้อมูลมาจาก HTML กับ CSS ที่ดึงมา หน้า [apple.com/store](https://www.apple.com/store) ดึงมาได้แต่ข้อความ ไม่เห็นชั้นวางการ์ด
- Aesop ดึงไม่ได้ (403) หน้ารายการของ Dribbble ดึงมาได้หน้าว่าง ได้แค่ชื่องานจากผลค้นหา
- งานจาก Awwwards สองชิ้นเป็นผู้เข้าชิง ไม่ใช่ผู้ชนะ และอ่านแค่หน้ารายละเอียดบน Awwwards ไม่ได้เปิดเว็บจริง
- เอกสารของ `<model-viewer>` ([modelviewer.dev](https://modelviewer.dev/docs/index.html)) ดึงมาได้หน้าว่าง ชื่อ `auto-rotate` ยืนยันจากไฟล์ของแพ็กเกจที่ติดตั้งใน repo แทน
- หน้าคำแนะนำของ three.js ที่ลองเปิดตอบ 404 ข้อแนะนำเรื่องประสิทธิภาพ 3 มิติจึงอ้างจากเอกสารของ fiber อย่างเดียว
- react.dev ไม่เขียนชัดว่า `<ViewTransition>` เป็นรุ่นเสถียรหรือยัง ตัวอย่างส่วนใหญ่ในหน้านั้นใช้รุ่น canary ที่ยืนยันได้คือ React 19.3.0 ใน repo มีให้ใช้ และเอกสารของ Next 16.4 บอกว่าใช้ได้โดยไม่ต้องตั้งค่า ยังไม่ได้ลองเขียนจริงในแอปนี้
- เอกสารของ Motion ระบุ React 18.2 ขึ้นไป ไม่ได้พูดถึง React 19 ตรงๆ ที่ยืนยันได้คือ `peerDependencies` ใน npm
- ขนาดของ three กับ drei หลังตัดส่วนที่ไม่ใช้ และขนาดจริงใน bundle ของเรา
- ความลื่นบนมือถือระดับกลาง ยังไม่มีต้นแบบให้วัด
- สัดส่วนเบราว์เซอร์ของผู้ใช้ไทย ตัวเลขการรองรับทั้งหมดเป็นของทั่วโลกจาก caniuse
- ฟอนต์ตัวโชว์ตัวไหนเหมาะ และ line-height 1.25 พอสำหรับสระซ้อนของไทยหรือไม่
- SplitText กับข้อความไทย
- สีที่เสนอคำนวณคอนทราสต์แล้ว แต่ยังไม่ได้ดูบนจอจริงคู่กับรูปสินค้า
